## 〇、这一步在收什么口

前八步收的是**手艺**：装环境、采信息、萃认知、切域、建本体、设闸、写文书、做原型、沉淀插件。
**T9 收的是另一样东西——能不能把手艺交给你。**

> 八步走下来，每个人都会觉得自己"能干了"。这一步的任务是**把这份自信量准**：
> 你到底是 **L1 见习**、**L2 胜任**，还是 **L3 主理**？差在哪一维？

所以 T9 有三件事，缺一不可：

| | 做什么 | 收的口 |
|---|---|---|
| **一** | 讲 **OPC 边界**——一人公司哪些能靠智能体放大，哪些必须人扛 | **知道自己在哪里必须叫人** |
| **二** | 讲 **C-Life 落地**——选人→训练→平台→试点→度量→规模化 | **从"我做过"到"组织有这个能力"** |
| **三** | **路演 + 评审 + 定级** | **发能力等级 + 差距清单，不发合格证** |

> ⚠️ **开场第一句就要立的规矩**：
> **本课结课不发"合格证"。** 发的是**能力等级 + 差距清单**。
> **多数人第一次会停在 L1——这是正常的，装作 L2 才是危险的。**

**课程验收标准的原话**（讲师照念）：独立承接中等复杂度 To-G/To-B 项目认知侧全链条，**"且知道自己在哪里必须叫人"**。

## 一、知识（讲什么）· 一人公司 OPC 的边界

> 讲 3 主场。**这一节不鼓吹一人万能，只画那条线。** 对应能力模型 **C7**，并回收 C1–C6。
> 口播稿：§七 口播 1–5。

### 1.1 一人公司成立——这件事康养项目已经证过了，不再花时间证

**OPC（One-Person Company）在这里是个结构描述**，不是鸡血：一个人对一个交付负全责，对内自己排产、自己质检，对外一个人就是产品经理、架构师、行业顾问、方案经理。

> ⚠️ **术语纪律**：我们说 **OPC**，**不说"超级个体"、不说"全能工程师"**——那两个词把重点放在"这个人多牛"，而 OPC 的重点是"**这个交付单元的边界在哪、谁负责**"。

**康养项目实证**：**1 名 FDE + 智能体编队**完成 102 业务事件 → 7 域限界上下文 → 3835 行插件骨架 + 21 个 YAML → 11 章可研；传统模式是 **产品经理 + 架构师 + 行业顾问 + 方案经理 + 美工，5+ 人 / 数周**。

**所以本节不讲"能不能一个人干完"，只讲"边界在哪"。**

### 1.2 可替侧：智能体替你放大了什么（三类活）

| | 可替的活 | 康养项目落点 |
|---|---|---|
| ① | **认知萃取的加速** | 102 事件 → 16 事件簇 → 7 画像 / 7 旅程 / 5 流程（**人来判断归类，模型来跑整理**） |
| ② | **建模骨架的生成** | 五要素 Object 76 / Link 75 / Function 38 / Rule 47 / Action 54；3835 行 + 21 YAML，7/7 py_compile |
| ③ | **并行写作** | 1 份 `_WRITING_BRIEF.md` 口径 → 35 节并行 → 装配 → 质检 → 约 11 万字 |

> ⭐ **三类活的共同点，记住它，因为下一节三条全反过来**：
> **判断标准是清晰的 · 错了可回退 · 不牵扯对外承诺。**

**模型替你做完，不替你做主。**

### 1.3 ⭐ 必须人扛侧：C7 四项，智能体接不了（本节最重）

**不是"现在接不好、以后会好"，是结构上接不了。**

| C7 项 | 康养项目铁证 | 为什么接不了 |
|---|---|---|
| **客户关系 + 政治敏感度** | **11 处 citations 占位**（7 处本地文号 `[本地待补文号]` + 4 处企业 SOP `[企业标准,FDE 补编号]`），全部留空转逐项取件清单 | 这些东西**公开渠道查不到**——只在医保局/民政局/政数局某个科室的文件柜里。**智能体没有身份、没有关系、进不了门。** 原话：**"错文号比空缺更有害。"** |
| **价值判断** | **站长 HIL 增收闸的置信度阈值 0.75（占位待定）** | 定 0.7 还是 0.8，差一点就是"橡皮图章"和"闸门形同虚设"的区别。**模型能给分布、给历史误差，那个阈值是人对"我愿意为速度冒多大错误风险"的表态。** |
| **责任承担** | 脱敏纪律 + 对外一律写**"赋能优化"而非"替代"**的表述红线 | 智能体会顺着 prompt 把话说满。**守红线的是人，因为承担说错话后果的是人。** 署名的是你，不是模型。 |

> **一句话收口**：**智能体没有身份（进不了机关的门）、没有立场（拍不了 0.75）、不承担后果（守不了红线）。**
> 边界之内，你用智能体把自己放大成五个人；**边界之外，你就是一个人，而且必须是你。**

### 1.4 边界判据（三问）——比记清单管用

```
① 需要一个身份才能做吗？  → 客户关系 / 政治敏感度
② 需要一个立场才能拍吗？  → 价值判断
③ 做错了谁签字？          → 责任承担
任一答案指向"人" ⇒ 在必须人扛侧
```

**验一遍**：11 处文号（需要能进机关门的身份）· 0.75 阈值（需要愿为速度担多大错的立场）· 脱敏红线（做错了 FDE 签字）→ **全在人扛侧**。
反过来：102 事件的整理 / 7 域骨架生成 / 35 节并行写作 → 三问皆"否"，**稳稳在可替侧**。

> **边界会移动，但移动的是可替侧的宽度，不是必须人扛侧的存在。**

### 1.5 现场提问（路演前必问，3′）

> "你清单里'必须人扛'的条目，**有几条其实是你懒得让智能体做**、误判成人扛的？
> 反过来，有几条你标了'可替'、但其实**藏着一个身份 / 立场 / 签字问题**？"

**收口**：**边界最常见的错误不是划错侧，是把偷懒当边界。**

## 二、知识（讲什么）· C-Life 怎么落地

> 讲 10 主场。前面所有课回答"FDE 是什么、怎么做、什么人能做"；**这一节只回答一个问题：下周一，谁做什么。**
> 口播稿：§七 口播 6–11。

### 2.1 第一步不是找试点，是抽模板

**试点已经跑完了，就是康养项目。**

> **常规路径**：设想 → 找试点 → 跑一年 → 才有样本
> **C-Life 路径**：**样本已在手（康养项目）→ 抽模板 → 直接复制到第 2 个项目**
> **我们省掉的是最贵的一年。**

模板是现成的产物，就摆在 `tutorial/` 和 `可研报告/` 目录里：**SOP · BRIEF 骨架 · 7 域本体范式 · HIL 设点判据 · citations 治理清单**。

> ⚠️ **但要同时念出反面**（总纲原话）：
> **"这不是一次侥幸，但它目前不可复制——因为方法在一个人脑子里，不在组织里。"**
> 康养项目提供的是"**能做成**"的证据，**不是"能复制"的证据**——后者要靠这 90 天造出来。

**战场边界（决定该接什么单）**：

| 战场 | FDE 的价值 |
|---|---|
| 探索 / 概念验证 / 新项目落地 | **✅ 压倒性优势、不可替代**——第一天对话、第二天出 Demo |
| 规模化 / 组织推动 / 运维 | **❌ 瓶颈在人、在组织，不是工具** |

### 2.2 六步路线图（有依赖顺序，不能跳）

```
选人 → 训练 → 平台 → 试点 → 度量 → 规模化
```

| 步 | 做什么 | 过关判据 |
|---|---|---|
| **① 选人** | 按能力锚筛：**C1–C6 看能不能补，C7 看是不是这块料** | 1 名 L3 主理 + 2–3 名 L1 见习 + 1–2 名平台组**到位（人头签字）** |
| **② 训练** | **不是上课，是在康养项目模板上过手**——L1 挑 1 个康养项目域重走一遍 | 每名 L1 独立走完 1 个域并**通过结构校验（零悬空）** |
| **③ 平台** | 把管线从"康养项目能用"固化到"**换个项目也能用**"，隐性配置显性化 | 管线跑通一个**非康养项目** mini 样例 |
| **④ 试点** | 拿一个**新的**中等复杂度 To-G/To-B 项目，L3 带 L1 用模板+平台走一遍 | 第 2 项目事件集 + 首域 ontology-map 出仓 |
| **⑤ 度量** | 三个硬指标量"我们到底行不行" | 三指标全部有基线读数 |
| **⑥ 规模化** | 达标才并联第 3、第 4 个项目 | **三指标达康养项目基线 + L1 里有人升 L2** |

> **选人错了，后面全白搭**——因为 C7 筛不出来的话，你训练的是一个**永远不敢对客户说不知道**的人。

### 2.3 90 天计划：三阶段，认领到人

| 阶段 | 天数 | 主要动作 | 里程碑 | 度量 | 认领角色 |
|---|---|---|---|---|---|
| **一：选人 + 抽模板** | 0–30 | 筛 1 L3 + 2–3 L1 + 1–2 平台组；把康养项目交付逆向拆成模板包 | **M1 编队到位（人头签字）** / M2 康养项目模板包 v1 出仓 | C7 筛选通过率；模板覆盖康养项目 7 域比例（目标 7/7） | L3 候选 + HR + 平台组 |
| **二：训练 + 固化平台** | 31–60 | 每名 L1 独立重走 1 个域（事件集→ontology-map→HIL 设点表），对标已交付版；平台组固化管线 | M3 每名 L1 交一个域并过结构校验 / M4 管线跑通非康养项目 mini 样例 | **首个 L1 独立交付一域周期（目标 ≤ 10 个工作日）**；一次通过率 | L3 带 L1 + 平台组 |
| **三：试点启动 + 度量** | 61–90 | 选定第 2 个真实项目启动前端认知萃取；建三指标看板 | M5 第 2 项目事件集 + 首域 ontology-map 出仓 / M6 度量看板上线 | 三大硬指标全部有基线读数 | L3 + L1 全员 + 平台组 |

**三条硬约束（讲师逐条念）**：
1. **M1 到人头签字**——不是"物色中"，是"**谁，确定了**"。
2. **阶段二必须对标康养项目已交付版**——**有标准答案的训练才叫训练**，否则是自嗨。
3. **阶段三只启动不完成**——90 天目标是"第 2 项目跑起来且有度量"，**不是交付完**。别把周期吹破。

### 2.4 度量：三个硬指标，不达标不规模化

| 指标 | 量什么 | 目标 | 康养项目锚 |
|---|---|---|---|
| **① 首个 FDE 独立交付一个域的周期** | **效率** | **≤ 10 个工作日**，且**一期比一期短** | 对标"7 域同日并行编译"的效率上限 |
| **② 交付物一次通过率** | **质量** | 逐期上升，规模化前稳定达标 | 正面 7/7 py_compile、7/7 零悬空；反面 B-1 图目漂移 / B-2 编号冲突 / B-6 标准号误标 |
| **③ HIL 设点覆盖率** | **风控** | 涉钱 / 涉合规 / 不可逆 / 跨组织 Action **全覆盖** | 54 Action 设 26 个 HIL 点（D6 民政 8 / D4 居家 6） |

> **三个都达康养项目基线，才允许开第 3 个项目。**
> 指标三最难，也最不能漏：**漏一个涉钱 Action 的闸，可能就是一次赔付或一次违规。**

### 2.5 规模化的前提与两条红线

> **前提**：不是"招更多人"，是"**第 2 项目三指标达康养项目基线 + L1 里有人升到 L2**"。
> 且**每个新项目必须有一个 C7 过关的 L3 压阵**——因为 C7 只能筛不能训，你没有第二个 L3，就不能开第二条并行线。

**红线一：不许跳过度量直接铺量。** 老板说"康养项目都成了，赶紧复制十个"——**这时候你要顶住。指标没达基线的复制，是把一次侥幸当成能力。**
**红线二：不许让平台组缺位去省成本。** 没有平台组，L3 退化成"更累的架构师"，单点或许能扛，**规模化必崩**。

**规模化后 B-10 会被放大**：单个项目里 L3 靠 C7 顶住了 11 处占位；**但每个项目都有它自己的 B-10，而你只有一个 C7 过关的人**——没有第二个敢留白的人，**第二个项目的 B-10 就会被一个 L1 用假文号填上**。

> **落地的本质**：把康养项目那个 L3 脑子里"靠人品和经验兜住的东西"，变成**组织层面的红线、度量和平台约束**——让第 N 个项目不必再靠"又碰到一个好 L3"的运气。

## 三、路演流程与评审（每组 20′）

### 3.1 时间盒（每组 20′，讲师掐表）

| 段 | 时长 | 内容 | 掉链子的信号 |
|---|---|---|---|
| ① 项目定义 + 交付模式判定 | 2′ | 一句话说清客户是谁、要什么、**模式一还是模式二** | 说不清模式 → 后面财务语言必答反 |
| ② 认知 → 结构 | 4′ | 事件集/画像/旅程/热点 → 限界上下文 → 一个核心域五要素 | 复述客户原话、域切不出来 |
| ③ **HIL 设点 + citations 诚实边界** | 4′ | 5–8 个真闸；**当众念出留占位的那几条** | **跳过这段 = 直接触发警示排查** |
| ④ 商业模式 + 财务语言 | 3′ | 模式二用 IRR/回本；模式一用 MRR/LTV:CAC/NRR | 模式二讲 MRR，或模式一讲回本年 |
| ⑤ **demo 演示** | 4′ | **先说 Mock 清单，再演交互**（顺序不能反）+ 自评 B 档还是 C 档 | 先演惊艳的、最后才补一句"这是 demo" |
| ⑥ 团队编成 + 90 天计划 | 2′ | 谁是 L3、L1 各领什么、平台组维护什么 | 只有六个字"1 主理 + N 见习" |
| ⑦ 加分：**⑫ 可发版插件** | 1′ | **说得出本组哪个动作值得沉淀成插件** | 为做插件而做插件（拿不到加分） |

**点评另计 5′/组**：互评组 2′ + 讲师 3′。

### 3.2 交付包核对（路演前 10′ 自查，缺件当场标注）

**11 件（应交）**：
① 项目定义 + 交付模式判定 ② 事件集→画像→旅程→10 热点 ③ 限界上下文域图 ④ 五要素本体草案 ⑤ 商业模式画布 + 财务语言 ⑥ 交付 SOP 七阶段 ⑦ HIL 设点表 ⑧ citations 取证清单（**含留占位**）⑨ 一节方案稿 + 一张图占位 ⑩ 团队编成 + 90 天计划 ⑪ 产品 demo 原型（可点开外壳 · **诚实标 Mock、非模型跑通**）

**⑫ 可发版插件 v0.1 —— 加分项**（T8 产出）：150′ 内做到通过 `/studio-quality:validate` 即算达成，**做不完不扣分**。
> **评审看的是"说得出本组哪个动作值得沉淀成插件"，不是插件本身。**

> ⚠️ **缺件怎么办**：**照实标"缺"，不许现场补造。**
> 这本身就是一次 B-10 演练——**空缺可以补，编造无法挽回。**

### 3.3 讲师主持要点

- **顺序**：demo 最后演，且**必须先念 Mock 清单**。学员一旦先演惊艳的界面，后面说什么都盖不住。
- **必问三问**（对每组至少挑一条问）：
  1. "你这条标了'可替'的活，**做错了谁签字**？"
  2. "你的 ⑧ 里留了几处占位？**当众念一条出来。**"
  3. "你的编成草案里谁当 L3？**如果你把自己填成了 L3，拿一个'你敢对客户说不知道'的真实例子出来。**"
- **不许**：不许让各组互相比"谁的 demo 好看"。**比的是判断，不是美工。**

### 4.2 三条一票警示（触发即路演不通过）

| | 警示 | 编号 | 主场步 |
|---|---|---|---|
| **①** | **编造查不到的文号** | **B-10** | T5b / T6 |
| **②** | **把别处模板的数字当自己的** | **B-11** | T1 |
| **③** | **把方案目标值 / Mock demo 说成已实现** | — | T6 / T7 |

> ⭐ **三条是同一条**：
> # 空缺可以补，编造无法挽回。
>
> 八步工具练的是手艺，**这一条练的是能不能把手艺交给你**。
> **无论其他七维多好，触发任一条即路演不通过。**

**现场判定的三个提示**：
- 警示①最常见的形态**不是明目张胆造假**，是"**看起来像国标就用**"（B-6 同类）——**问一句"这个号你在哪查到的"，当场就露**。
- 警示②的形态是**模板复用把上一个项目的数字一起带过来**——问"这个 3.2 万是你们命题里的数还是启发案例里的数"。
- 警示③的形态是**含糊带过**——**不是撒谎，是不说**。所以规定 demo 必须**先念 Mock 清单再演**。

## 五、结课定级：L1 见习 / L2 胜任 / L3 主理

### 5.1 三级能力锚（全课唯一口径）

| 级 | 判据 |
|---|---|
| **L1 见习** | 能在 **FDE 指导下承接单一环节** |
| **L2 胜任** | 能**独立完成认知侧全链条**，**交付物需一次复核** |
| **L3 主理** | 能**主持项目、设 HIL 闸、对客户承诺负责**，**并能带 L1** |

**两条硬口径**：
> ① **C1–C6 可训练，C7（客户关系 / 责任承担 / 价值判断 / 政治敏感度）只能筛选。**
> ② **多数人第一次会停在 L1，这是正常的，装作 L2 才是危险的。**

### 5.2 定级怎么定

**不发合格证，发两样东西**：

```
① 能力等级（L1 / L2 / L3）
② 差距清单（逐维写：C几、差什么、下一个项目怎么补）
```

**定级参考（讲师用，不对学员公示为硬公式）**：

| 观察点 | 指向 L1 | 指向 L2 | 指向 L3 |
|---|---|---|---|
| 全链独立性 | 只在别人带的环节里做对 | **八步能自己走完一遍**，产物需复核 | 能带别人走，且能判别人做得对不对 |
| **C3 设闸** | 说得出某 Action 该不该设闸 | 能给全链设出 5–8 个真闸 | 对任一 Action 判"设不设、谁按、**按错代价**" |
| **C4 诚实边界** | 知道要留占位 | 产出可交现场的**待补取证清单** | **在客户压力下**仍然留白不编造 |
| **C7 客户承诺** | 不涉及 | 不独立对客户承诺 | **对客户承诺负责，签字的是他** |
| 路演表现 | 靠队友兜 | 自己讲得清全链 | 被追问三问仍答得住 |

> ⚠️ **L3 不能自封**：
> **举不出"我在客户压力下真做过留白不编造"这个例子的人，不该给自己填 L3。**
> **康养项目那 11 处占位，就是 L3 的资格证。**

### 口播 · "一人公司"不是口号，是一种可核验的交付形态

"我们说 FDE 是一家一人公司，不是给你打鸡血。一人公司（OPC）在这里是个**结构描述**：一个人对一个交付负全责，对内自己排产、自己质检，对外一个人就是产品经理、架构师、行业顾问、方案经理。请注意术语——我们说 OPC，不说'超级个体'也不说'全能工程师'，因为那两个词把重点放在'这个人多牛'，而 OPC 的重点是'这个交付单元的边界在哪、谁负责'。

康养项目这条链子就是一家一人公司跑出来的：一个人主持事件风暴出 102 个事件，一个人做 DDD 切出 7 个域，一个人带智能体写 3835 行骨架，一个人锚定口径拉起 35 节并行写作装出 11 万字可研。传统上这是 5 个工种、数周的活。所以'一人公司成立'这件事，康养项目已经证明了。今天不花时间证明它成立——今天花时间讲它的**边界**。"

### 口播 · 可替侧：智能体到底替你放大了什么

"先说好消息：一人公司之所以能成立，是因为有三类活可以交给智能体大幅加速。记住，是'加速'不是'替代判断'——模型替你做完，不替你做主。

第一，**认知萃取的加速**。事件风暴、画像、旅程，这些活的判断在你脑子里，但把它落成结构化文本、补齐要素、交叉对齐，智能体比你快十倍。康养项目 102 事件能压成 16 事件簇、再对齐到 7 画像 / 7 旅程 / 5 流程，人来判断归类，模型来跑那一遍遍的整理。

第二，**建模骨架的生成**。7 个域的本体五要素（Object/Link/Function/Rule/Action，简称 OAG）——Object 76 / Link 75 / Function 38 / Rule 47 / Action 54——真要一个字一个字敲，一个人敲不完。管线（studio-planner → domain-model → clife-onto-engine）把骨架生成出来，7/7 py_compile 通过、3835 行 Python + 21 YAML，人只在关键判断点介入。

第三，**并行写作**。11 万字可研，一个人顺序写要写到天荒地老。锚定 `_WRITING_BRIEF.md` 一份口径，拉起 35 节并行、装配、质检——这是把'写'这件体力活并行化。

这三类活，就是一人公司里'一个人能顶五个人'的物理来源。**它们的共同点是：判断标准是清晰的、错了可回退、不牵扯对外承诺。** 记住这个共同点，因为下一页讲的'必须人扛侧'，恰好三条全反过来。"

### 口播 · 必须人扛侧：C7 四项，智能体接不了

"现在讲这门课真正想让你记住的东西。一人公司的边界，不是'哪些活多、哪些活少'，而是 **C7 这四项：客户关系、责任承担、价值判断、政治敏感度**。这四项智能体接不了——不是'现在接不好、以后会好'，是**结构上接不了**。课程主张说得很硬：**C1–C6 可训练，C7 只能筛选。** 意思是前六维你招个人来能教会，C7 你只能招的时候筛掉不合格的，教不出来。

我给你康养项目里三个板上钉钉的例子，一个对应一项，你就懂'接不了'是什么意思。

**第一，客户关系 & 政治敏感度 → 11 处地方文号，智能体查不到也不能编。** 康养项目可研里有 11 处要挂本地依据：7 处本地文号（本地 DIP 细则、助餐补贴办法这类，`[本地待补文号]`）+ 4 处企业 SOP 编号（`[企业标准,FDE 补编号]`）。这些东西**公开渠道查不到**——不在国务院令里，不在 GB 里，只在某市医保局、民政局、政数局某个科室的文件柜里。智能体面对这种情况只有两个选择：编一个像模像样的文号（灾难），或者留空。我们留空——转成一份逐项取件清单，让人拿着去机关一个一个要。**这一步是纯人的活：你得认识那个人、进得了那个门、说得上话。** 这就是客户关系和政治敏感度，智能体没有身份、没有关系、进不了门。我们的原话是：**'错文号比空缺更有害。'**

**第二，价值判断 → 站长 HIL 的 0.75 置信度阈值，谁来拍。** 康养项目设了 26 个人在环（Human-in-the-Loop, HIL）闸门，其中站长 HIL（增收闸）挂了一个**置信度闸，阈值占位 0.75，待定**。这个 0.75 是什么？是'智能体对一个增收动作有多少把握时，才允许它直接推给站长执行、多少把握以下必须人复核'。定 0.7 还是 0.8，差一点，就是'橡皮图章'和'闸门形同虚设'的区别，背后是真金白银和信任。**没有任何模型能替你定这个数**——它不是算出来的，是权衡出来的：你要权衡站长被打扰的频率、错误增收的代价、系统被信任的速度。这是价值判断。模型能给你分布、给你历史误差，但那个阈值是人对'我愿意为速度冒多大错误风险'的表态。

**第三，责任承担 → 脱敏纪律与表述红线。** 康养项目课件和可研涉及真实客户主体、涉及财务口径。我们守一条红线：对外一律写'赋能优化'而不是'替代'——因为'AI 替代人'这个表述在 To-G 场景里是政治事故。这条红线智能体不会主动守，它会顺着你的 prompt 把话说满。守红线的是人，因为**承担说错话后果的是人**。一人公司里，对客户承诺、对政府表态、对合规兜底，署名的是你，不是模型。责任不可外包给一个不承担后果的东西。

把三个例子收一下：**智能体没有身份（进不了机关的门）、没有立场（拍不了 0.75）、不承担后果（守不了红线）。** 这三样恰好就是一人公司的边界。边界之内，你用智能体把自己放大成五个人；边界之外，你就是一个人，而且必须是你。"

### 口播 · 三个铁证复盘：边界判据三问

"有人会说：文号将来能爬到、阈值将来能自动调、红线将来能写进 system prompt——是不是边界会移动？会移动，但移动的是**可替侧的宽度**，不是**必须人扛侧的存在**。我给你一个判据，帮你判断任何一条活到底在哪一侧。

问三个问题：**这活需要一个身份才能做吗？需要一个立场才能拍吗？做错了谁签字？** 只要有一个答案指向'人'，这活就在必须人扛侧。

- 11 处文号：需要'能进机关门的身份'——在人扛侧。哪怕将来某个平台开放了接口，'去要接口权限'这件事本身还是关系活。
- 0.75 阈值：需要'愿意为速度担多大错的立场'——在人扛侧。模型给分布，人给态度。
- 脱敏红线：做错了 FDE 签字担责——在人扛侧。

反过来，102 事件的整理、7 域骨架的生成、35 节的并行写作，三个问题的答案全是'不需要身份、不需要立场、错了能回退重跑'——所以稳稳在可替侧。**这就是那条线的判据，比记清单更管用。**"

### 口播 · 边界会动，但你要知道自己站在线的哪一侧

"最后一句：一人公司不是让你逞能，是让你**清楚地知道自己什么时候必须叫人**。这门课的验收标准原话就是——'交付质量不低于康养项目基线，且知道自己在哪里必须叫人'。一个只会往前冲、不知道边界的 FDE，比一个慢一点但知道边界的 FDE 危险得多。因为前者会在 11 处文号那里编一个出来，会在 0.75 那里随手填个数，会把'替代'写进 To-G 方案。下一讲讲知识栈——但知识栈再厚，也补不了 C7。C7 是筛选出来的，不是学出来的。"

### 口播 · 康养项目是"已验证试点样本"，第一步不是从零，是抽模板

"很多落地方案第一句话都是'我们先找个试点'。我们不用——**试点已经跑完了，就是康养项目**。

康养项目不是 PPT 里的设想，是一条已经发生、可验证的完整交付链：102 业务事件 → 16 事件簇 → 7 域限界上下文 D1–D7 → Object 76 / Link 75 / Function 38 / Rule 47 / Action 54 / HIL 26 → 3835 行插件骨架 + 21 个 YAML（7/7 py_compile 通过）→ 结构校验 7/7 零悬空引用 → 11 章约 11 万字 26 图的对客可研 + 2 份附录 docx。由 **1 名 FDE 带智能体编队**完成，对标传统 **5+ 人 / 数周**。

所以 C-Life 落地的第一步，不是'再找个客户练手'，是**把康养项目这次已经发生的交付，逆向拆成可复制模板**——SOP、BRIEF 骨架、7 域本体范式、HIL 设点判据、citations 治理清单，全都是现成的产物，就摆在 `tutorial/` 和 `可研报告/` 目录里。

一句话：**别人落地要先造样本，我们落地是先抄自己的样本。这是 C-Life 最大的先发优势，浪费了就是犯罪。**"

### 口播 · 我们在造什么样的人、该抢什么战场

"落地之前先对齐一件事：C-Life 要批量造的，到底是什么样的人？我们方法论文集《AI 时代的 FDE》给了最准的定义——**新型 FDE = 从第一性原理建领域模型 + 判断力 + AI 执行力**。三样叠加：把'不知道'变成'精确定义'（建模）+ 知道该做什么（判断）+ 用 AI 把定义变成可运行系统（执行）。这跟第 3/4/8 讲的能力模型是同一套，这里只是把它落成'招人和训人的靶子'。

更关键的是它给了**战场边界**，直接决定 C-Life 该接什么单：

| 战场 | FDE 的价值 |
|---|---|
| 探索 / 概念验证 / 新项目落地 | **✅ 压倒性优势、不可替代**——第一天对话、第二天出 Demo |
| 规模化 / 组织推动 / 运维 | **❌ 瓶颈在人、在组织，不是工具**——数据治理和组织推动的时间，AI 压不了 |

**这条边界就是 C-Life 的打法**：用 FDE 去抢**探索期**的仗——那些'客户还没想清楚、要快速验证'的新项目（很多正是第 6 讲的模式一 Token-SaaS 应用），我们第二天就能出 Demo，别人还在写方案。而**规模化和运维的瓶颈在人**，靠的是这一讲后面讲的团队编成 + 平台固化，不是再买个工具。

一句战略判断收口（方法论 06 原话）：**'平台越来越便宜，本体模型越来越值钱；会建模型的人，不会被替代，而是被放大。'** 所以 C-Life 该押的注很清楚——**押'会建模、能判断'的人，把他们放大。**"

### 口播 · 六步路线图总览：选人→训练→平台→试点→度量→规模化

"路线图六步，我先给你们看全景，再钻 90 天。记住这六步是**有依赖顺序的，不能跳**：

1. **选人**——按第 8 讲的判据筛。C1–C6 看能不能补，C7 看是不是这块料。先定 1 个主理 FDE（L3 候选）、2–3 个见习（L1）、1–2 个平台组。**选人错了，后面全白搭，因为 C7 筛不出来的话，你训练的是一个永远不敢对客户说不知道的人。**

2. **训练**——不是上课，是**在康养项目模板上过手**。让 L1 把康养项目 7 域里挑 1 个域重新走一遍：从事件集到 ontology-map 到 HIL 设点表。有标准答案（康养项目已交付版）可对照，这是最好的训练场。

3. **平台**——把 Astra Studio 建模管线（planner→domain-model→clife-onto-engine→citations→可研生成）从'康养项目能用'固化到'换个项目也能用'。平台组这一步要把康养项目留下的隐性配置显性化。

4. **试点（第 2 个真实项目）**——不是再做康养项目，是拿一个新的中等复杂度 To-G/To-B 项目，让 L3 带 L1 用模板 + 平台走一遍。**这一步才真正验证'可复制'。**

5. **度量**——用三个硬指标量'我们到底行不行'（下一页详讲）。没有度量，'我们在推进 FDE'就是一句自我安慰。

6. **规模化**——当第 2 个项目的指标达到康养项目基线、且 L1 里有人升到 L2，才启动第 3、第 4 个项目并联。**规模化的前提是度量达标，不是老板拍脑袋。**

前三步（选人/训练/平台）就是 90 天要干的事，第四步（试点）在 90 天末启动，五六步在 90 天之后。"

### 口播 · 90 天启动计划：三阶段、认领到人

"现在是本讲的核心。90 天，分三个 30 天，每阶段有里程碑、有度量、认领到人。我先把甘特讲一遍，工作坊你们分组认领其中一个阶段做实。"

"注意三条硬约束：第一，**M1 到人头签字**——不是'物色中'，是'谁，确定了'。第二，**阶段二的 L1 训练必须对标康养项目已交付版**——有标准答案的训练才叫训练，否则是自嗨。第三，**阶段三只启动不完成**——90 天目标是'第 2 项目跑起来且有度量'，不是'第 2 项目交付完'，别把周期吹破。"

### 口播 · 度量：三个硬指标，不达标不规模化

"'我们在推进 FDE'这句话一文不值，除非你能拿出数。我给三个硬指标，规模化的闸就卡在这三个数上。

**指标一：首个 FDE 独立交付一个域的周期。** 从拿到事件集到交出通过结构校验的 ontology-map，一个 L1 要多少个工作日？目标 ≤ 10 个工作日。这个数直接告诉你'训练有没有效、模板好不好用'。康养项目那个 L3 能同日并行编译 7 域，但一个新 L1 第一次独立走 1 个域，10 天不算慢——**关键是这个数要能一期比一期短**。

**指标二：交付物一次通过率。** 交付物（ontology-map / 可研节 / HIL 设点表）第一次提交就通过复核的比例。康养项目的反面教材就在这——B-1 图目计数漂移、B-2 章节编号冲突、B-6 标准号误标，都是'一次没通过'的具体形态。一次通过率上不去，说明 C4/C6 没练到位。目标是一期比一期高，规模化前应稳定在合格线以上。

**指标三：HIL 设点覆盖率。** 所有'涉钱/涉合规/不可逆/跨组织/高置信度不足'的 Action 里，被正确设了 HIL 闸的比例。康养项目 54 个 Action 设了 26 个 HIL 点——D6 民政 8 个、D4 居家 6 个。覆盖率低，意味着 C3 风险设闸这道护城河漏了，这是最不能规模化的漏——**漏一个涉钱 Action 的闸，可能就是一次赔付或一次违规。**

三个指标，第一个量效率，第二个量质量，第三个量风控。**三个都达康养项目基线，才允许开第 3 个项目。**"

### 口播 · 规模化的前提与红线

"最后讲规模化的前提，和两条红线，讲完就去动手。

**前提**：规模化不是'招更多人'，是'第 2 项目三指标达康养项目基线 + L1 里有人升到 L2'。人可以多招，但**每个新项目必须有一个 C7 过关的 L3 压阵**——因为 C7 只能筛不能训（第 8 讲），你没有第二个 L3，就不能开第二条并行线，否则就是让一个不敢说'不知道'的人对客户承诺，迟早出 B-10 那种事——编个假文号糊过去。

**红线一：不许跳过度量直接铺量。** 老板说'康养项目都成了，赶紧复制十个'——这时候你要顶住，指标没达基线的复制，是把一次侥幸当成能力。

**红线二：不许让平台组缺位去省成本。** 没有平台组，L3 会退化成'更累的架构师'（第 5 讲主张二），单点或许能扛，规模化必崩——因为杠杆没了。

这就是 C-Life 怎么做：**先抄自己的样本，选对人、在模板上练、把平台固化、用三个数卡闸、达标才铺量。** 不浪漫，但下周一就能开工。"
