# T6 · 文档工程（studio-docs / studio-platform）

> 目标：造一个写作专家，让 N 个智能体并行写作而**文风与口径不打架**。**150′**（知识注入 30′ + 实操 90′ + checkout 30′）
> 知识（讲什么）：讲 4 **栈④商业模式与财务** + **栈⑥交付物工程** + **栈⑦合规治理**（讲义 `讲义/04_知识背景栈.md` 已并入本册第七节，讲师无需另开文件）
> 主教具：**肖作仕**（写作专家）· 学前教育项目 653KB 可研 · HR项目 招投标全套
> 工具：`studio-docs` v0.1.0（A 线文书）+ `studio-platform` v0.1.0（B 线平台文档）

---

## 〇、这一步真正在教什么

不是"用 AI 写文档"——那个谁都会。**是教"让 10 个作者写出来像一个人写的"。**

> 康养项目可研 **11 章 / 约 11 万字 / 26 图**，是 **35 个分节并行写作**产出的。
> 学前教育项目可研 **653KB / 44 分章**，同一套打法。
> **并行写作的全部难点不在"写"，在"不打架"**：术语要一致、数字要同源、编号不能撞、图文引用不能断。

**这门课的答案是三件东西**：
1. **蓝图**（blueprint）—— 定文档骨架，谁都不许自己发挥章节
2. **写作专家**（writer）—— 定文风，让 N 个作者有同一个人设
3. **装配期收口**（assemble）—— **编号权、术语统一权归装配阶段，不归写作阶段**

> ⭐ 第 3 条正是反例 **B-2** 的教训固化成的机制：康养项目 35 节并行写作时各节自行起标题层级，装配期出现编号重复与跳号。**现在这条纪律被写进了工具**——`write-section` 只管本章内部，跨章编号一律由 `assemble-document` 重排。
> **这就是"平台=方法论固化物"最具体的一次兑现。**

## 一、A 线：招投标文书（studio-docs）

### 四个命令

| 命令 | 参数 | 产物 |
|---|---|---|
| `/studio-docs:blueprint [类型\|list\|customize X]` | 文档类型名或 `list` | `studio/blueprints/{doc-type}.yaml` |
| `/studio-docs:writer [名字\|analyze 路径\|list]` | 专家名 或 参考文档路径 | `studio/agents/writers/{slug}.md` |
| `/studio-docs:generate [文档类型 域名] [export\|docx\|pdf]` | | 串 plan → write×N（并行）→ assemble →(可选)export |
| `/studio-docs:export [md路径 格式]` | 格式 ∈ `docx`/`pdf`/`docx+pdf` | 同目录的 `.docx` / `.pdf` |

> ⚠️ **只有这四个命令**。插件文档里出现的 `/studio-docs:plan`、`/studio-docs:write`、`/studio-docs:export-document` **都不存在**，别照着敲。
> `write-section` 是 `user-invocable: false` 的**内部技能**，由 `generate` 调度，学员不直接调用。

### `generate` 的四道前置检查
① `studio/` 不存在 → 先 init ② 域的规划产物不存在 → 先跑 `/studio-planner:plan` ③ 无 blueprint → 先跑 `blueprint` ④ 无 writer → 问你要不要先造一个，或用默认风格

### 7 个内置蓝图

`project-proposal`（项目建议书，8 章）· `feasibility-study`（可研，12 章+附录）· `preliminary-design`（初步设计，11 章+附录）· `construction-plan`（建设方案，9 章+附录）· **`tender-document`（招标文件）** · **`bid-document`（投标文件）** · **`acceptance-package`（验收材料）**

**蓝图 YAML 的顶层结构**：
```yaml
name / display_name / version / lifecycle_stage / description
inherits_from: []          # 继承其他蓝图
structure:                 # ← 核心：章节列表
  - chapter: 第一章 投标邀请
    required: true
    sections: [...]
    artifact_sources: [event-storm.md, domain-model.md, ...]   # ← 从哪些分析产物取料
    word_count: "1000-1500"
    guidelines: 一段中文写作指导
compliance: [...]          # 硬性检查语句
style_rules: {numbering, paragraph_length, tone, required_elements[]}
export: {page_size, margins, fonts, line_spacing, header, footer}
```

**⭐ `artifact_sources` 是全链路打通的证据**：全部蓝图里只用了 10 种取料来源，全是 T3/T4 的产物——
`process-flow.md`(19次) · `domain-model.md`(18) · `skill-design.md`(14) · `persona-insight.md`(11) · `opportunity-brief.md`(10) · `behavior-matrix.md`(10) · `event-storm.md`(9) · `journey-map.md`(7) · `brief.md`(7) · `domain-canvas.md`(5)

> **T3/T4 做得糙，这里就没料可取。** 学员到这一步才会真正理解为什么前面要认真做。

### 三个重点蓝图（HR项目 案例覆盖的那三本）

**`tender-document` 招标文件**（7 章 + 附件，继承可研 + 初步设计，tone `formal-legal`）
第四章「技术需求与服务要求」8000–12000 字是核心章。
**compliance 硬指标**：总分 100 分 · 资质无排他条款 · **预付款 ≤30%** · 须含格式模板 · 须声明采购方式及法律依据 · 技术需求逐条编号 · 知识产权归属明确

**`bid-document` 投标文件**（3 大部分共 11 个 chapter，继承招标文件）
第二部分技术文件拆成九条独立章节，其中「三、详细技术方案」**10000–18000 字，全篇最大**。
required_elements 8 项含**需求响应表 / 偏离说明表 / 进度甘特图 / 人员组织架构图**。

**`acceptance-package` 验收材料**（9 部分 + 附件）
含**需求跟踪矩阵**（招标需求→功能模块→测试用例→完成状态）。
**compliance 量化门槛**：跟踪矩阵 100% 覆盖 · **功能测试通过率 ≥98% 且 P1 缺陷归零** · 等保测评通过 · 培训覆盖率 100% · 决算不得超合同额

> ⭐ **这三本连起来，就是HR项目 那个项目的完整生命周期**——也是全部案例里唯一覆盖「招标 ↔ 投标 ↔ 验收」的。康养项目和学前教育项目都只到可研，接不到后面两段。

## 二、⭐ 写作专家：肖作仕（本步主教具）

### 它是什么

「解决方案专家 — 肖作仕」（`solution-expert-xiao.md`，3.5KB）。领域是**政府信息化项目建设方案 · 产教融合 · 人力资源数字化**。

**它同时是三样东西**：
1. **studio-docs 官方文档里的示例名**（模板、命令、SKILL 三处都拿它举例，还示范了命名规则 `解决方案专家-肖作仕` → `solution-expert-xiao.md`）
2. **三个真实项目的作者人设**：康养项目可研、学前教育项目可研（`_WRITING_BRIEF.md` 第 7 行标题就是「作者人设与文风（肖作仕）」，**44 章 / 653KB 正文按此纲领产出**）、HR项目 全套文书
3. **T6 的现成范本**——学员照着它造自己的写作专家

> ⚠️ **诚实标注（课上必须说这句）**：`_WRITING_BRIEF` 以肖作仕为作者人设是**硬证据**；但**"这些 docx 逐字由该 agent 生成"无法证明**（没有生成日志）。准确说法是"**按其文风纲领组织写作**"。
> **这本身就是 T6 的第一课**：连自己的案例都要区分"能证明的"和"听起来像的"。

### Writing Style 四维（造专家时要填满的）

| 维 | 填什么 |
|---|---|
| **① 语言标记** | 四字短语密度（高/中/低）· 对仗句式频率 · 递进模式（"从…到…""由…向…转变"）· 标志性表达 |
| **② 政策引用** | 引用格式模板（`《政策全称》（发文字号）`）· 偏好机关 · 引用密度 |
| **③ 段落模式** | 结构（论点+论据+价值阐述）· 字数区间 · 量化数据要求 |
| **④ 术语偏好** | ✅/❌ 成对列举，如 ✅信息化建设 / ❌IT建设、✅总体架构 / ❌系统架构、✅保障措施 / ❌风险应对 |

### 三种造法

| 方式 | 怎么做 | 什么时候用 |
|---|---|---|
| **A 分析参考文档**（最佳） | 给 1–3 篇样本 → 抽 6 类特征 → **先给你看 style profile 确认，再生成** | 手上有客户既往文书 |
| B 口述定义 | 你描述风格，它翻译成结构化维度 | 没样本但清楚要什么 |
| C 定制已有 | 读已有 writer 改 | 微调 |

**方式 A 的量化启发式表**（这张表值得单独讲，它把"文风"变成了可测量的东西）：

| 特征 | 度量 | 分级 |
|---|---|---|
| 四字短语密度 | 每段计数 | 高 ≥5 · 中 2–4 · 低 0–1 |
| 对仗句式 | 每页计数 | 高 ≥3 · 中 1–2 · 低 <1 |
| 政策引用密度 | 每章计数 | 高 ≥4 · 中 2–3 · 低 0–1 |
| 段落长度 | 每段平均字符 | 短 <150 · 中 150–350 · 长 >350 |
| 量化数据 | 每段数字/百分比计数 | 高 ≥2 · 中 1 · 低 <1 |

> ⭐ **SKILL 里有一条实操提醒，直接念给学员**：
> 客户说"我要一个像肖总那样的写手"时，**必须索要样稿**——**光有名字抓不到文风**。
> 这句话可以推广到整个 FDE 工作：**客户给你一个人名/一个标杆，你要的是那个东西本身。**

## 三、并行写作三段：plan → write → assemble

### `doc-plan-{type}.yaml`（plan-document 产出）

```yaml
document_type / blueprint / domain / writer / target / parts_dir / created_at
chapters:
  - id: ch1
    title: ...
    parallel_group: A          # A=无依赖先写  B=依赖A  C=汇总章最后写
    artifact_refs: [{path, usage}]
    estimated_words: ...
    split_strategy: single | by-section | by-subsection
    status: pending | writing | written | failed | manual
parallel_groups: {A: {max_concurrent: 3, chapters: [...]}, ...}
recovery: {retry_limit: 2, checkpoint_interval: 2000, fallback: manual|skip|template}
```

**拆分阈值**：<5,000 字符 → `single`（1 个任务）；5,000–15,000 → `by-section`（2–3 个）；>15,000 → `by-subsection`（4–6 个）

**覆盖度四分类**：✅Full · ⚠️Partial · 📝Auto（模板可生成，如项目管理、质量保证）· ❌Manual（如经费预算）

**⏸ 这里有一个硬性人工确认点**：会给你「章节×产物映射表 + 并行阶段图 + 统计 + Gap 提示」，你可以 approve / 改分组 / 预先标 manual / 调字数 / 排除可选章。

> **这个确认点是本步最该认真对待的地方**：它在告诉你**哪些章节没有料可写**。标 ❌Manual 的那些，就是你得自己去要数据的地方——**跟 T5 的 citations 取证清单是同一个动作。**

### `.parts/` 与写作

每章写成 `docs/{domain}/.parts/{chapter_id}.md`（如 `.parts/ch5a.md`），**纯 markdown、无 frontmatter**，子任务为 `ch5a-1.md`、`ch5a-2.md`。写完回写 doc-plan 的 `status: written`。**同 chapter_id 重跑直接覆盖（幂等）。**

**write-section 的自检 7 项**：编号约定 · 每大节 ≥1 Mermaid（若蓝图要求）· 数据密集节有表 · 政策引用 · 字数在区间 · 标题不跳级 · `[待补充：XXX]` **仅用于真缺数据**

> ⭐ **最重要的一条硬约束**：事实内容**一律来自 artifacts，禁止编造统计数字、政策文号、预算**。
> 这就是 B-10「错文号比空缺更有害」被写进工具的样子——**缺数据就写 `[待补充：XXX]`，不许圆。**

### ⭐ assemble：编号权在这里（B-1 / B-2 的机制化解法）

| 收口动作 | 怎么做 |
|---|---|
| **章级编号** | 按蓝图约定校验并**补缺重排**（缺"三"则四→三顺移） |
| **节级编号** | `（一）(二)` / `1. 2.` / `(1)(2)` 在**每章内独立重排**，校验标题不跳级 |
| **图表编号** | **统一在装配期分配**：图 `图X-Y`（caption 在图**下方**）、表 `表X-Y`（caption 在表**上方**） |
| **术语统一** | 读 writer 的 `## Terminology` 替换变体；**不替换**代码块、mermaid、`「」`/`《》`内直引 |
| **交叉引用** | **只校验不自动修**（章/节/表/图/附录五类） |

**前置**：**required 章缺失 → 停止装配**；part 文件 <10 行或不以 `#` 开头视为缺失。
**部分失败**：装配可用部分，并在缺口处插入 `> ⚠️ **本章内容待补充**` 占位块 + 失败原因。

> ⭐ **回收 B-1（图目计数漂移）**：康养项目 `_FIG_SPECS.md` 标题写"22 张"、表体实际 26 行，后补的图追加到表尾但头部计数没回改。
> **现在图表编号由装配期统一分配**——摘要与明细有了单一真相源。**并行产出必须有收口回改动作，这条纪律现在是机器在执行。**

### `.quality-report-{type}.md`

装配时间戳 · 章节清单(present/missing) · **术语替换日志**(含出现次数与行号) · 交叉引用校验 · 图表编号分配 · 合规清单 · 缺失章节建议

**6 条合规检查**：政策引用数 ≥ 蓝图下限 · required 章齐全 · 含投资/预算表 · Mermaid 数量 ≥ 下限 · 字数在区间 · 需要则有甘特

## 四、导出（export-document）

**依赖**：`pandoc` **唯一硬依赖，缺则 STOP**；`mmdc` 缺 → 保留 mermaid 代码块；`python-docx` 缺 → 只出裸 pandoc DOCX；Chrome 缺 → 跳过 PDF（可退 XeLaTeX）

**DOCX**：`pandoc {md} -f markdown -t docx --toc --toc-depth=3 -o {out}.docx`，再由 `format_docx.py` 做中文公文美化——
六步固定流水线：页面布局 → 标题 → 正文 → 表格 → 页眉 → 页脚。
**关键实现**：东亚字体通过 XML 直写 `w:rFonts/@w:eastAsia`（python-docx 不原生支持），行距 `240×1.5=360`，页边距上下 2.54cm / 左右 3.17cm，页眉取首个 Title/Heading 1 并加下边框线，页脚插 `PAGE` 域。

**PDF**：优先 pandoc → html5 → 注入中文公文 CSS（A4、仿宋 14pt/1.5、方正小标宋标题）→ Chrome headless 打印；兜底 XeLaTeX（`-V CJKmainfont="仿宋"`）

**Mermaid**：抽块 → `.export-temp/mermaid-{i}.mmd` → `mmdc -b white -s 2` → 替换成图片引用（保留原图题）→ 清理临时目录

## 五、B 线：平台文档套件（studio-platform）

```
/studio-platform:platform-docs {domain} [--output dir] [--steps ...] [--reference ref.pen]
```

**`--steps` 六个可选值**（逗号分隔，默认 all）：`brainmap` | `mapping` | `tech` | `plan` | `visual` | `speech`

**前置**：`studio/changes/{domain}/` 需有 `event-storm.md` 与 **`domain-map.md`**

| 步 | 产物 | 看点 |
|---|---|---|
| brainmap | `brainmap-index.md` + `brainmap-module-1~N.md` | 每个智能体固定 4 小节（技能清单 / 数据与知识依赖 / 模型与工具依赖 / 典型场景）；**agent 编号全局连续** |
| mapping | `agent-plugin-mapping.md` | ASCII 架构图 + 模块-Plugin 矩阵 + **覆盖率分析** + 依赖拓扑 + P0–P3 优先级 |
| tech | **5 份技术设计**（数仓 / 数据采集 / 知识图谱 / ML 模型 / RAG） | 数仓走 Kimball 分层；数据采集有 **6 维质量框架**；RAG 有**四路混合检索** |
| plan | `project-plan.md` | 固定 10 章 + Mermaid 甘特 + 6–10 条并行 track |
| visual | `{platform}.pen` | 4 帧（全景驾驶舱 / 角色智能体 / 知识网络 / 数智场景） |
| speech | `迎检话术-{platform}.md` | **与 .pen 四帧一一对齐**，要求朗读 **5–8 分钟** |

> ⚠️ `--steps all` 且无交互时**全程不暂停**，会一口气生成 11 类文档。**课堂上先跑 `--steps brainmap` 看一下再决定。**
>
> ⭐ `generate-speech` 的质量检查里有一条值得念：**"无其他行业项目残留术语"** —— 这正是 **B-11（模板复用的数字迁移污染）**在平台文档侧的同一个坑。工具知道这个风险，学员更要知道。

## 六、实操（90′）

| 序 | 做什么 | 时长 | 产出 |
|---|---|---|---|
| 1 | `/studio-docs:writer analyze <参考文档>` 造写作专家 | 25′ | `studio/agents/writers/{slug}.md`，四维填满 |
| 2 | `/studio-docs:blueprint list` 看内置蓝图，选一本 | 10′ | 选定文档类型 |
| 3 | `/studio-docs:generate <类型> <域>` 跑到 plan 确认点**停下细看** | 25′ | doc-plan yaml + **Gap 清单** |
| 4 | 让它写 1–2 章（不用写全本） | 20′ | `.parts/` 下的成稿 |
| 5 | assemble + 看 quality-report | 10′ | 装配稿 + 质量报告 |

**🔔 本步交付物**：写作专家 1 份 + **一节方案稿** + 一张配图占位 +（可选）导出的 docx

**🔔 难点**
- **造专家优先用"分析参考文档"方式**，2–3 页样本即可。没样本就去要——别凭空捏一个文风。
- **plan 确认点要认真看 Gap 清单**：标 ❌Manual 的章节就是你缺数据的地方，**列进取证清单，别指望写作时圆过去**。
- **关键数字一律引用不重算**（B-5）。分节作者各算各的，装配期必然对不上。

## 七、知识（讲什么）· 商业建模 + 交付物工程 + 合规治理

> 对应讲 4「FDE 七角色知识栈」的**栈④（商业模式与财务）· 栈⑥（交付物工程）· 栈⑦（合规治理）**。
> 栈①②在 T3/T4 讲、栈③在 T5a 讲、栈⑤（财评功能点）本步只做引用。
> **时间盒 30′**：栈④ 12′ · 栈⑥ 9′ · 栈⑦ 9′。要加时，从"三个蓝图快讲"那 10′ 里借。

### 〇 为什么这三栈捆在 T6 一起讲

讲 4 的原命题是：**FDE 不是"会建模的人"，是七个专业角色的方法论合体；建模只是七分之二。**

这三栈捆在一起，是因为**它们共同决定了客户手里那份文件能不能签字**：

```
栈④ 商业模式与财务  → 决定文件里"这生意怎么成立"那几章有没有内容
栈⑥ 交付物工程      → 决定这些内容能不能被组织成一份能过评审的正式文书
栈⑦ 合规治理        → 决定这份文书经不经得起一句"这个数据/文号哪来的"
```

> **讲义原话**：多数技术出身的人**不是倒在建模，是倒在栈④⑤⑥**——盘不出账、过不了财评、组织不起百页交付物。
> T6 就是这三块塌陷的正面战场。

### 栈④ 商业模式与财务（12′）· 商业顾问的方法论

**【原本是谁】** 商业顾问 / 战略——负责回答"这事怎么挣钱、谁付钱、付多少、几年回本"。
**这是最多技术型 FDE 完全空白的一维**：能出 7 域本体，却搭不出一个能自洽的商业模式，方案在客户那边就是"技术很好，但不知道怎么赚钱"。

#### ① 商业模式设计五件套（先有工具，再看案例）

| # | 框架 | 内核 | 一句话记法 |
|---|---|---|---|
| **①** | **商业模式画布**（Osterwalder & Pigneur, 2005） | **9 个模块**：右侧价值面＝客户细分/价值主张/渠道/客户关系/**收入来源**；左侧效率面＝关键伙伴/关键活动/关键资源/**成本结构** | 画一张就能和客户对齐"这生意怎么转"的通用底图 |
| **②** | **免费 / 交叉补贴**（Chris Anderson《Free》） | 四型：**直接交叉补贴**（剃须刀送、刀片赚）· **三方市场**（用户免费、广告主付）· **Freemium** · **非货币市场** | **关键是想清楚"谁被补贴、谁来买单"** |
| **③** | **互联网三级火箭**（周鸿祎/360 · 梁宁） | 一级**头部流量**（免费高频入口）→ 二级**沉淀用户**（锁进商业场景）→ 三级**商业闭环**（低频高价变现） | 从高频到低频；**一级不赚钱，要有人扛得住** |
| **④** | **SaaS 指标体系** | MRR/ARR · CAC · LTV · **LTV:CAC ≥ 3:1** · Churn · **NRR > 100%** · **Rule of 40**（增长率+利润率>40%） | 订阅制生意的**专用财务语言** |
| **⑤** | **增长思维**（梁宁） | **北极星指标**（全公司只对齐一个）+ 四个增长关卡（机会拿捏→模式取巧→组织扩容→战略借势） | **"增长能力＝持续作出正确决定的能力"** |

#### ② ⭐ 本栈最关键的洞察：**财务语言随"交付模式"变**

| 交付模式 | 商业模式底色 | 该用的财务语言 | 别用错 |
|---|---|---|---|
| **模式二 · 大平台建设+运营**（康养项目/草业项目/辣椒） | 重资产、投—建—运、多元收入 | **投资估算 / EBITDA / IRR / NPV / 回本周期** | **别用 MRR**——一次性建设+运营盘不是订阅 |
| **模式一 · Token 计费 SaaS**（教育督导项目/草业项目 SaaS 层/辣椒 OQL 按量） | 轻资产、订阅/按量、可复制 | **MRR/ARR / LTV:CAC / NRR / Churn / Rule of 40** | **别用 IRR/回本年**——SaaS 早期没有"回本年"这回事 |

> **一句话记死**：客户问模式二的项目，你答 **IRR 15.2%、第 9 年回本**；客户问模式一的 SaaS，你答 **LTV:CAC 3:1、NRR 120%**。
> **答反了，客户当场就知道你没做过这类生意。**

**这条直接影响 T6 的写作动作**：`feasibility-study`（可研）蓝图里的效益分析章，用的是模式二语言；如果你的命题其实是模式一 SaaS，**照着可研蓝图硬写 IRR，写出来就是空的**——这也是 checkout 里"蓝图选型说得出为什么"那一条的真实理由。

#### ③ 范本：康养项目 BP 就是"交叉补贴 + 三级火箭"的活体

康养项目 BP + 财务测算 Excel 模型（`嘉城数联医康养生态运营财务测算模型.xlsx`），用上面的框架能一层层拆开：

| 段 | 康养项目的答案 | 对应框架 |
|---|---|---|
| **顶层逻辑** | 门诊医疗引流 → 照护康养创收 → 产品增值补充 → 政企合作加速 | **三级火箭**：门诊医疗＝一级（低毛利引流入口）· 会员沉淀复购＝二级（患者锁成会员）· 照护/商城/长护险＝三级（高毛利变现） |
| **收入结构（谁付钱）** | **三元支付** ＝ 老人自费 + 长护险（PICC 康养项目已打通全闭环）+ 政府购买服务 | 画布的"收入来源"多渠道；本质是**交叉补贴**——政府/长护险补贴了老人自付不起的那部分 |
| **最小验证单元** | 微康养单店模型：峰值资金约 **73 万**、**约 21 个月回本**、单站 1.5–5 人，**60 站可复制** | BP 的说服力来自"**一个单元跑通、可复制**"，不是"整盘很大" |
| **增长引擎** | 会员转化复购飞轮（中医理疗 + 长者食堂 + 康养商城三线咬合） | 画布的"客户关系"+ 增长思维 |
| **主体与分账** | 投—建—运分离（EPCO）、**项目联合体**、分账核算 | 回答"钱怎么进、谁分、独立定价"。⚠️ 2026-07-20 起禁用"合资公司/股权/注册资本" |

#### ④ 一个 Excel 财务模型里的基础概念（技术人最缺，务必讲清）

| 概念 | 是什么 | 康养项目的数 |
|---|---|---|
| **EBITDA**（息税折旧摊销前利润） | 营收减经营成本，但**加回利息、税、折旧、摊销**——衡量**主业本身的现金创造能力**，剔除"怎么融资、怎么折旧"的干扰 | 基准口径 **约 5219 万/年**（营收约 **3.83 亿/年**、净利约 **3535 万**） |
| **IRR**（内部收益率） | 使**净现值 NPV = 0** 的那个折现率——通俗说是项目每年的"复合回报率"，**必须跟一条门槛线比** | **运营口径 15.2%（第 9 年回本，主口径）** vs **发改口径 8.7%（第 11 年回本，仍高于国企 6% 门槛）** |
| **NPV**（净现值） | 未来每年净现金流按折现率折回今天再求和，**>0 才值得投** | — |
| **回本周期**（Payback） | **累计净现金流由负转正**的那一年 | 第 **9** / **11** 年（两套口径） |

**⭐ 一句话串起来（模式二重资产语言）**：
```
营收 − 成本 = EBITDA（主业赚钱力）
  → 扣息税折旧 = 净利
  → 逐年净现金流折现求和 = NPV
  → 令 NPV = 0 的折现率 = IRR
  → 累计转正之年 = 回本
```
**这五个数，就是 To-G 大平台项目签字前客户和财评专家盯的那几行。**

> ⭐ **两套 IRR 口径并存不是矛盾，是财务常识**——算的钱流范围不同（**运营口径**只看运营主体分到的，**发改口径**看整盘）。
> ⚠️ 口径名以成品可研为准：叫**运营口径**，不叫"合资口径"（"合资"2026-07-20 起已禁用）。
> **课上必须把这句说出来**，否则学员看到"15.2% 和 8.7%"第一反应是"数据打架"，然后自己去改一个——**那就正好踩中 B-5（关键数字必须锚在单点，一律引用不重算）**。

#### ⑤ 换成模式一 SaaS 的语言（同一件事、另一套数）

如果做的是教育督导项目那种订阅/按量的 SaaS，客户不问"几年回本"，问的是：
**获客花多少（CAC）· 一个客户一辈子贡献多少（LTV）· 这两个比值健不健康（LTV:CAC ≥ 3:1）· 客户跑不跑（Churn）· 光靠老客户能不能增长（NRR > 100%）· 整盘增长+利润够不够格（Rule of 40）。**

> **FDE 要能在两套语言间自由切换**——这就是本栈"自评到能交付"的标准。

#### ⑥ 栈④ 与栈⑤（财评）的接口：一句话交代

商业模式回答"**这生意成不成立**"，财评回答"**这笔钱算得准不准**"。
- 学前教育项目走的是财评这条线：**484 个功能条目 → 约 27,056 功能点（FP）→ 约 22,014 人天 → 总投资 4,839 万**（三重依据交叉校核）。
- 康养项目走的是投资回报这条线：**一期 1.36 亿（依托条件，不计入本轮新增）+ 二期 3200 万（五块预算）→ 运营口径 IRR 15.2% / 发改口径 8.7%**。

> **两条线在可研里是两章，但共用一条纪律：数字锚在单点，谁都不许在自己那节重算。**

### 栈⑥ 交付物工程（9′）· 方案/标书工程师的方法论

**【原本是谁】** 方案经理 / 标书工程师——负责把一堆认知与测算，组织成**一份能中标、能过评审的正式交付物**。

**【内核 + 权威参照】** 发改委《政府投资项目可行性研究报告》编制大纲 / 各地可研编制规范（章节结构、政务文风、依据引用、图表规范）+ 招投标响应文件的组织。
**本课程把它固化成三件东西**：**肖作仕写作规范**（四字对仗 / "依托…构建…实现…"递进 / 标题层级 / 红线表述）+ **锚定口径机制 `_WRITING_BRIEF.md`** + **装配质检**。

**【康养项目/某工业城市怎么用】**

| 项目 | 交付物规模 | 组织方式 |
|---|---|---|
| 康养项目（🟢唯一全域编译交付） | 可研 **11 章 / 约 11 万字 / 26 图** + 2 附录 docx，格式对齐客户既有模板 | **35 个分节并行写作**，靠一份 `_WRITING_BRIEF.md` 统一口径；**编号权归装配阶段**（防 B-2） |
| 学前教育项目（🟢可研满配·建模半配） | 可研 **653KB / 44 分章** + 送审报价包 + 单一来源论证 | 同一套打法；**没做本体建模、没有 persona/journey，照样交付** |

> **这一栈就是把前面几栈的产物"落成客户手里那份文件"的能力——没有它，你脑子里有 7 域本体，客户手里什么都没有。**

#### ⭐ 并行写作的三条铁律（本步的操作定义）

1. **口径单点** —— 所有数字锚在一份 BRIEF，**分节作者一律引用不重算**（**B-5**）
   > 反例根因：县区七普老龄化率在跨节引用中**60+ 与 65+ 两个口径被混用**。不是笔误，是**没建立"单一真相源"的纪律**。
2. **编号权归装配** —— 写作阶段只管本章内部，跨章编号一律由 `assemble-document` 重排（**B-2**）
3. **占位符即契约** —— slug 必须先定后画，不可事后改名（**B-3**，T7 会再撞一次；T8 的校验器"引用的脚本必须真实存在"是同一条）
   > 配套回收 **B-1**：康养项目 `_FIG_SPECS.md` 标题写"22 张"、表体实际 26 行——**摘要与明细必须有单一真相源**，现在图表编号由装配期统一分配。

> **三条铁律都不是"建议"，是被工具执行的**——这就是"平台＝方法论固化物"在 T6 的兑现。

### 栈⑦ 合规治理（9′）· 合规官的方法论

**【原本是谁】** 合规官 / 法务——负责守红线、给每条涉规论断挂**可核验的官方现行依据（citations）**。

**【权威体系】** 等保 2.0（**GB/T 22239-2019**）·《个人信息保护法》·《数据安全法》·《生成式人工智能服务管理暂行办法》，及行业国标/法规。

#### 三态诚实（写作时的三选一）

| 情况 | 怎么写 |
|---|---|
| 查到了**现行有效**的 | 挂标准号 + 发文字号 |
| 是常识 | 标"通用"（T5 的 source 三态同理） |
| **查不到** | **留占位 + 锚定上位国标 + 转取证清单** |

**康养项目的实数**：**18 处挂已核验国标/法规**（等保、养老机构服务安全 GB 38600-2019、DIP 医保办发〔2020〕50号、长护 医保办发〔2021〕37号、个保法第 6/15/29/47 条…）；**11 处坚决保留 `[本地待补文号]`**（7 本地文号 + 4 企业 SOP），每处锚定上位国标、转成向医保局/民政局/政数局**逐项取件的清单**。

> 内部原话：**"错文号比空缺更有害。"**（**B-10**）

#### ⚠️ 反例 B-6（标准号误标）

康养项目编制期两处真实误标：
- 药食同源目录被误标为 **"GB 药食同源目录"**——它根本不是 GB，是原卫生部/卫健委发布的名单；
- 星评标准沿用了**已废止的 MZ/T 标准**——标准还在，版本已废止。

> **引标准必须核到官方现行版本**："看起来像国标"不等于是国标，"标准存在"不等于"现行有效"。
> **已废止比查不到更危险**，因为它看起来完全合规。
> 硬动作：用"全国标准信息公共服务平台"核现行/废止，用"国家法律法规数据库"核法规。

#### ⭐ 复调：三个场景，同一条判据

栈⑦的"诚实边界"不是 T6 一册的局部纪律，它在全课程出现三次——**这是复调，不是重复**：

| 场景 | 说法 | 在哪讲 |
|---|---|---|
| **B-10** | 查不到的文号**留占位不编造** | T5 / **T6 栈⑦** |
| **B-11** | **别人的数字不是你的数字**——模板可复用，数字不可复用 | T1 / T6（`generate-speech` 的"无其他行业项目残留术语"检查） |
| **T7 Mock 边界** | **Mock 不能说成跑通** | T7 |

> **三者是同一句判据的三个场景**：**空缺可以补，编造无法挽回。**
> T7 会把这条推到第四个场景——**外部事实分官方/二手/未获证实三档，"未获证实"要亲口念出来**。
> **课上要把这个复调关系点破**：学员会以为"合规"只是可研最后一章的事，其实它是这门课的价值观支点。八步工具练的是手艺，这一条练的是**能不能把手艺交给你**。

|---|---|---|

### 口播 · 为什么是"角色合体"，不是"技能清单"（开场 3′）

"上一版这一讲我讲'五维知识栈'，讲浅了。今天换个讲法，也是更真实的讲法：你要成为 FDE，本质上是要**一个人干完过去七个岗位的活**。传统模式做康养项目这种项目，会议室里坐七种人——产品经理定需求、架构师切系统、知识工程师建图谱、商业顾问搭模式、财评专家算功能点、方案经理写标书、法务把红线。他们各说各的行话，交接处全是信息衰减（这就是第 1 讲的交付断层）。FDE 消除断层的办法，不是协调这七个人，是**把这七套方法论装进自己脑子**，一个人从头跑到尾。所以这一讲不是七个技能点，是**七个角色的方法论体系**，每一个我都给你一本业界压舱的经典——你补哪一栈，就去啃那一本。"

### 口播 · 转入自评：你能做几分之几个 FDE（过渡话术）

"七栈讲完，别急着觉得'我大概都沾一点'。现在去工作坊做两件残忍的事：第一，**按七个角色给自己逐个定级**（这一栈你到 L1 还是能独立交付的 L3），画出七维雷达——你会看到明显塌下去的一两根轴，多数技术出身的人塌在**栈④商业模式 / 栈⑤财评 / 栈⑥交付物**。第二，为最弱那一栈，**翻开它对应的那本经典的一章，读完写一页'怎么用到康养项目/我的项目'的笔记**——不是读后感，是能用的动作。48 分钟。雷达不是让你自我感觉良好，是让你看清你现在能做**几分之几**个 FDE。"

### 口播 · 难听话：建模只是七分之二

"你以为 FDE 就是会建模？建模只是七分之二。你能交出 7 域本体、3835 行骨架——很好，那是栈②栈③。客户翻到可研最后一章问你'总投资多少、功能点怎么算的、IRR 几年回本'，你答不出某工业城市那样的'27,056 功能点 / 4,839 万'、答不出'15.2% 第 9 年回本'，你就只是个更贵的建模师，不是 FDE。缺的那五个角色，不会因为你建模漂亮就自动长出来。"

### 口播 · 讲师收口：唯一能靠努力补上的部分

"七套方法论是这门课里**唯一能靠努力补上的部分**——上一讲的 C7 补不了，这一讲的七栈全能补，而且我把七本压舱经典都给你了。所以别在这找借口。雷达上那根短轴，就是你和'完整 FDE'之间的距离——它可量化、可补、也**藏不住**。还有一句要记住：**七栈不是让你成为七个专家，是让你样样够用、缝缝对齐、边界自知**。真专家该上场时（比如复杂财评、重大法律风险），你要认得出'这里该请专家了'——这也是能力半径的一部分。"
