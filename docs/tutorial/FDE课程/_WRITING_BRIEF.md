## 二·补 案例库 —— FDE 两大交付模式（主轴，详见 `案例矩阵_跨项目对照.md`）

> **核心框架**：四个真实项目 = **两大 FDE 交付模式**的实例（不按行业分，按交付模式分）。FDE 的第一个判断是"这是哪种模式的活"。任何 callout 引用必须带下表"成熟度状态"标签，不得拉平当等同实证。

**模式一 · Token 计费智能体 SaaS 应用**（轻/快/产品化/按量计费/agent 即产品）
- 交付物=可跑 agent 应用+本体+HIL；商业=按 token/调用/席位计费、无运营盘；团队轻（1 FDE + 平台组）；HIL 命门在应用内裁定/质检闸。
- 代表：**教育督导项目**。注："Token-SaaS"是 C-Life 商业定位；教育督导项目源材料述其"平台赋能/游学并行外挂"、未见计价表，讲"定位为按量 SaaS"不编单价。

**模式二 · 大型平台建设 + 生态运营**（重/长周期/投建运/多元收入）
- 交付物=可研+平台建设+运营+财务测算+本体+多端；商业=投建运+运营盘+碳汇/交易/数据要素；团队重（主理 Lv.3 + 见习 + 平台组）；FDE 全链 S1–S7 尤重 S5 合规/S6 可研/商业建模；HIL 命门=增收闸+监管发布闸+凭证闸。
- 代表：康养项目（标杆）、草业项目、辣椒。

## 三、观点主张（全课程反复回收，措辞对齐）

1. **FDE 的核心资产不是"会用 AI"，是把客户模糊意图压成可执行结构**（证据：102 事件 → 7 域，模型不替你做判断）
2. **没有工程化平台的 FDE 只是"更累的架构师"**（证据：7 域同日并行编译、7/7 零悬空引用）
3. **FDE 专业性一半体现在"敢说不知道"**（证据：11 处占位不编造）
4. **C1–C6 可训练，C7（客户关系/责任承担/价值判断/政治敏感度）只能筛选**（**L1 一人公司 OPC 段**第一次讲透 → **L8 OPC 边界回收段**第二次说；无法用实操训练）
5. **HIL 设点四条硬判据：不可逆 / 涉钱 / 涉合规 / 跨组织**，命中任一即插人；**另加一条"置信度兜底闸"**（模型置信度低于阈值即转人，康养项目占位 0.75）——四判据看动作性质、兜底闸看模型把握。闸分两层：能固化成硬规则的走自动闸（引擎确定性回滚），判不了/涉钱涉合规的才上人工闸 HIL（**L5 下半场**核心：★两道闸）
