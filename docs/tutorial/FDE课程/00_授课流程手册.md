## 〇、三句话说清这个工作坊

1. **先给地图，再上路。** L1 用一整个上午把「FDE 是什么」讲透，**包括 SOP 七阶段和它对应后面哪一课**——学员知道自己在练什么。
2. **L3–L7 每课同一个骨架**：目的 → 启发 → 沉浸（真实案例）→ 实操（本组命题，**产物落盘**）→ checkout。
3. **验收不看"讲得好不好"**，看学员能不能独立走完认知侧全链条，**并且知道自己在哪里必须叫人**。

## 二、D0（选修）· 专题课 S1–S3 · **本体线**

> **专题课有两条线，别混**：**S1–S3（本体线）排在 L5 之前，就是本章**；
> **A1–A3（工具链线）排在八课之后，见第八章。**

> **专题课是选修的，共三门 × 180′ = 540′。** 开不开、开几门，按下面的判据决定——
> **不是"时间够就加"，是"这批学员需不需要"。**
> **教材来源与八课不同，三门各不相同**——口径隔离见 `_WRITING_BRIEF.md` 第八节。

### 三门课是一条线，不是三个散课

| | 回答 | 教材 | 形式 |
|---|---|---|---|
| **S1 · 本体论** | 本体**是什么**、为什么必须有 | 《工程师的本体论》方法论文集 | 纯讲解 180′ |
| **S2 · 本体引擎的工程实现** | **怎么造出来** | `clife-onto-engine` 源码 + 内核"宪法" | 讲解 + **当场读码** 180′ |
| **S3 · 建模端如何支撑引擎** | **怎么给它编译应用**（架构图右下角那个橙色框） | **我们自己的 `studio-ontology`**（一档）+ 信通院分析（二档，一节） | 讲解 + **管线走查** 180′ |

**终点是 L5**：S2 讲运行时端，S3 讲建模端，**L5 把两端接起来，学员亲手交一个能跑的插件。**

> **顺序上不能破的三条**：**S2 在 S3 前**（S3 要回扣 S2）· **S3 在 L5 前**（S3 第十一章是交棒章）· **S1 在 L5 前且尽量相邻**。

| 症状 | 处置 |
|---|---|
| "我们已经有数据中台了" | **别否定**——先肯定"这件事做成了"，再讲边界：**只管数据的流动，不管业务的逻辑** |

## 八、D6+（选修）· 专题课 A1–A3 · **工具链线**

> ⚠️ **和第二章的 D0 不是一回事。**
> **S1–S3 排在 L5 之前**（本体线，是 L5 的前置）；**A1–A3 排在八课全部结束之后**（工具链线，是八课的进阶）。
> **顺序反过来上会废掉 A3**——A3 的实操素材直接来自第五课的产出。

### 三门课是一条台阶，不是三个散课

```
零级   用内置的                    ← 八课全程停在这一级
二级   自定义专家（A1）            ← 让工具懂你的行业
三级   写自己的插件（A2）          ← 把工具变成你的工具
四级   回贡上游（A3）              ← 让别人也用上你的东西
```

**A 系列讲的不是本体，是「astra-studio 这套工具本身怎么改、怎么扩、怎么往回推」。**
**落点是：学员从工具的使用者变成工具的贡献者。**

| | 时长 | 形式 | 硬产出 |
|---|---|---|---|
| **A1 · 自定义智能体** | 180′ | 讲解 + 实操 | 一个能被选中的专家 `.md` |
| **A2 · 扩展插件** | 180′ | 讲解 + **当场读码** | 一张真实插件的解剖图 |
| **A3 · 回贡上游** | 120′ | 讲解 + **实操（真的提一个）** | **一个 PR / issue 链接** |

### 怎么排

| 档 | 怎么排 |
|---|---|
| **集训档（5 天）** | **A 系列不进 5 天**。集训结束后另择 1.5 天：**Day A** A1 上午 + A2 下午 · **Day B 上午** A3 |
| **分散档（8 周）** | 第 9–10 周。**A2 要读源码，学员需要有过一次完整交付的手感** |
| **只上一门** | **上 A1**——从"会用工具"跨到"能改工具"的那一步，成本最低 |

**顺序上不能破的两条**：
1. **A 系列必须在 L5 之后**——A3 的素材来自第五课发现的那六处「文档说 A、代码是 B」
2. **A1 必须在 A2 之前**——A2 的 `expert-scoped` trait 要回扣 A1 的专家发现五步

### 讲师要额外准备什么

| | 准备什么 |
|---|---|
| **A1 / A2 共同** | **提前 clone `Ameng2001/astra-studio-plugins`**——两课都要当场翻文件 |
| **A1** | 提前跑通一次 `/studio-core:create-expert`；准备一个**故意写坏 `## Your Domain`** 的专家用来演示「静默失效」 |
| **A2** | 提前 `ls fund-review/scripts/` 一遍——**课上要当场数出 38 个脚本、12 个 `scan_*.py`** |
| **A3** | ⚠️ **建好内部 fork 并把地址写进 T-1 天通知**（学员提到这里，不直提公开上游）；<br>**确认学员有 GitHub 账号、且已被加进内部 fork 的协作者**（这是最常见的现场卡点）；<br>自己先走一遍完整流程：内部 fork 开 PR → 转提上游 |

### A1 · 09:00–12:00（180′）

| 时段 | 讲什么 | 讲师动作 |
|---|---|---|
| 0–30′ | 查找顺序就是设计 | **当场打开 `studio/agents/` 和内置 `agents/`**，让他们看到两个目录 |
| 30–70′ | 动态发现五步 | ⭐ **指着"扫内置时跳过同名"那一步说：覆盖就发生在这一行** |
| 70–100′ | ⭐ **专家是复核者不是生成者** | **本课的题眼**——主角色出初稿，专家只挑"不正确 / 过度简化 / 遗漏" |
| 100–135′ | 专家文件四部分解剖 | **`## Your Domain` 决定被不被选中**；**Quality Criteria 最难写也最值钱**（哪些错危险、哪些只是难看） |
| 135–180′ | **实操：写一个行业专家** | 巡场只查两件事：**Domain 写得够不够具体**、**Quality Criteria 有没有分"危险 vs 难看"** |

> **卡点**：学员写完不被选中 → **不报错，只是不出现**。**这就是"静默失效"，别急着帮他修，先让他体会一次。**

### A2 · 13:30–16:30（180′）

| 时段 | 讲什么 | 讲师动作 |
|---|---|---|
| 0–40′ | fund-review 是什么 | 强调：**它是工具链的产出物，不是工具链的一部分** |
| 40–75′ | 红蓝对抗 | ⚠️ **必须补一句：两个智能体都没有 Write 权限** |
| 75–120′ | ⭐⭐ **但对抗不是重点** | **38 个脚本 : 2 个智能体**——当场 `ls` 数给他们看。**能写成确定性脚本的绝不交给模型（确定 / 可测 / 便宜）** |
| 120–150′ | 插件骨架 + Plugin Traits | "Traits 是观察结果，不是配置项" |
| 150–180′ | **两级工作区** | `studio/changes/` 只放设计 · `{target_dir}/` 只放实现 · `status.json` 连接 = **B-5 单一真相源** |

> **卡点**：一半人会被"红蓝对抗"吸引住，然后忽略 38:2。**第 75 分钟要用力拐这个弯。**

### A3 · 09:00–11:00（120′）

| 时段 | 讲什么 | 讲师动作 |
|---|---|---|
| 0–10′ | 为什么回贡（对你自己的四条好处） | 别讲成鸡汤，讲第 ① 条（定制不再是孤儿） |
| 10–30′ | **四档门槛 + 你手上已经有的素材** | ⭐ **本课最重要的一段**——让学员当场翻第五课手册，**找出那六处落差里最有把握的一条** |
| 30–55′ | ⚠️ **该仓没有 `CONTRIBUTING.md`** | **坦率讲这个现状**，然后立刻转成机会：**补一份就是最容易被接受的第一个 PR** |
| 55–70′ | ⚠️ **两段式** + PR 描述四段 | **先讲两段式**（提到内部 fork，你课后统一转提），再讲四段。⭐ **"为什么"那段决定命运**——念一遍反例、再念一遍正例 |
| **70–110′** | **实操：真的提一个**（**提到内部 fork**） | 巡场四个抓手：**还在纠结"配不配"的 → 直接让他提 issue**；**"为什么"只写一句的 → 当场重写**；**没跑就想提的 → 按住**；**⚠️ 把项目原文整段粘进 PR 描述的 → 当场删客户名和商务数字** |
| 110–120′ | 被拒了怎么办 + 收链接 | **每人念一遍自己在内部 fork 上的 PR / issue 链接。没有链接 = 没完成**。<br>**当场给出你的复核与转提时间点**（例如"本周内转提，上游链接回传"）——**别让它悬着** |

> **降级方案要提前说**：素材不成熟的，**在内部 fork 提一个 issue 也算完成**——第五课那六处落差随便挑一处，十分钟。
>
> ### ⚠️ **两段式：学员提到内部 fork，讲师课后统一转提公开上游**
>
> ```
> 学员（课上）  内部 fork → 分支 → 改 → 本地测通 → 向内部 fork 的 main 开 PR
> 讲师（课后）  复核 + 脱敏检查 → 从内部 fork 向公开上游统一转提 → 上游链接回传
> ```
>
> **开场就要交代，别等到第 55 分钟**——把内部 fork 地址写在白板上。
> **⭐ 必须补一句"转提时写明原作者、上游链接回传给你"**，否则会有人觉得自己的活被截胡了。
>
> **脱敏是两道关**：**学员自己先过一遍**（不带客户名、不带商务数字），**你转提前再查一次**。
> **上游是公开仓库——推上去之后，删掉也还在 git 历史和各种镜像里。**
