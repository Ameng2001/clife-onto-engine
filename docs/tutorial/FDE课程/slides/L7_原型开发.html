② 启发 · 工具 2/3 · 实测澄清

.pen 到底是什么

实测结论

本地三份真实 .pen（含一份 1.7MB 的）都是明文 UTF-8 JSON，顶层键 children / variables / version，version: 2.10，首节点 type: frame。
所以 把 .pen 当普通 JSON 直接读写的路子是成立的。
插件的 CLAUDE.md 里"需要 Pencil MCP"的说法，与本地实际文件不符。

结构四层

frame（屏）→ 布局区 → 组件组 → text / icon_font / ellipse

尺寸标准

桌面 1440×900
移动 390×844

它明确不做

不生成代码 · 不建 OpenSpec
不需要 Pencil 桌面端 · 不处理动效交互

令牌就是设计层的"口径单点"——
和第六课的 BRIEF 数字单点是同一个思想。

颜色必须走 $variable，不许写死色值——这就是为什么追加帧能自动统一风格。

.pen

【这一页本身就是"别信文档，去看代码"的又一个实例】"插件文档说需要 Pencil MCP，我们打开文件一看，就是普通 JSON。第五课六处、第六课九处、今天又一处——你们该形成条件反射了：文档说 A，先去看看代码是不是 B。"

【令牌 = 口径单点，这个类比要点破】第六课的数字锚在 BRIEF 单点，这里的颜色锚在 $variable 单点。同一个思想在不同层的两次出现。

⭐ 帧 → 能力的映射规则

.pen 里→ OpenSpec 里
同一页的不同状态帧
"1. 空状态" / "1a. 下拉展开" / "1b. 已提交"		一个能力，多个 Scenario
不同页不同能力
reusable 组件共享能力或横切需求

五类需求：①Layout 布局（含具体像素）②Component 组件（占位符文案直接取自 .pen 的 content）③State 状态 ④Navigation 导航（含 active 高亮）⑤Visual 视觉

③ 出代码时，它不按 tasks.md 的原序做

layouts → shared components → feature components → pages → routes → integration
# 逐条 Scenario 心算校验 WHEN/THEN/AND，不满足就补逻辑；最后回写 tasks.md 打勾

⚠️ 两个已知坑：spec delta 模板缺 ADDED/MODIFIED/REMOVED 包裹（按 guide 补）；生成路径用 app/ 而技术栈规定 frontend/src/app/，要人工对齐前缀。一条硬纪律：未经询问不得新增 npm 依赖。

映射规则

【"同一页不同状态帧 = 一个能力多个 Scenario"是最需要理解的一条】学员容易把每一帧都当成一个页面，结果 spec 里冒出一堆重复能力。画状态帧的时候就要想清楚它是"另一个状态"还是"另一个页"。

② 启发 · 直接关系诚实边界

缺信息时的兜底约定 = 你的 Mock 清单

缺什么它怎么做
缺 APImock 数据 + TODO: connect to API
缺状态管理本地 useState + TODO: lift state
缺鉴权TODO: add auth guard
缺错误态基础 error boundary + TODO: improve error handling

这些 TODO 就是你的 Mock 清单。
别删掉它们。

演示前把它们 grep 出来，就是一份现成的"哪些是假的"说明。
删了 TODO 不等于实现了功能，只等于你看不见了。

Mock 清单

【这一页是本课最实用的一页】学员会觉得"Mock 清单"是个额外的作业。不是——工具已经替你标好了，你只要 grep 出来。

【"删了不等于实现了"要说重一点】每年都有学员为了让代码"看起来干净"把 TODO 删掉。那就是从"诚实的 demo"变成"骗人的 demo"的那一步。

③ 沉浸 · 落到你自己身上

你的 demo 在哪一档？

档你的 demo 是演示时必须说
A壳真 + 数据真 + 模型真（还没有人到这一档）
B壳假 + 数据真"界面是原型，数据是客户真实数据，AI 回答是预设的"
C壳假 + 数据假"这是交互外壳，数据和 AI 回答都是演示用的，不是模型跑通"

说不出自己在哪一档
→ 路演一票警示。

⚠️ 演示顺序不能反

必须先说清哪些是 Mock（哪屏的"AI 回答"是写死的、哪块数据是假的），再展示交互。
反过来做，前面说的一切都成了事后免责声明。

三档自评

【A 档那句"还没有人到这一档"要说】包括康养项目。这门课里没有任何一个 demo 是模型真跑通的。 承认这一点，学员才不会觉得"三档自评"是在为难他们。

【顺序不能反，讲一个反例】先演一圈把客户逗乐了，最后补一句"当然这还是原型"——客户只会记得前面那一圈。那不叫诚实标注，那叫事后免责。

同一条纪律，第四个场景

场景纪律在哪一课
查不到的文号留占位，不编造（B-10）第五课
别处模板的数字复用模板可以，复用数字不行（B-11）第三课

四个场景是同一句判据的四次出现：
空缺可以补，编造无法挽回。

第一课讲这条纪律时用的是 Palantir 的招聘页，
本课用的是你自己的 demo——对象换了，判据没换。

四场景

【收口话术，照念】"你们在第一课听我念'未获证实'的时候，可能觉得那是我谨慎。今天你们自己做了个 demo，它的 AI 是 Mock、数据是假的。下周你拿它去见客户，你会怎么说？
说'我们做了个智能体'——没错，但客户听到的是另一件事。
说'这是交互外壳、AI 是预设回答、数据是演示数据'——你会紧张，觉得掉价。但这一句话，就是客户以后愿不愿意信你第二次的分界线。"

【难听话】"你觉得'查不到就写未获证实'很简单？那你回顾一下第一课——我念了十几条外部事实，你能当场分清哪条是官方、哪条是二手、哪条是网传吗？分不清，你就没资格拿 Palantir 给客户站台，你只是在转发朋友圈。"

⚠️ 四个翻车点

其中一条是我们自己的诚实标注

1. 别把外壳当交付（一票警示）

演示时必须先说清哪些是 Mock，再展示交互。顺序不能反。

2. 目录前缀要人工对齐

生成的是 app/，技术栈规定的是 frontend/src/app/。工具不会自动加前缀。

3. spec delta 缺三段包裹

模板没写 ADDED/MODIFIED/REMOVED，按 guide 补。

4. 端到端尚未实测（诚实标注）

本课的 .pen 格式结论来自对现存文件的实测。
但"跑一次 screenshot-to-pencil 然后用 Pencil 编辑器打开产物"这条端到端链路还没实测过。

把第 4 条写在手册里，
本身就是本课要教的东西。

翻车点

【第 4 条是全课最重要的一次身教】"这门课教你们诚实标注。那我们自己呢？ 这条链路我们没跑通过，所以我在手册里写了'尚未实测'。我完全可以不写——你们也查不出来。但那样我就没资格站在这里讲 B-10。"

【首次开课前建议补跑一次】如果讲师课前补跑了，把结果当场更新给学员看——那比什么都好。
