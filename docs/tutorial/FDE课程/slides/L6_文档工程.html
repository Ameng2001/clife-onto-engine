② 启发 · 栈④ 商业模式与财务 1/2 · 12′

⭐ 财务语言随"交付模式"变

交付模式商业模式底色该用的财务语言别用错
模式二 大平台建设+运营
康养项目 / 草业项目 / 辣椒		重资产、投—建—运、多元收入投资估算 / EBITDA / IRR / NPV / 回本周期别用 MRR——一次性建设+运营盘不是订阅
模式一 Token 计费 SaaS
教育督导项目		轻资产、订阅/按量、可复制MRR/ARR / LTV:CAC / NRR / Churn / Rule of 40别用 IRR/回本年——SaaS 早期没有"回本年"这回事

客户问模式二，你答 IRR 15.2%、第 9 年回本；
客户问模式一，你答 LTV:CAC 3:1、NRR 120%。
答反了，客户当场就知道你没做过这类生意。

这条直接影响你今天的写作动作：可研蓝图的效益分析章用的是模式二语言——命题是模式一 SaaS 却照可研蓝图硬写 IRR，写出来就是空的。

② 启发 · 栈④ 2/2 · 当场打开 Excel 指着列走

签字前客户盯的那五行

概念是什么康养项目的数
EBITDA
息税折旧摊销前利润		营收减经营成本，但加回利息、税、折旧、摊销——衡量主业本身的现金创造能力约 5219 万/年
营收约 3.83 亿/年、净利约 3535 万
IRR
内部收益率		使 NPV = 0 的那个折现率——项目每年的"复合回报率"，必须跟一条门槛线比运营口径 15.2%（第 9 年回本，主口径）
发改口径 8.7%（第 11 年，高于国企 6% 门槛）
NPV未来每年净现金流折回今天求和，>0 才值得投—
回本周期累计净现金流由负转正的那一年第 9 / 11 年（两套口径）
营收 − 成本 = EBITDA（主业赚钱力） → 扣息税折旧 = 净利
  → 逐年净现金流折现求和 = NPV → 令 NPV=0 的折现率 = IRR → 累计转正之年 = 回本

⭐ 两套 IRR 并存不是矛盾，是财务常识——算的钱流范围不同。看到 15.2% 和 8.7% 别以为数据打架，更别自己改一个——那就正好踩中 B-5。

五个数

⚠️【这一页必须打开真 Excel，别只投幻灯片】技术型学员对着表格记不住，对着真实的列能记住。指着走一遍：营收列 → 成本列 → EBITDA 行 → 净利行 → 现金流行 → IRR 单元格。

【口径名纠正，课上必须说】叫运营口径，不叫"合资口径"（"合资/股权/注册资本"2026-07-20 起已禁用）。旧课件撞到这些词当场改口。

【顺带交代财评接口，一句话】商业模式回答"这生意成不成立"，财评回答"这笔钱算得准不准"。学前教育项目走财评线：484 功能条目 → 约 27,056 功能点 → 约 22,014 人天 → 总投资 4,839 万。两条线共用一条纪律：数字锚在单点。

⚠️ 反例 B-6 · 标准号误标（康养项目编制期两处真实误标）

· 药食同源目录被误标为 "GB 药食同源目录"——它根本不是 GB，是原卫生部 / 卫健委发布的名单
· 星评标准沿用了已废止的 MZ/T 标准——标准还在，版本已废止

② 启发 · 本课主教具 · 20′

写作专家：把"文风"变成可测量的东西

Writing Style 四维

① 语言标记　四字短语密度 · 对仗句式频率 · 递进模式（"从…到…"）· 标志性表达
② 政策引用　引用格式模板 · 偏好机关 · 引用密度
③ 段落模式　结构（论点+论据+价值阐述）· 字数区间 · 量化数据要求
④ 术语偏好　✅/❌ 成对：✅信息化建设/❌IT建设、✅总体架构/❌系统架构、✅保障措施/❌风险应对

量化启发式表

四字短语密度　每段计数　高 ≥5 · 中 2–4 · 低 0–1
对仗句式　　　每页计数　高 ≥3 · 中 1–2 · 低 <1
政策引用密度　每章计数　高 ≥4 · 中 2–3 · 低 0–1
段落长度　　　平均字符　短 <150 · 中 150–350 · 长 >350
量化数据　　　每段计数　高 ≥2 · 中 1 · 低 <1

客户说"我要一个像肖总那样的写手"，
必须索要样稿——光有名字抓不到文风。

这句话可以推广到整个 FDE 工作：客户给你一个人名 / 一个标杆，你要的是那个东西本身。

写作专家

⚠️【诚实标注，课上必须说这句】"BRIEF 以肖作仕为作者人设是硬证据；但'这些 docx 逐字由该 agent 生成'无法证明（没有生成日志）。准确说法是'按其文风纲领组织写作'。"
这本身就是本课的第一课：连自己的案例都要区分"能证明的"和"听起来像的"。

【三种造法，强调 A】分析参考文档（最佳，2–3 页样本即可）/ 口述定义 / 定制已有。没样本就去要——别凭空捏一个文风。

④ 实操 · 90′（穿插）

造专家 → 选蓝图 → plan → 写 1–2 章 → assemble

序做什么时长产出
1writer analyze <参考文档> 造写作专家25′四维填满的 writer
2blueprint list 看内置蓝图，选一本10′选定文档类型
3generate 跑到 plan 确认点 停下细看25′doc-plan + Gap 清单
4让它写 1–2 章（不用写全本）20′.parts/ 下的成稿
5assemble + 看质量报告10′装配稿 + 质量报告

难点 ①

造专家优先用"分析参考文档"。没样本就去要——别凭空捏一个文风

难点 ②

plan 确认点认真看 Gap 清单。❌Manual 的章节列进取证清单，别指望写作时圆过去

难点 ③

关键数字一律引用不重算（B-5）。分节作者各算各的，装配期必然对不上

实操

⚠️【绝不让他们跑全本】generate 全本跑下来很久，一跑就到下课。只写 1–2 章——要看到的是 plan 的 Gap 清单和 assemble 的编号收口。

【巡场抓手】①没样本硬造文风的组；②直接 approve 跳过 Gap 的组；③在自己那节重算数字的组。

⚠️ 工具链的已知不一致

照文档做会撞的九个坑

#坑以什么为准
1blueprint / writer 存放路径两说以 SKILL 为准（3 处一致 vs 1 处）
2蓝图 schema：文档版用 chapters:，实际内置蓝图用 structure:写新蓝图按磁盘实际结构

7mermaid 渲染实参与文档不符以脚本为准
8:plan / :write / :export-document 不存在只有 blueprint / writer / generate / export
