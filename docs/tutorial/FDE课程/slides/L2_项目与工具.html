预算 · 工期 · 政策边界

五个命题

发命题卡。让各组花 5 分钟看完再举手认领，不要先到先得抢——抢完的组往往没看清自己领了什么。

【模式分布是刻意的】模式一 B/C/E，模式二 A/D。第六课写财务那一段，两边用的是完全不同的语言。现在埋下这颗雷，第六课引爆。

【如果某个命题没人领】不要强塞。让人多的组拆成两组，或者你指定——但要说明理由，别显得随机。

介绍项目 3/3 · 现在就做

🔔 写下一句话项目定义

给【谁】做一个【什么】，
解决【什么错配 / 痛点】。

示例（命题 A）

给县域失能老人家庭做一个"助浴+喘息"上门服务调度与结算网络，
解决"服务供给散在各机构、家属找不到、补贴走不通"的三方错配。

这一句在第三课会被打回来重写好几次。
现在写得糙没关系，但必须写下来——它是后面所有产出的锚。

命题一旦认领就不换。

项目定义

【现场动作，别只是讲】给 5 分钟，每组必须把这句话写在工作簿首页并念出来。念出来这一步不能省——念的时候自己就会发现哪里空。

【常见毛病，当场纠】①"给政府做一个智慧养老平台"——谁是政府？民政局和医保局要的完全不是一个东西。②"解决信息化水平低的问题"——这不是错配，这是形容词。逼他们说出"谁和谁之间对不上"。

"一认到底"要说重一点：中途换题的组，等于把前面所有产出作废。这本身就是 FDE 的一课——需求会变，但项目不会因为你觉得难就换一个。"

介绍工具 2/4 · 必须建立的认知 ①

工具之间不靠内存传参，靠文件

studio/changes/{domain}/ 下每个文件，都是上一步的输出、下一步的输入。

随时可中断

今天跑到域图，明天接着跑

每步可单独跑

不用从头再来

可以人工改产物再继续

模型给的结构不满意，你直接改文件

占位符即契约

你在文档里写了要引用的文件，它就必须存在。
这条在第八课有物理落点——校验器会把"引用了不存在的文件"直接判 failed。

产物即接口

"这一条听起来像技术细节，其实是方法论。它决定了你可以在任何一步停下来、改一改、再往下走——而不是必须一口气跑完，跑歪了推倒重来。"

【第三条最重要】"可以人工改产物再继续"——这是 FDE 和"让 AI 全自动跑"的分界。模型提议，你拍板，然后接着跑。第五课会看到它的物理机制。

介绍工具 3/4 · 必须建立的认知 ②

认知到行动 = OAG，不是 RAG

RAG

检索得准一点

防幻觉在检索层
——找对了资料，但生成还是自由的

OAG

越权的结果根本生成不出来

防幻觉在执行层（本体约束求解）
——不是"劝它别这么干"，是"它干不了"

LLM proposes,
ontology enforces.

第五课会讲透，并给出物理机制：guards / post_rules / HilPolicy 三道关。

OAG ≠ RAG

【这一页会有人抬杠，准备好】常见反驳："RAG 加上好的 prompt 也能约束住。"回答：prompt 是劝，不是拦。劝有概率失败，拦没有。第五课我们会当场演示一个被引擎硬回滚的写入——数据根本没落库。

"今天你只要记住这一句：LLM proposes, ontology enforces. 模型负责提议，本体负责执法。这句话是第五课全课的题眼。"

介绍工具 4/4

⭐ 平台 = 方法论的固化物

产出=结构化能力× 平台固化×模型算力

第一课的公式。这一堆插件就是第二个因子。

层固化了什么例
工具层做事的步骤顺序planner 的 5 步流水线，不用每次想"先干哪个"
结构层产物的形状每个 skill 的产出路径与章节结构固定，下游能直接消费
纪律层什么不许做校验器的治理审计、编译红线

工具能省时间，纪律能防事故。
而纪律有个特点——它在你最想违反的时候生效。

三层固化

【第三层最值钱，讲慢一点】"前两层是效率，第三层是安全。而且你注意——纪律有个特点，它在你最想违反的时候生效。你赶工期的时候最想跳过校验，而校验器恰恰在那时候拦住你。这不是碍事，这是它的全部价值。"

【活证据 fund-review】"政府采购报价优化插件，首发案例就是学前教育项目。一个真实交付里反复做的动作，被沉淀成可复用插件，下个项目直接调用。第八课我们会再回收一次——到时候我会问你们：你们这五天做的动作，哪个值得沉淀？"

介绍工具 · 补

⚠️ 但固化也有反面

模板可以复用，
数字不可以。

反例 B-11 · 模板复用的数字迁移污染

辣椒和草业项目两份调研件是同一个模板换领域填的——结尾整段逐字相同，连"关系数 40万/200万/500万+"都一样。

草业项目那三个数（10万+案例 / 500+标准 / 200+专利）挂在客户30 年真实积累上、有主；
辣椒同样这三个数无主——是模板带过来的。

今天只需要记住一句：
固化提问结构是对的，固化答案是灾难。 第三课深讲。

B-11 预告

【纪律：点到即止，不抢第三课的主场】这一页只讲"正面之外还有反面"，不要展开讲怎么防——那是第三课的主场戏。给他们一个悬念就行。

"我刚讲完平台固化有多好，现在给你们看它的反面。固化提问结构是对的——那叫方法论。固化答案是灾难——那叫抄。 这两件事长得非常像，而且是同一份文件。第三课我们把这两份原件打开，一段一段比给你们看。"

四个翻车点

现象原因正确处置
① 装完当前会话
看不到新 skill
install 明确报成功		 插件在会话启动时加载，装完不会热更新 重启 Claude Code。
别重装——重装解决不了，因为它根本没装失败。反复卸载重装会浪费十分钟还越搞越乱
② 装不到
studio-ontology		 它是后加进 marketplace 的，旧快照里没有 先跑 marketplace update。
打印 Found stale directory… 是正常行为，不是报错
③ 升级没生效 再跑一次 install 无效 marketplace update + plugin update；
兜底 install --force
✅ ④ 两个仓库 URL
曾以为是坑		 Ameng2001 与 VanLengs 指向同一个 commit——改名后 GitHub 自动重定向 手册统一用 VanLengs。
看到另一个也别慌，不是两个仓库
翻车点

【① 要讲透，它是最真实的课堂翻车点】"install 明确回报成功，但技能列表里就是没有。这时候人的本能是'一定是装失败了'，然后去卸载重装。反复重装十分钟，越搞越乱。 实际上它根本没装失败——插件是会话启动时加载的，装完不会热更新。"

【④ 是诚实边界的小示范】"这一条我们一开始以为是个坑，写进了讲义。后来 git ls-remote 一查，两个 URL 指向同一个 commit——是仓库改名后 GitHub 的自动重定向。所以我们把讲义改了。查证之后推翻自己的结论，这也是这门课要教的。"
