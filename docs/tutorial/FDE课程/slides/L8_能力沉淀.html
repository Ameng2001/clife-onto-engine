一 · 能力沉淀 2/5 · 本节唯一要带走的心智模型

⭐ 固化三问

任何一条你反复叮嘱新人的纪律，
都问它三个问题——
能不能固化？固化成什么？谁来跑？

档例子固化成什么人力成本
全固化"跨域不许越界写"A 结构校验器（编译期自动）零人力，永不疲劳
全固化"SKILL.md 引用的脚本必须存在"validate_skills.py零人力
半固化"关键数字锚在单点、不重算"BRIEF 单点 + 装配期一致检查FDE 走一道人肉闸
半固化"SDK 能力不确定就挂账"docstring 显式挂账约定（人肉跑）FDE 走一道人肉闸
未固化只活在你脑子里的那条无，全靠自觉请假即崩

评估一个平台成不成熟，就看它把你多少条纪律固化进了校验器。
康养项目能做到 1 人顶 5+ 人，不是因为手快，是因为绝大部分一致性纪律被搬进了编译期和装配期。

一 · 能力沉淀 4/5 · "什么叫做完了"的操作定义

校验器查什么

A 结构（7 类）

manifest 存在（退而找 .draft，用 draft 会 warning）· JSON 可解析 · name/version/description 非空 · name 匹配 ^[a-z][a-z0-9-]*$ → failed · name==目录名 → warning 不是 failed · version 格式 · 声明路径能 resolve

B 技能（逐 skill 9 类）

每子目录有 SKILL.md · 行数 ≤ 500（超 = warning）· frontmatter 可解析 · description ≤ 1024 字符（超 = failed） · 未知 frontmatter key = warning，白名单只有 7 个（name, description, allowed-tools, user-invocable, disabled, trigger, model）
⭐ 正文引用的 scripts/*.py、references/*.md 必须真实存在 → failed

C 依赖（3 组）

.mcp.json（每 server 必须有 command，重名 failed）· hooks.json（事件名白名单 6 个）· dependencies[]（找不到 = warning）

报告 .validation-report.json，verdict 只有 PASS / FAIL，warning 不影响 verdict

B 组最后那条是 B-3 的同类机制：
占位符即契约。
康养项目当年是 docx 导出丢图，
这里是校验器直接判 failed。

校验器

🔔【务必现场做的演示，2′】当场故意制造一次 failed——把某个 SKILL.md 引用的 scripts/foo.py 删掉，跑 validate 让它报 failed，再修好。
学员亲眼看到校验器抓住讲师，比听十遍"纪律靠机制"都管用。

【一处文档 vs 实现的落差】SKILL.md 示例用 ✅/⚠️ emoji，实际脚本输出纯文本 PASS/WARN/FAIL。以脚本为准。这已经是这门课的第 N 处了，学员应该不惊讶了。

校验器替你守纪律，与 promote 的「不做清单」

B-8 越域写入冲动B-9 SDK 能力想当然
冲动是什么让一个 Action 直接写别的域的对象（省事）某两个符号导没导出，不确定但"应该支持吧"
谁挡住了它A 结构校验器——当场报悬空/越界没人挡——校验器管不到运行时符号导出

B-8 的教学点：7/7 零悬空不是因为我们 7 次都自觉，是因为校验器不给我们自觉的机会。
B-9 的教学点：平台会告诉你它保证什么，也会暴露它不保证什么——在校验器覆盖不到的地方，用 docstring 手动补一道"诚实闸"。

⭐ promote 明确不做的事

不拷贝实现文件 · 不 git add/commit · 不删实现文件 · 不跑校验 · 不删活动工作区 · 不把 promote 当终态
为什么不自动 commit：因为提交是人的决定。工具把状态推进到位，但"我认可这个版本"这句话必须由人说出口。

校验器管"什么叫做完了"，
不做清单管"做完了也不等于我认了"。
机器判 PASS，人签字发版。

它是"下个项目还会再做一遍"的动作吗？
还是只有你们这个命题才有？

✅ 答得好的形态

"我们命题里反复在做'把地方标准解码成可校验的规则条目'——A 组做康养要做，E 组做督导也要做，换个客户还得做一遍。这个值得沉淀成 standard-decode 插件。"

三 · C-Life 落地 3/3

两条红线，与编成的本质

红线一：不许跳过度量直接铺量

老板说"康养项目都成了，赶紧复制十个"——这时候你要顶住。
指标没达基线的复制，是把一次侥幸当成能力。

红线二：不许让平台组缺位去省成本

没有平台组，Lv.3 退化成"更累的架构师"，单点或许能扛，规模化必崩。

规模化后 B-10 会被放大：单个项目里 Lv.3 靠 C7 顶住了 11 处占位；但每个项目都有它自己的 B-10，而你只有一个 C7 过关的人——没有第二个敢留白的人，第二个项目的 B-10 就会被一个 Lv.1 用假文号填上。

落地的本质：把那个 Lv.3 脑子里
"靠人品和经验兜住的东西"，
变成组织层面的红线、度量和平台约束——
让第 N 个项目不必再靠"又碰到一个好 Lv.3"的运气。

编成的本质（第 ⑩ 件就写这个）：Lv.3 提供判断和责任，Lv.1 提供手数和成长通道，平台组提供杠杆。三者缺一，康养项目都不可复制。别只写"1 主理 + N 见习"六个字。

红线 · 编成
