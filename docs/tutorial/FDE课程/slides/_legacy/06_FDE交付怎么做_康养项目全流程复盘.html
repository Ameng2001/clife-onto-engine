FDE 交付不是"手艺好"，是"有 SOP + 会设闸"——SOP 保证你能重复，HIL 保证你不出事。

能力靶：C3 风险设闸 · C6 交付物工程 实践蓝本：康养行业大模型平台
前五讲讲了 FDE 是什么、为什么组织需要、边界在哪、要什么知识栈、为什么离不开平台，都是认识论。从这一讲开始是方法论——你回去要怎么干。这是全课程最长的一讲，别的讲的两倍，因为要交给你两样能带走的东西：一张七阶段交付 SOP，套任何 To-G/To-B 项目都能用；一套 HIL 设点原则，让你知道在哪必须叫人、谁按、按错了赔什么。我先把最难听的话放开头，省得你以为我在夸 AI：你们大多数人现在能把康养项目那条链跑完，但跑不出第二遍，因为你靠的是当时的手感，不是流程。手感不能交接，流程能。这一讲就是把手感拆成流程。

本讲命题

你能跑完康养项目那条链，
但你跑不出第二遍。

难听话 · 整讲都在拆它

"你靠的是当时的手感，不是流程。手感不能交接，也不能背锅。"

真正值钱的不是"你会干"，是"你知道在哪必须停下来叫人"，以及"你敢在查不到的地方留个空、而不是编一个"。前者让你跑得快，后者让你活得久。

这一页是题眼。多数人栽，不栽在不会干，栽在该叫人的时候逞能、该说不知道的时候硬编。你现在能把康养项目这条链跑完，靠的是手感——但手感有两个致命缺陷：不能交接，你请假这活儿就停了；不能背锅，出事了你说不清当时为什么这么判。这一讲要干的事，就是把手感拆成两样可交接的东西：一张 SOP，让别人照着也能跑；一套 HIL 设点原则，让每一次自动决策都能追溯到谁在什么置信度下拍的板。听完你要从"跑通过一次康养项目"，变成"能跑第二遍、第三遍、别的项目也能跑"的人。

设 HIL 之前：闸分两层，HIL 只是第二层

软约束不是工程约束——
会被遗忘 · 会被稀释 · 会被绕过（prompt injection）。

三层强度对比
层次机制强度 / 可绕过
提示词层靠 LLM 自觉最弱 · 注入即破
API 网关层校验参数格式中 · 参数可伪造
本体层校验业务状态 + 全局不变式最强 · 引擎强制无旁路
第一层 = 自动闸（引擎确定性回滚）

本体层 Rule "违反即拦截 + 回滚"：内存变更 → 全局规则命中 → 回滚，记录从未被写。

结构化拒绝三件套

triggered_rulecurrent_statesuggestion

发现→调用→被拒→调整→重试

能固化成硬规则的，就交给自动闸，别浪费人力。

设 HIL 之前，先搞清一件最容易被讲漏的事——闸有两层，HIL 只是第二层。我们自己的方法论文集把这件事讲透了，我搬三条硬结论。第一条，软约束不是工程约束。你在提示词里写"发起采购前必须检查认证有效期"，这是软约束，有三个结构性缺陷：会被遗忘，多轮对话后早期指令权重下降；会被稀释，上下文塞满约束被挤出；会被绕过，提示词注入让模型忘掉约束。看这张三层强度表：提示词层靠 LLM 自觉，最弱，注入即破；API 网关层校验参数格式，中等，参数可伪造；只有本体层校验业务状态加全局不变式，最强，引擎强制、没有旁路。第二条，第一层是自动闸，引擎确定性回滚，机器把关。本体层的 Rule 是违反就拦截加回滚：内存里先变更，全局规则一命中，就回滚、记录从未被写。Agent 收到的不是 500 错误，是结构化拒绝三件套——triggered_rule 告诉它为什么不行，current_state 给它当时世界快照，suggestion 告诉它可以怎么调。于是 Agent 据 suggestion 改选重试，这就是 OAG 闭环：发现、调用、被拒、调整、重试，全程在约束内没绕过。记住这句：能固化成硬规则的就交给自动闸，别浪费人力去人肉点确认。

第二层才是 HIL；留痕 = 决策快照，不是日志

第二层 = 人工闸 HIL · 两种情形上人

① 机器判不了的价值判断——涉钱 / 涉合规 / 跨组织的拍板。

② 机器没把握——AI 断言是概率的（balance_sufficient = (False, 0.78)）；置信度太低必须触发人工复核。

→ 这就是康养项目站长置信度闸 0.75 的方法论根据（置信度总线）：不是拍脑袋阈值，是"低置信必须转人"的工程共识。

以及越界时——是被它自己拦下，还是被现实拦下。

自动闸 + HIL = 被它自己拦下；两样都没设 = 等着被现实拦下（赔钱、赔合规、赔客户关系）。

第三条，第二层才是人工闸 HIL，人拍板。什么时候上 HIL？两种情形。一是机器判不了的价值判断，涉钱、涉合规、跨组织的拍板，这类事没有对错公式，必须人来担。二是机器没把握，AI 原生系统里每个断言都是概率的，比如余额是否充足这个判断带着置信度 0.78，当置信度太低、接近随机时，基于它的决策就不该当最终结论，必须触发人工复核。这就是康养项目站长置信度闸 0.75 的方法论根据——那个 0.75 不是拍脑袋定的阈值，是"低置信必须转人"的工程共识，我们叫它置信度总线。第四条也很关键：HIL 按完要留痕，但留的不是操作日志，是决策快照——记录上下文，不只记录结果。康养项目的 HILReview 强制留四样：签字人、复核时间、决定、以及改动前后对比。为什么这么严？为了回答那个迟早会来的问题：三个月后合规团队问你"AI 当时凭什么觉得能下单"，你能不能当天答上来。最后板书这句金句：你能把多大的权力交给一个系统，取决于设计时边界定义在哪里，以及越界时是被它自己拦下、还是被现实拦下。自动闸加 HIL，就是被它自己拦下；两样都不设，就是等着被现实拦下，那时赔的是钱、是合规、是客户关系。下面讲的四判据，就是帮你决定这道闸该自动、还是该上人。

两大闸门 · 按错的代价（本章高潮）

闸门① 站长 HIL · 增收闸 · 置信度闸 0.75 防橡皮图章

判据命中：涉钱（生成订单）+ 跨组织（卖给会员）+ 置信度兜底。

⚠ 按错场景 A：阈值调成 0 或站长养成"一律点同意"——闸门在，等于没有。AI 给低置信的不合适高价套包，站长机械点过卖出去。钱是长者的、口碑是客户的、责任是 C-Life 的；熟人获客 77.59%，卖错一单毁整个片区信任飞轮。

原则：闸门的价值不在"有没有"，在"会不会真拦"。阈值是活的，谁调阈值谁负责。

闸门② 民政 DP-H · 监管发布闸

判据命中：涉合规 + 涉钱（补贴）+ 跨组织（政府对社会发布），三条全中，全项目命中最密。

⚠ 按错场景 B：DP-H 失守，AI 把未核验的床位一张图、或补贴资格认定直接对外发布——违反个保法最小必要、错发漏发补贴（涉公帑）、政府信用受损。不可逆：数据发出去收不回，补贴发错追缴是政治事件。

原则：跨组织 + 涉合规的动作，人工闸是法律义务不是可选项。谁发布谁签字，签字的人为真实性背书。

设闸就问五个问题：不可逆吗？涉钱吗？涉合规吗？跨组织吗？模型够确定吗？中一条，插人。

两个闸门，本章高潮。闸门一站长 HIL 增收闸。机制是六智能体链路，洞察根因需求方案 HIL 执行评估回流，AI 生成增收方案后必须站长在审核台点确认才能转订单。判据命中涉钱加跨组织加置信度兜底。为什么设置信度闸？不是走个形式让站长点同意，建模时把它设成硬闸 function pre，目的就是防橡皮图章——AI 高置信的方案快速过、低置信的强制站长细看。按错场景 A：如果把阈值调成零或站长养成一律点同意的习惯，闸门在等于没有，AI 给一个对长者不合适的高价套包卖出去，钱是长者的、口碑是客户的、责任是 C-Life 的；微康养做熟人生意，熟人获客七成七，卖错一单毁的是整个片区的信任飞轮。闸门二民政 DP-H 监管发布闸，涉合规涉钱跨组织三条全中。按错场景 B：DP-H 失守，把未核验的数据直接对外发布，违反个保法最小必要、错发漏发补贴、政府信用受损，而且不可逆。两句话记住：站长闸防钱按错，置信度闸就是防橡皮图章的；民政闸防合规越界，跨组织发布是法律义务谁签字谁背书。你回去设闸就问五个问题，中一条插人，别嫌麻烦，嫌麻烦的代价你赔不起。

根因：编号权归装配阶段，不归写作阶段。写作只管写内容，编号装配时统一分配——并行的东西，全局唯一性只能在收拢点解决，不能指望各分支自己协调。

别的讲一讲一个反例，这一讲是反例主场，一次给你四个。因为交付物工程和合规治理是出错高发区，这四个坑我们全踩过。每个反例讲三件事：怎么发生的、怎么被发现的、根因是什么原则。B-1 图目计数漂移，FIG_SPECS 标题写二十二张图但表体实际列了二十六行，后期补的图追加到表尾，头部那个计数没人回去改，质检时对不上。根因是摘要与明细必须单一真相源，并行追加式产出必须有一个显式的收口回改动作——漂移不是因为谁粗心，是没有一步流程负责在追加后回改头部计数。B-2 章节编号冲突，三十五个分节并行写作各自起编号，装配期编号重复跳号。根因是编号权归装配阶段不归写作阶段，并行的东西全局唯一性只能在收拢点解决，不能指望各分支自己协调。
