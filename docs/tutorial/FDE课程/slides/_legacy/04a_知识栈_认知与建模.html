C-Life · FDE 内训

第四讲我拆成四册讲。这一册讲两件事：认知，和建模。开场先把命题钉死——很多人以为 FDE 约等于会做领域建模、会画本体。这一讲要扭转的就是这个误解。FDE 本质上是七个专业角色方法论的合体：产品经理、领域架构师、知识工程师、商业顾问、财评专家、方案工程师、合规官。过去这七种人各坐一屋、各说行话，交接处全是信息衰减。FDE 把这七套方法论装进一个脑子。本册先讲头两栈，也是大家最熟的两栈：产品设计和领域驱动设计。

本讲命题

建模只是七分之二

FDE 出现之前，做康养项目这种项目，会议室里要坐七种人——各司其职、各说行话，交接处全是信息衰减。

FDE 消除断层的办法，不是协调这七个人，是把七套方法论装进一个人，从头跑到尾。

会做领域建模 / 本体

康养项目那条链：102 事件 → 7 域 → 3835 行本体 → IRR 15.2% → 18 处挂国标 → 11 章可研——每一段由一个不同角色的方法论撑着，缺一段链就断。

建模只是七分之二

这一页要扭转的误解，我说得直白点：你以为 FDE 就是会建模，其实建模只是七分之二，就是栈②栈③。康养项目那条链你数一遍——一百零二个事件、切七个域、三千八百三十五行本体、算到 IRR 十五点二、挂十八处国标、写十一章可研——每一段都是一个不同角色的方法论在撑。多数技术出身的人不是倒在建模上，恰恰倒在后面三栈：盘不出账、过不了财评、组织不起百页交付物。所以别把这门课听成"教你建模"。建模你可能已经会了，缺的是另外五个角色。

方法论管线

正式进七栈之前，先给你一个贯穿全讲的框架，别把这七栈当成七门要背的知识。每一栈本质上是一条方法论管线——有明确的输入、产出、和交给下一段的接口。产品栈是"事件到画像到旅程到机会矩阵"的认知萃取管线；DDD 栈是"事件簇到限界上下文到上下文映射"的域切分管线；本体栈是"业务语义到五要素到编译到校验"的建模管线，就是 methodology 零三那四阶段；财评栈是"功能点到取值依据到投资估算"的测算管线；交付物栈是"锚定口径到并行写作到装配到质检"的成文管线。把这七条管线首尾接起来，就是 FDE 那条完整交付管线：从 event-storm 开始，经 planner 出画像旅程机会矩阵，到 domain-model 切限界上下文，到 clife-onto-engine 建五要素本体，到 quality 做 citations 治理，最后到 docs 生成可研。这也是本讲和第五、第七讲的桥。记住一个因果方向,千万别搞反:本讲讲管线本身,第五讲讲管线为什么要被固化,第七讲讲工具怎么咬合。是先有了这些方法论管线,Astra Studio 才长成这些工具;工具是管线的固化物,不是反过来。所以你学这一讲,是在脑子里装那条能自己跑、也能交给工具跑的交付管线。

栈 ① · 产品设计 · 产品经理的方法论

四个把模糊意图变结构的具体方法

产品设计不是"画原型"——是四件可照做的方法，一步步把"客户想要点什么"逼成可归域的结构。

① Persona 用户画像

按行为 / 目标 / 动机 / 痛点定义真实用户——不是人口属性堆砌。画像是整条旅程的地基。

② User Journey Map 用户旅程图

Figma 五要素框架：把用户在各阶段的行为、情绪、机会点画出来（下一页详解）。

③ Opportunity Matrix 机会矩阵

把旅程暴露的痛点排优先级：影响 × 可行性 × √频率、ROI 排序，决定先做哪个。

④ Event Storming 事件风暴

业务事件全量铺开再归簇，喂给后面栈② 的限界上下文。

＋ 产品思维（情绪与势能内核 · 梁宁《产品思维30讲》）

给上面四法补一层"人和情绪"：同理心（痛点/痒点/爽点，画像旅程里的"痛点"就从这来）· 点线面体（从一个点看到所附着的线—面—体与势能，别做没势能的孤点）· 用户体验五层（战略存在/能力圈/资源结构/角色框架/感知层——底下四层才决定成败）。这是 Persona/Journey 的情绪与势能内核。

栈① 四法 + 产品思维

第一栈，产品设计，原本是产品经理的活——把客户模糊的意图变成"要做什么"。我把它讲实：产品设计不是画原型，核心是四件可照做的方法，一步步把"客户想要点什么"逼成可归域的结构。第一件，Persona 用户画像，按行为、目标、动机、痛点来定义真实用户，不是拿人口属性堆砌，画像是整条旅程的地基。第二件，User Journey Map 用户旅程图，用 Figma 那套五要素框架把用户在各阶段的行为、情绪、机会点画出来，这个下一页专门拆。第三件，Opportunity Matrix 机会矩阵，把旅程里暴露的痛点排优先级，按影响乘可行性乘频率的开方做 ROI 排序，决定先做哪个。第四件，Event Storming 事件风暴，把业务事件全量铺开再归簇，喂给后面栈二的限界上下文。这四件方法是有顺序、能照做的，不是玄学。最后补一层底：产品思维，梁宁《产品思维30讲》那套。前面四法是骨架，产品思维给它补"人和情绪"这层肉——同理心把需求分成痛点、痒点、爽点，画像旅程里的痛点就从这来；点线面体提醒你从一个具体产品这个"点"，看到它附着的线、面、体和势能，别做一个没势能的孤点；用户体验五层告诉你产品不止感知层好看，底下战略存在、能力圈、资源结构、角色框架四层才决定成败。所以产品思维是 Persona 和 Journey 的情绪与势能内核。

栈 ① · 用户旅程图 · Figma 五要素框架

Journey Map 五要素 · 五步做法

五要素

① 用户（persona）② 场景与目标 ③ 旅程阶段 ④ 行为·态度·情绪（每阶段正负情绪）⑤ 机会点（从摩擦/痛点长出来）。

旅程阶段（可按业务定制）

awareness→ consideration→ decision→ purchase→ retention

五步做法

① 从研究数据定 persona 与目标 ② 找触点 ③ 可视化阶段 ④ 逐阶段记录行为与情绪 ⑤ 用真实反馈校验迭代
Journey Map 五要素

四个方法里 User Journey Map 最容易被做成流水账，所以单独一页讲透。它用 Figma 给的五要素框架：第一是用户，就是 persona，让旅程反映真实用户视角；第二是场景与目标；第三是旅程阶段，通用的一条线是 awareness、consideration、decision、purchase、retention，认知、考虑、决策、购买、留存，可以按你的业务定制；第四是行为、态度、情绪，每个阶段都要标出用户的正面和负面情绪，这一栏最常被漏掉；第五是机会点，机会点不是拍脑袋想的，是从摩擦和痛点里长出来的。五步做法照着走：先从研究数据定 persona 和目标，再找触点，再把阶段可视化，逐阶段记录行为和情绪，最后一定要用真实反馈校验迭代。一张合格的旅程图，情绪和机会点两栏必须齐全，否则就退化成了功能清单。

锚 studio planner

这一页是新增的重点。这些方法在 C-Life 不是靠某个高手手画白板，是固化成了 studio 技能，任何人都能调。你看这一串：persona-insight 做画像，journey-map 做用户旅程，process-flow 做业务流程，opportunity-brief 做机会矩阵、里面就是影响乘可行性乘频率开方那套 ROI 排序，behavior-matrix 做行为矩阵，domain-canvas 做领域画布，event-storm 做事件风暴。注意这个结构——它跟本体栈是对称的：本体栈锚到 clife-onto-engine 这个内核，产品栈锚到 Astra Studio 的 planner 工具链。两栈的方法论都被平台固化了，这正好呼应第五讲讲的"FDE 依赖成熟工程化平台"。这告诉你一件事：方法论不是嘴上功夫，真正成体系的方法论最后都会沉淀成能被工具复用的资产。

栈 ① · 康养项目 / 教育督导项目 + 自评到能交付

同一套 planner 方法 · 跨行业成立

行为分群（不是人口属性）

按行为切：熟人获客接受度 77.59%、智能监护接受但要简单式 84.48%。教育督导项目同一套——3 画像（李科长/张园长/王老师）+ opportunity-brief ROI（material-qc / standard-decode 为 P0）。

自评到能交付

能独立主持事件风暴产出可归域事件集；做一张情绪+机会点齐全的 journey map；每个画像特征都能指到一份数据来源（368 问卷=B-5 前的"锚点"纪律）。

同一套 planner 方法跨行业跨模式成立——这就是第 8 讲"C1 认知萃取迁移力"的底座。

栈① 康养项目/教育督导项目证据

看这套 planner 方法在康养项目怎么串起来：event-storm 出一百零二个事件、十六簇，persona-insight 定七个画像、用三百六十八份问卷按行为聚类校准，journey-map 画七条旅程，process-flow 出五个流程，opportunity-brief 排十个热点 P1 到 P5。重点还是行为分群：不按"六十岁以上老人"这种人口属性切，是按行为切——熟人获客接受度百分之七十七点五九、智能监护接受但要简单式百分之八十四点四八。关键的证据在这——教育督导项目用的是同一套：三个画像李科长、张园长、王老师，加 journey，加 opportunity-brief 做 ROI 排序，把 material-qc 和 standard-decode 排成 P0。同一套 planner 方法，从康养跨到学前教育照样成立，这就是第八讲讲的 C1 认知萃取迁移力的底座。自评标准：能独立主持事件风暴产出可归域的事件集，能做一张情绪和机会点齐全的旅程图，每个画像特征都能指到一份数据来源——康养项目那三百六十八份问卷，就是反例 B-5 之前那条"锚点"纪律的正面示范。

康养项目怎么用这栈。把栈一那一百零二个事件、十六簇，切成七个限界上下文 D1 到 D7。切域的判据我强调一句：看"谁拥有这个决策"，不是看"谁的数据"，这是新手最容易切错的地方。切完之后立三条纪律：跨域一律 ref 引用或者发布，绝不越界写入；两处防腐层，D6 对 D5、D4 对 D5，这就是 DDD 里的 ACL；Elder 这个共享根只有一个写入点，这就是统一语言加单一真相的落地。切得对不对不靠嘴说，靠结构校验兜底——A 结构七比七零悬空引用，意思是没有任何一个对象被两个域同时写。越域写入的冲动特别真实，人人都想抄近路直接写别人域，这个坑第五讲 B-8 会专门讲。

栈② 自评

这栈自评标准。练法：把你在栈一产出的事件集，按"谁拥有这个决策"切成几个域，切完做一件事自查——有没有哪个对象被两个域同时写，只要有，就是切错了。验收到能交付的标准是两条：第一，你能独立完成一个域的 ontology-map 并且通过结构校验；第二，随便指两个域，你能一句话说清它俩之间是引用关系还是发布关系。为什么这栈这么重要？因为切域是本体的地基，域切歪了，下一册讲的本体五要素全立在流沙上。所以别急着跳到本体，先把这栈的切域纪律吃透。
