FDE 实战工作坊

先给地图，再上路。第一课把「FDE 是什么」讲透，后面每课一个工作环节、一次实操。 一条命题贯穿 L2–L8（L1 纯讲解不产交付物），结课交出「迷你 FDE 交付包」11 件。

8 课 · 约 21.5 小时 + 路演 集训 5 天 / 压缩 3 天 / 分散 8 周 L5 是全课重心，压缩档绝不砍 + 专题课 S1–S3 · 本体论 / 引擎 / 建模端

每课两件产物

课件（蓝色按钮）= 讲师投屏用。口播稿、时间盒、卡点提示、"要砍先砍哪里"全在演讲者备注里—— 按 S 开演讲者窗口（当前页 + 下一页 + 备注 + 计时），N 拉备注抽屉， O 总览，← → 翻页。投屏侧看不到备注。
学员手册（白色按钮）= 打印成册发给学员。学员视角、含参考答案，可脱离课堂自学。

专题课 S1–S3（一条线，可独立开设，不占八课课时）

S1

本体论：从数据到世界模型  第五课的方法论前置

纯讲解 · 180′ · 完全基于《工程师的本体论》方法论文集（45 篇 + 番外）
露华浓 ERP 的 7000 万美元 → 字典 vs 物理引擎 → 四层架构 → 五要素 → OAG ≠ RAG 与三层能力 → Software 3.0 的文件系统 → Harness 管循环，本体管世界 → 建模 SOP → AI FDE 为什么能 work。
硬指标：说得出幻觉的真正成因 · GraphRAG 属于哪一边 · Harness 与本体的边界
课件 26 屏 学员手册
S2

本体引擎的工程实现  内核怎么造

讲解 + 当场读码 · 180′ · 教材 = clife-onto-engine 源码 + 内核"宪法"
三层切分与判缝准则（"换成医疗大模型还成立吗"）→ 五要素的工程契约 → Action 六步生命周期 + 三条内核铁律（写后判 · 判全部 · 拒绝是数据）→ 双写路径 → SPI 七槽位（含第五课实测：只覆盖五格）→ 审计快照与置信度总线 → 两个 CI 门禁。
硬指标：说得出为什么规则在写入"之后"执行 · 两个门禁脚本的执法方向 · 用判缝准则当场判一段代码放哪层
课件 17 屏 学员手册
S3

建模端如何支撑引擎 · studio-ontology  交棒第五课

讲解 + 管线走查 · 180′ · 教材 = 我们自己的 FDE 工具箱（astra-studio-plugins/studio-ontology）
全课 = 架构图右下角那个橙色框。两仓一条流水线 → 为什么不直接手写插件（业务专家看不懂 Python，所以要有 IR）→ DDD ↔ 五要素翻译表 → IR 七段（§4 Rules ★FDE 核心）→ 编译产物与四类 NotImplementedError → 四命令里唯一那个强制停点 ⏸ → 诚实边界：设计上的克制 ≠ 能力上的边界 → IR 七段只覆盖 SPI 五格（结构性缺口，不是待补功能）→ 验收标准：与手写 plugins/grass 五要素同构 → ⚠️ 两仓红线。
硬指标：区分设计上的克制与能力上的边界 · 说得出七段 IR 覆盖七槽位中的哪五格、为什么那两个 ❌ 是结构性缺口 · 说得出建模端的验收标准
课件 15 屏 学员手册

这三门课和第五课的关系

建议顺序：S1 → S2 → S3 → L5
S1 本体是什么、为什么必须有（方法论文集，不含任何实现细节）→ 判断力
S2 引擎怎么造（clife-onto-engine 源码）→ 运行时端的骨架
S3 怎么给它编译应用（我们自己的建模端 studio-ontology）→ 那把工具，以及它的边界
L5 亲手用那把工具，产出一个能在那套引擎上跑起来的插件

S2 讲运行时端，S3 讲建模端，第五课把两端接起来。
只上一门的话，上 S1——工具会换，那套判断不会。
