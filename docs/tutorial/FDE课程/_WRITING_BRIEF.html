〇、维护纪律（红线）

课程内容已产出完毕（课程/L1–L8_*.md）。以下纪律适用于任何后续改动——你自己改、或派子智能体改：

  • 改哪一课就只改那一课的文件；不要顺手改别课、不要改总纲、不要动 figures。跨课的口径变更先改本文件，再逐课回改。
  • 每课两件产物：slides/LN_*.html（讲师投屏，口播稿在 .notes 演讲者备注）+ 课程/LN_*.md（学员手册，打印发学员）。改内容时两边都要改，别只改一边。
  • 讲义/、工作坊/NN_*_workshop.md、工具实操/T*.md 都是历史素材，改它们不影响授课。
  • 派子智能体时只回摘要：改了哪几节、动了哪些数字、用了哪个反例编号、与哪几课有交叉。不要把正文粘回来（防上下文爆炸）。
  • 每一个论断后面必须跟一个具体证据或数字（见第二节数据表 / 第二·补 案例库）。空洞概念堆砌一律不合格。
  • 数字一律引用不重算（反例 B-5）。第二节的数字与已冻结的成品可研逐字一致，改它们等于制造第二个真相源。
  • 外部事实（L1「别人怎么做」段）必须联网核证，逐条标来源；查不到写"未获证实"，绝不虚构。
  • 面向内部专业人员，要有观点、敢说难听话。不吹 AI 万能，如实写智能体做不好、必须人接管处。

编号纪律：L1–L8 = 课次。能力定级一律写 Lv.1 见习 / Lv.2 胜任 / Lv.3 主理，不写 L1/L2/L3——旧讲义与旧课件里的"L1 见习"讲师要当场改口。

二·补 案例库 —— FDE 两大交付模式（主轴，详见 案例矩阵_跨项目对照.md）

核心框架：四个真实项目 = 两大 FDE 交付模式的实例（不按行业分，按交付模式分）。FDE 的第一个判断是"这是哪种模式的活"。任何 callout 引用必须带下表"成熟度状态"标签，不得拉平当等同实证。

模式一 · Token 计费智能体 SaaS 应用（轻/快/产品化/按量计费/agent 即产品）

  • 交付物=可跑 agent 应用+本体+HIL；商业=按 token/调用/席位计费、无运营盘；团队轻（1 FDE + 平台组）；HIL 命门在应用内裁定/质检闸。
  • 代表：教育督导项目。注："Token-SaaS"是 C-Life 商业定位；教育督导项目源材料述其"平台赋能/游学并行外挂"、未见计价表，讲"定位为按量 SaaS"不编单价。

模式二 · 大型平台建设 + 生态运营（重/长周期/投建运/多元收入）

  • 交付物=可研+平台建设+运营+财务测算+本体+多端；商业=投建运+运营盘+碳汇/交易/数据要素；团队重（主理 Lv.3 + 见习 + 平台组）；FDE 全链 S1–S7 尤重 S5 合规/S6 可研/商业建模；HIL 命门=增收闸+监管发布闸+凭证闸。
  • 代表：康养项目（标杆）、草业项目、辣椒。

三、观点主张（全课程反复回收，措辞对齐）

  1. FDE 的核心资产不是"会用 AI"，是把客户模糊意图压成可执行结构（证据：102 事件 → 7 域，模型不替你做判断）
  2. 没有工程化平台的 FDE 只是"更累的架构师"（证据：7 域同日并行编译、7/7 零悬空引用）
  3. FDE 专业性一半体现在"敢说不知道"（证据：11 处占位不编造）
  4. C1–C6 可训练，C7（客户关系/责任承担/价值判断/政治敏感度）只能筛选（L1 一人公司 OPC 段第一次讲透 → L8 OPC 边界回收段第二次说；无法用实操训练）
  5. HIL 设点四条硬判据：不可逆 / 涉钱 / 涉合规 / 跨组织，命中任一即插人；另加一条"置信度兜底闸"（模型置信度低于阈值即转人，康养项目占位 0.75）——四判据看动作性质、兜底闸看模型把握。闸分两层：能固化成硬规则的走自动闸（引擎确定性回滚），判不了/涉钱涉合规的才上人工闸 HIL（L5 下半场核心：★两道闸）
