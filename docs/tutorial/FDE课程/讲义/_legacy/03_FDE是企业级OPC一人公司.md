# 第 3 讲 · FDE = 企业级 OPC（一人公司）——一人打通，边界在哪

> 讲义（讲师用）· 90′ · 对应能力模型 **C7 人的部分**（并回收 C1–C6）
> 实践蓝本：康养行业大模型及微康养生态运营平台

---

## 1. 一句话命题 + 本讲在能力模型中的位置

**命题**：前置交付工程师（Forward Deployed Engineer, FDE）在交付形态上是一家**一人公司（One-Person Company, OPC）**——一个人打通产品 / 架构 / 方案的全链条；但一人公司有**清晰的边界**，边界之内可以靠智能体把人放大，边界之外必须人亲自扛。**这一讲不鼓吹一人万能，只画那条线。**

**能力位置**：本讲是能力模型 **C7（人的部分：客户关系 / 责任承担 / 价值判断 / 政治敏感度）** 的主场，同时回收 C1–C6——因为 C1–C6 正是"可以交给智能体加速"的那一侧。课程主张 4 的原话在这里落地：**"C1–C6 可训练，C7 只能筛选。"**

**实证锚点**：康养项目由 **1 名 FDE + 智能体编队**完成了从 102 业务事件 → 7 域限界上下文 → 3835 行插件骨架 → 100+ 页可研（11 章 / 约 11 万字 / 26 图 + 2 份附录 docx）的完整认知侧链条。传统模式这条链条要 **产品经理 + 架构师 + 行业顾问 + 方案经理 + 美工，5+ 人 / 数周**。这是"一人公司成立"的证据。但同一个项目里，有 **11 处地方文号一个人也补不上**、**1 个 0.75 的置信度阈值一个人必须自己拍**、**一整套脱敏红线一个人必须自己守**——这是"一人公司有边界"的证据。**本讲讲的就是后半句。**

## 3. 认知输入

### 3.1 要点页｜"一人公司"不是口号，是一种可核验的交付形态（5′）

**【讲述脚本】**
"我们说 FDE 是一家一人公司，不是给你打鸡血。一人公司（OPC）在这里是个**结构描述**：一个人对一个交付负全责，对内自己排产、自己质检，对外一个人就是产品经理、架构师、行业顾问、方案经理。请注意术语——我们说 OPC，不说'超级个体'也不说'全能工程师'，因为那两个词把重点放在'这个人多牛'，而 OPC 的重点是'这个交付单元的边界在哪、谁负责'。

康养项目这条链子就是一家一人公司跑出来的：一个人主持事件风暴出 102 个事件，一个人做 DDD 切出 7 个域，一个人带智能体写 3835 行骨架，一个人锚定口径拉起 35 节并行写作装出 11 万字可研。传统上这是 5 个工种、数周的活。所以'一人公司成立'这件事，康养项目已经证明了。今天不花时间证明它成立——今天花时间讲它的**边界**。"

**【板书/图】**
```
        ┌─────────── 一人公司（OPC）的交付单元 ───────────┐
客户模糊意图 →│ 产品设计  架构建模  方案撰写  交付物工程  质检 │→ 可交付成果
        └──────────────────── 1 名 FDE + 智能体编队 ────────┘
                              vs 传统 5+ 工种 / 数周
```

**【康养项目证据】** 1 名 FDE 完成 102 事件 → 7 域 D1–D7 → 3835 行骨架 + 21 个 YAML → 11 章可研；传统对照为产品经理 + 架构师 + 行业顾问 + 方案经理 + 美工 5+ 人。

### 3.2 要点页｜可替侧：智能体到底替你放大了什么（8′）

**【讲述脚本】**
"先说好消息：一人公司之所以能成立，是因为有三类活可以交给智能体大幅加速。记住，是'加速'不是'替代判断'——模型替你做完，不替你做主。

第一，**认知萃取的加速**。事件风暴、画像、旅程，这些活的判断在你脑子里，但把它落成结构化文本、补齐要素、交叉对齐，智能体比你快十倍。康养项目 102 事件能压成 16 事件簇、再对齐到 7 画像 / 7 旅程 / 5 流程，人来判断归类，模型来跑那一遍遍的整理。

第二，**建模骨架的生成**。7 个域的本体五要素（Object/Link/Function/Rule/Action，简称 OAG）——Object 76 / Link 75 / Function 38 / Rule 47 / Action 54——真要一个字一个字敲，一个人敲不完。管线（studio-planner → domain-model → clife-onto-engine）把骨架生成出来，7/7 py_compile 通过、3835 行 Python + 21 YAML，人只在关键判断点介入。

第三，**并行写作**。11 万字可研，一个人顺序写要写到天荒地老。锚定 `_WRITING_BRIEF.md` 一份口径，拉起 35 节并行、装配、质检——这是把'写'这件体力活并行化。

这三类活，就是一人公司里'一个人能顶五个人'的物理来源。**它们的共同点是：判断标准是清晰的、错了可回退、不牵扯对外承诺。** 记住这个共同点，因为下一页讲的'必须人扛侧'，恰好三条全反过来。"

**【板书/图】**
```
可替侧（智能体放大，人只做主）
 ① 认知萃取加速   102 事件→16 簇→7 画像/旅程
 ② 建模骨架生成   OAG: Obj76/Link75/Fn38/Rule47/Act54，3835 行 7/7 编译
 ③ 并行写作       1 份 BRIEF → 35 节并行 → 11 万字
 共同点：标准清晰 · 可回退 · 不涉对外承诺
```

**【康养项目证据】** 五要素合计 Object 76 / Link 75 / Function 38 / Rule 47（声明式 18 + function 骨架 29）/ Action 54 / HIL 26；代码 3835 行 + 21 YAML，7/7 py_compile ✓；知识图谱 14 类知识库 / 8 图谱 / 约 350 万三元组——这些"量"都是智能体放大出来的，不是手速。

### 3.3 要点页｜必须人扛侧：C7 四项，智能体接不了（12′，本讲最重）

**【讲述脚本】**
"现在讲这门课真正想让你记住的东西。一人公司的边界，不是'哪些活多、哪些活少'，而是 **C7 这四项：客户关系、责任承担、价值判断、政治敏感度**。这四项智能体接不了——不是'现在接不好、以后会好'，是**结构上接不了**。课程主张说得很硬：**C1–C6 可训练，C7 只能筛选。** 意思是前六维你招个人来能教会，C7 你只能招的时候筛掉不合格的，教不出来。

我给你康养项目里三个板上钉钉的例子，一个对应一项，你就懂'接不了'是什么意思。

**第一，客户关系 & 政治敏感度 → 11 处地方文号，智能体查不到也不能编。** 康养项目可研里有 11 处要挂本地依据：7 处本地文号（本地 DIP 细则、助餐补贴办法这类，`[本地待补文号]`）+ 4 处企业 SOP 编号（`[企业标准,FDE 补编号]`）。这些东西**公开渠道查不到**——不在国务院令里，不在 GB 里，只在某市医保局、民政局、政数局某个科室的文件柜里。智能体面对这种情况只有两个选择：编一个像模像样的文号（灾难），或者留空。我们留空——转成一份逐项取件清单，让人拿着去机关一个一个要。**这一步是纯人的活：你得认识那个人、进得了那个门、说得上话。** 这就是客户关系和政治敏感度，智能体没有身份、没有关系、进不了门。我们的原话是：**'错文号比空缺更有害。'**

**第二，价值判断 → 站长 HIL 的 0.75 置信度阈值，谁来拍。** 康养项目设了 26 个人在环（Human-in-the-Loop, HIL）闸门，其中站长 HIL（增收闸）挂了一个**置信度闸，阈值占位 0.75，待定**。这个 0.75 是什么？是'智能体对一个增收动作有多少把握时，才允许它直接推给站长执行、多少把握以下必须人复核'。定 0.7 还是 0.8，差一点，就是'橡皮图章'和'闸门形同虚设'的区别，背后是真金白银和信任。**没有任何模型能替你定这个数**——它不是算出来的，是权衡出来的：你要权衡站长被打扰的频率、错误增收的代价、系统被信任的速度。这是价值判断。模型能给你分布、给你历史误差，但那个阈值是人对'我愿意为速度冒多大错误风险'的表态。

**第三，责任承担 → 脱敏纪律与表述红线。** 康养项目课件和可研涉及真实客户主体、涉及财务口径。我们守一条红线：对外一律写'赋能优化'而不是'替代'——因为'AI 替代人'这个表述在 To-G 场景里是政治事故。这条红线智能体不会主动守，它会顺着你的 prompt 把话说满。守红线的是人，因为**承担说错话后果的是人**。一人公司里，对客户承诺、对政府表态、对合规兜底，署名的是你，不是模型。责任不可外包给一个不承担后果的东西。

把三个例子收一下：**智能体没有身份（进不了机关的门）、没有立场（拍不了 0.75）、不承担后果（守不了红线）。** 这三样恰好就是一人公司的边界。边界之内，你用智能体把自己放大成五个人；边界之外，你就是一个人，而且必须是你。"

**【板书/图】** 见配图占位。
```
必须人扛侧 = C7 四项
 客户关系 + 政治敏感度 → 11 处地方文号：查不到也不能编，人去机关取
 价值判断           → 站长 HIL 0.75 阈值：不是算的，是权衡拍的
 责任承担           → 脱敏纪律 / "赋能优化"红线：署名的是人
 本质：智能体 无身份 · 无立场 · 不担责
```

![图3-1 一人公司能力边界：可替 / 必须人扛](../figures/fig-3-1-OPC边界.png)
**图 3-1  一人公司能力边界：可替 / 必须人扛**
左半区是"可替侧"（认知萃取加速、建模骨架生成、并行写作），标注康养项目量化证据；右半区是"必须人扛侧"的 C7 四项，各挂一个康养项目铁证（11 处文号 / 0.75 阈值 / 脱敏红线）。中缝那条线就是一人公司的边界——图的重点是这条线，不是两侧的多少。

### 3.4 要点页｜三个铁证复盘：为什么这三条外包不出去（8′）

**【讲述脚本】**
"有人会说：文号将来能爬到、阈值将来能自动调、红线将来能写进 system prompt——是不是边界会移动？会移动，但移动的是**可替侧的宽度**，不是**必须人扛侧的存在**。我给你一个判据，帮你判断任何一条活到底在哪一侧。

问三个问题：**这活需要一个身份才能做吗？需要一个立场才能拍吗？做错了谁签字？** 只要有一个答案指向'人'，这活就在必须人扛侧。

- 11 处文号：需要'能进机关门的身份'——在人扛侧。哪怕将来某个平台开放了接口，'去要接口权限'这件事本身还是关系活。
- 0.75 阈值：需要'愿意为速度担多大错的立场'——在人扛侧。模型给分布，人给态度。
- 脱敏红线：做错了 FDE 签字担责——在人扛侧。

反过来，102 事件的整理、7 域骨架的生成、35 节的并行写作，三个问题的答案全是'不需要身份、不需要立场、错了能回退重跑'——所以稳稳在可替侧。**这就是那条线的判据，比记清单更管用。**"

**【板书/图】**
```
边界判据（三问，任一指向"人"即人扛侧）：
 ① 需要身份才能做？   → 客户关系 / 政治敏感度
 ② 需要立场才能拍？   → 价值判断
 ③ 做错了谁签字？     → 责任承担
```

**【康养项目证据】** 三问在康养项目的三个落点：文号取件（身份）、0.75 阈值（立场）、赋能优化红线（签字）。同一项目里可替侧的三类活（102 事件整理 / OAG 骨架 / 35 节并行）三问皆"否"。

### 3.5 要点页｜边界会动，但你要知道自己站在线的哪一侧（3′）

**【讲述脚本】**
"最后一句：一人公司不是让你逞能，是让你**清楚地知道自己什么时候必须叫人**。这门课的验收标准原话就是——'交付质量不低于康养项目基线，且知道自己在哪里必须叫人'。一个只会往前冲、不知道边界的 FDE，比一个慢一点但知道边界的 FDE 危险得多。因为前者会在 11 处文号那里编一个出来，会在 0.75 那里随手填个数，会把'替代'写进 To-G 方案。下一讲讲知识栈——但知识栈再厚，也补不了 C7。C7 是筛选出来的，不是学出来的。"

**【康养项目证据】** 课程验收标准（总纲一节）：独立承接中等复杂度 To-G/To-B 项目认知侧全链条，"且知道自己在哪里必须叫人"。

"讲了三个我们项目里的边界例子，现在轮到你的项目。打开工作坊，你要做的不是抄我这三条，而是**把你手上正在做的那个项目，逐个环节拍到线的两侧去**，并且**为每一条写清楚它为什么在这一侧**——用刚才那三问：需要身份吗？需要立场吗？错了谁签字？写不出理由的，说明你还没想清楚这条边界，那正是你今天要收获的东西。36 分钟，去工作坊。"

## 5. 复盘研讨（3 题 + 收口）

1. **你清单里"必须人扛"的条目，有几条其实是你**懒得让智能体做**、误判成人扛的？反过来，有几条你标了"可替"、但其实藏着一个身份/立场/签字问题？**（收口：边界最常见的错误不是划错侧，是**把偷懒当边界**。）
2. **假如你被要求把一条"必须人扛"的活外包给智能体（老板说"提效"），你会怎么向他解释这条不能外包？用康养项目 0.75 阈值或 11 处文号做类比。**（收口：能把边界讲给外行听，才算真懂边界。）
3. **C7 四项里，你个人最弱的是哪一项？它能靠这门课补吗？**（收口：诚实回答"补不了"的人，比嘴上说"我都行"的人更接近 L3。）

**讲师收口话术**："今天不发'你能当一人公司'的证书。今天让你带走一张**你自己项目的边界图**。一人公司的成熟度，不看你一个人干了多少活，看你**多准确地知道哪些活不能一个人干**。"

## 6. 本讲难听话 + 反例讲解

**难听话（1 句）**：
> "你以为'一个人干完'是本事——真正的本事是**在该叫人的地方叫人**。康养项目那 11 处文号，我们一个都没编；你要是遇到查不到的文号会顺手编一个，你不是一人公司，你是一个人的事故现场。"

**反例讲解（C7 边界实证，非 B 系列独立反例，按 BRIEF 第 4 节'第 3 讲：OPC 边界，引 C7 四项智能体接不了'）**：
康养项目编译期我们不是没动过"让智能体把 11 处地方文号也一起补上"的念头——它能生成格式完全正确、编号规则完全合理的假文号，肉眼几乎分辨不出。**恰恰因为它编得太像，才最危险**：一份挂着假文号的可研交到医保局，比一份坦白写"此处待补"的可研，杀伤力大得多。所以我们把这 11 处**全部保留占位**，每处锚定一个已核验的上位国标（如 DIP 技术规范 医保办发〔2020〕50 号），再转成向某市医保局 / 民政局 / 政数局逐项取件的清单。这就是主张 3——"FDE 专业性一半体现在敢说不知道"——在一人公司边界上的具体形态。**注意这和第 6、9 讲的 B-10 是同一个失误点的三次复调**：第 3 讲讲它划定 OPC 边界，第 6 讲讲它的 HIL 处置流程，第 9 讲讲它对标 Palantir 的现场取证文化。

## 7. 与其他讲的钩子

- **← 第 2 讲**：第 2 讲用人力对比数字（5+ 人 / 数周 vs 1 FDE）证明"一人公司能成立"；本讲接着证明"一人公司有边界"，两讲合起来才完整。
- **→ 第 4 讲**：本讲说 C7 补不了；第 4 讲讲 C1/C2/C4/C5/C6 对应的**七角色方法论合体（七栈）**——**能补的那一半**。听完本讲你该带着"我 C7 哪项弱"的问题去听第 4 讲，别指望知识栈补 C7。
- **→ 第 6 讲**：本讲的 0.75 阈值、26 个 HIL 点，在第 6 讲展开为 **HIL 设点四条硬判据（不可逆 / 涉钱 / 涉合规 / 跨组织）+ 一条置信度兜底闸**；本讲只讲"为什么人扛"，第 6 讲讲"怎么设闸"。
- **→ 第 8 讲**：本讲"C7 只能筛选"是第 8 讲"什么样的人能成为 FDE / 多数人第一次停在 L1"的直接前置。
- **反例复调**：B-10（11 处地方文号）在第 3 / 6 / 9 讲各出现一次，本讲负责"划边界"这一声部。
