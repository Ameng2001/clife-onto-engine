第 8 讲 · 什么样的人能成为 FDE（讲师用讲义）

版本 v1.0 · 对象：C-Life 内部专业人员 · 时长 120′ · 实践蓝本：康养行业大模型及微康养生态运营平台 本讲义讲"怎么讲"；学员动手材料见 工作坊/08_什么样的人能成为FDE_workshop.md，不重复。

一、一句话命题 + 能力位置

命题：解决方案架构师、交付架构师、需求分析师——都不是 FDE。

这三类是我们组织里现成的、看起来"最像 FDE"的人，也正因为像，才最危险：他们会以为自己"稍微学一下 AI 工具就是 FDE 了"。这一讲的任务是把这层误会当众撕开——不是打击谁，是让每个人看清自己现在的能力结构差在哪一维，然后知道往哪补。

本讲在能力模型中的位置：本讲是能力模型（C1–C7）的总检票口。前 7 讲逐维训练 C1–C6、反复点名 C7；本讲把七维拉成一张招聘/选拔可用的对照表和画像，并落到一句总纲里那句话上——C1–C6 可训练，C7 只能筛选。本讲不新增技能，发的是"照镜子的尺子"。

三、认知输入

要点页 1 · 三类"看起来最像 FDE"的人，为什么都不是（8′）

【讲述脚本】（讲师原话级）

"我们先把三个候选人请上台，因为你们中的大多数，简历上写的正是这三个词之一。

解决方案架构师——他从'一个技术方案'开始工作，交给客户一份架构图。他很强，但他的起点是'系统怎么搭'，不是'客户的模糊话到底是什么意思'。康养项目这条链的第一步不是画架构，是把客户一句'帮站长管好老人'拆成 102 个业务事件——这一步架构师通常直接跳过，因为他默认需求已经有人整理好了。

交付架构师——他从'一个已经定型的方案'开始，负责把它落地、集成、上线，交付一套跑得起来的系统。他的价值在'把定好的东西做出来'，可 FDE 的价值恰恰在'定'之前那一段——从 16 事件簇收敛到 7 域限界上下文，那是判断，不是集成。

需求分析师——他离 FDE 最近，也最容易自我感觉良好。他会做访谈、写需求文档。但他的交付物是'一份需求清单'，交给下游就结束了；他不为'这份需求能不能编译成 7 域、38 个 Function、47 条 Rule、54 个 Action'负责，更不为'哪个 Action 要设 HIL 闸、按错了谁赔'负责。

三个人都真、都强、都有用。但他们各自只握住 FDE 这条链的一段。FDE 不是这三个人里最好的那个，FDE 是这三段本来就不该切开的那条链。"

【板书/图】

图 8-1 传统三角色 vs FDE 六维对照

图说：左三列为解决方案架构师 / 交付架构师 / 需求分析师，右一列为 FDE。六行分别是工作起点、交付物、与客户的关系、失败归因、能力半径、工具依赖。用颜色深浅表示"覆盖了 FDE 这条链的哪一段"，直观呈现三类角色各自只覆盖一段、FDE 贯通全段。

【康养项目证据】

康养项目这条链——102 事件 → 16 簇 → 7 画像 → 7 旅程 → 5 流程 → 10 热点（P1–P5）→ 7 域 D1–D7 → 3835 行骨架 + 26 个 HIL 点 → 11 章可研——由 1 名 FDE 带智能体编队完成。传统模式是产品经理 + 架构师 + 行业顾问 + 方案经理 + 美工 5+ 人 / 数周。三类角色恰好分别对应其中一段：架构师管"系统怎么搭"、方案经理管"落地"、需求分析对应产品经理那段的一部分。没有任何一段能单独对客户的最终结果负责。

要点页 2 · 六维对照表：逐维拆开三类角色与 FDE 的差（12′）

【讲述脚本】

"现在我把这张对照表逐维讲透。你们招人、内部选拔，就用这六维当尺子。我一维一维过，每一维你都对号入座——你自己现在站在哪一列。"

"看第 4 维'失败归因'——这是最见人品的一维。三类角色出了问题，话术都是'别人的锅'；FDE 没有这个话术，因为全链是他一个人走的，接缝数为零，断层无处推。这不是道德要求，是结构决定的：你把四段合成一段，就再也找不到'上一棒没交好'这个借口了。"

【康养项目证据】

  • 第 ④ 维实证：康养项目全链 0 次跨人交接，7 域引用 7/7 零悬空——因为定义方和引用方是同一个大脑，没有"D3 引 D1 对不上口径"这种接缝断层（呼应第 1 讲）。
  • 第 ⑥ 维实证：7 个域同一天并行编译、7/7 py_compile 通过，靠的是 studio-planner → domain-model → clife-onto-engine 这条固化管线，不是个人手速（呼应第 5 讲主张二"没有工程化平台的 FDE 只是更累的架构师"）。

要点页 3 · 硬能力矩阵 C1–C6：可训练的六维（12′）

【讲述脚本】

"好消息先说：FDE 的六维硬能力，都能训练。坏消息随后：训练它们，比你想的贵、慢、且必须在真实项目上磨。我把 C1–C6 逐维给你判定基线——达到哪个程度算过关。这张矩阵你在工作坊里就要拿来给自己打分。"

【康养项目证据】

C1–C6 每一维都有康养项目的量化落点（见上表"康养项目对应动作"列）。特别是 C3：康养项目 54 个 Action 里筛出 26 个 HIL 点，其中 D6 民政域 8 个（DP-H 闸）、D4 居家照护 6 个（含急救指挥）——设闸判断没有任何模型能替你做，这是 C3 作为"护城河维"的直接证据。

要点页 4 · 软能力 C7：只能筛选，不能训练（8′）

【讲述脚本】

"现在讲最扎心的一维——C7，人的部分：客户关系、责任承担、价值判断、政治敏感度。总纲里那句话是全课程的支点：C1–C6 可训练，C7 只能筛选。

什么意思？C7 不是'练一练会变好'的技能，是'你这个人是不是这种人'的底色。我给你们四个具体切片：

客户关系——不是会说话，是客户信不信你敢对他说'这个我不知道'。康养项目 11 处地方文号查不到，FDE 的处理是坚决保留 [本地待补文号] 占位、锚定上位国标、转成向医保局/民政局逐项取件的清单，而不是编一个像模像样的假文号糊过去。内部原话——'错文号比空缺更有害。' 一个改不掉'不能在客户面前露怯'这个本能的人，永远做不到这一步。

责任承担——第 2 维对照里那个'无处甩锅'，能不能扛得住，是天性不是培训。

价值判断——康养项目那条红线：表述一律用'赋能优化'而非'替代'，因为涉及民政、就业、政治敏感。什么时候该踩刹车，是价值观在做判断，不是流程在做判断。

政治敏感度——To-G 项目里，一句话措辞不当就可能引火烧身。这个雷达，有的人天生有，有的人怎么教都装不上。

所以选拔 FDE，C1–C6 看能不能补，C7 看是不是这块料。C7 不合格，前六维再强也不能给他 L3、不能让他对客户承诺负责。"

【板书/图】 板书四象限：横轴"可训练↔︎只能筛选"，纵轴"硬↔︎软"。C1–C6 落在"可训练"半区，C7 四项（客户关系/责任承担/价值判断/政治敏感度）落在"只能筛选"半区，用红框圈出并写一句："C7 不是加分项，是一票否决项。"

【康养项目证据】

C7 的四个切片各有康养项目锚点：客户关系→11 处占位不编造（"错文号比空缺更有害"）；价值判断→"赋能优化"而非"替代"的表述红线；政治敏感度→D6 民政域 8 个 DP-H 监管发布闸的设置本身，就是政治敏感度的结构化产物。

要点页 5 · 团队编成：1 主理 + N 见习 + 平台组（8′）

【讲述脚本】

"最后一页最实际。你现在知道 FDE 稀缺、C7 筛不出几个，那怎么组队干活？答案不是'招一堆全能 FDE'——那是幻想。答案是一个非对称编队：

1 名主理 FDE（L3）——C7 过关、C1–C6 齐全，主持项目、设 HIL 闸、对客户承诺负责。康养项目就是这个角色一个人带编队走完的。一个 L3 是整个编队的'判断中枢'和'甩锅终点'。

N 名见习 FDE（L1）——C7 有潜质、C1–C6 在补齐中。他们在 L3 指导下承接单一环节：比如专攻 C1 主持事件风暴、或专攻 C6 写并行章节。L1 不独立对客户承诺，但在真实项目里练六维。康养项目若要复制，第二个项目就应该配 2–3 个 L1 在 L3 身边过手。

平台组——不是 FDE，是让 FDE 不必'更累'的人。他们维护 Astra Studio 建模管线（planner/domain-model/clife-onto-engine/citations/可研生成），把方法论固化成工具，让 7 域能同日并行编译。没有平台组，L3 就退化成一个更累的架构师（第 5 讲主张二）。

记住这个编队的本质：L3 提供判断和责任（C7 + 高阶 C1–C6），L1 提供手数和成长通道，平台组提供杠杆。三者缺一，康养项目都不可复制。"

【板书/图】

图 8-2 FDE 团队编成（1 主理 + N 见习 + 平台组）

图说：中心为 1 名主理 FDE（L3），标注"判断中枢 / 责任终点 / C7 过关"；环绕 N 名见习 FDE（L1），各标注承接的单一环节（C1 事件风暴 / C6 并行写作等）；底座为平台组，标注"维护 Astra Studio 管线 / 提供杠杆 / 非 FDE"。箭头体现 L3 向 L1 的指导流、平台组向全员的能力供给流。

【康养项目证据】

康养项目现状是"1 名 FDE 带智能体编队"跑通了单点——但总纲说得很直白："目前不可复制——因为方法在一个人脑子里，不在组织里。" 这个编成图就是把"一个人的方法"变成"组织能力"的最小结构：L3 把判断显性化教给 L1，平台组把工具固化下来。第 10 讲的 90 天计划，第一步招的就是这三类人。

要点页 5·补 · 能力半径 + 团队编成随"交付模式"变（板书 · 4′）

讲述脚本："六维里最容易被高估的是 ⑤ 能力半径，而它跨交付模式才见真章。有人在康养项目做完一个康养大平台，就以为自己是 L3 了。我泼盆冷水：能做模式二的大平台，不代表你能做模式一的 SaaS 应用，反之更是。 两种模式的团队编成根本不同——模式一（Token-SaaS，如教育督导项目）编成轻：1 个 FDE + 平台/运行时组，快跑快迭代；模式二（大平台建设运营，如康养项目/草业项目/辣椒）编成重：1 个主理 FDE（L3）+ N 个见习 + 平台组，而且要扛得起可研、财务测算、监管合规——商业和合规的能力半径要宽得多。你擅长哪种模式，直接决定你能主理哪种项目。 而真正的分水岭是 C1 认知萃取的跨行业迁移力：教育督导项目能用和康养项目同一套管线做出来，证明方法能迁移；但你能不能在一个你不熟的行业（学前督导、辣椒育种、草原修复）里，快速把模糊意图压成可归域的结构？康养你可能靠沉淀蒙对了，换个行业沉淀归零、只剩方法——这就是 L2 和 L3 的分界。 最后一句诚实话：辣椒/草业项目目前只到方案、草业项目 demo 还是 Mock，所以我讲它们只敢讲'定位与结构'，不敢讲交付实测——知道自己在哪个模式、哪个行业、哪个阶段还没有发言权，本身就是能力半径的一部分。"

板书：能力半径随交付模式变——模式一轻编成(1 FDE+平台组) / 模式二重编成(主理 L3+见习+平台组+宽商业合规半径)；C1 跨行业迁移力=L2/L3 分水岭。康养项目🟢/教育督导项目🟢/辣椒🟡/草业项目🟡。

四、现场演练导入（过渡话术）

"道理讲完，现在照镜子。接下来 48 分钟分两步走：

第一步，给自己打分。用刚才那张 C1–C7 矩阵，逐维给自己评 L0/L1/L2/L3，并且必须写出'证据'——你凭哪个真实项目动作打的这个分，不许空评。这一步会很难受，因为你会发现自己大概率停在 L1，尤其是 C3 风险设闸和 C4 合规治理这两维。停在 L1 是正常的，装作 L2 才是危险的（总纲原话）。

第二步，起草一份团队编成草案。假设下个月给你一个康养项目量级的项目，你怎么配 1 主理 + N 见习 + 平台组？谁当 L3？为什么？你自己站哪个位子？

工作坊材料里有能力矩阵打分表、编成草案模板和评分卡，翻到 08_什么样的人能成为FDE_workshop.md。"

五、复盘研讨（24′）

六、本讲难听话 + 反例讲解

难听话（1 句）

"你现在的能力结构做不了 FDE，而且我能当场说出你差在哪一维——

  • 架构师型：你卡在 C1 认知萃取。你太急着画架构图，默认'需求有人给你整理好了'，可 FDE 这条链的第一刀就是自己把客户一句模糊话拆成 102 个事件——这一步你从来没做过，你只是接手了别人做完的那一步。
  • 需求分析型：你卡在 C2 结构建模 + C3 风险设闸。你能采集需求、能写文档，但你交出去就完事，从不为'这份需求能不能编译成 7 域 47 条 Rule 54 个 Action、哪个 Action 要设闸'负责——你握着离 FDE 最近的一段，却最容易停在 L1 而自以为是 L2。
  • 项目经理型：你卡在 C2 结构建模（外加 C6 的'并行编排'你会调度但压不出结构）。你擅长把人和进度管起来，但 FDE 的杠杆不是管人，是一个人的头脑里长出可编译的结构——你调度得再好，结构还是得有人压出来，而那个人不是你。 别急着反驳。先在工作坊里诚实打一次分，你会发现我说得比你想的准。"

反例讲解 · 全反例作"这些坑谁来兜"论据（B-3 / B-6 / B-10 为主）

本讲不专属某一个反例，而是把全课程反例库当作**"如果编队里少了某一维能力，这些坑就没人兜"**的证据链，正面论证六维缺一不可：

  • B-6 标准号误标（药食同源目录曾误标"GB 药食同源目录"、星评沿用已废止 MZ/T）——缺 C4 合规治理的人兜不住。需求分析师、架构师"看起来像国标就用"，正是 C4 缺位的典型症状。
  • B-3 图片路径断裂 / B-4 Word 主题色覆盖——缺 C6 交付物工程的人兜不住。这两个坑发生在"内容都对、但交付物散架"的环节，恰是三类角色最不设防的一维。
  • B-10 十一处地方文号无解——缺 C7 的人兜不住，会去编一个假文号。这个坑不是能力问题，是价值观问题，只能靠 C7 筛选把关。B-10 是全课程价值观支点，本讲第三次出现（前见第 3、6 讲），此处的角度是：它证明了为什么 C7 必须"只筛不训"——因为面对查不到的文号，"编还是留白"这个选择，暴露的是人的底色，不是技能的高低。

引出的原则：六维不是选修，是编队的六根承重柱。招聘和选拔时，你可以接受一个候选人某一维暂缺（L1 补），但你必须在编队层面凑齐六维，否则总有一类坑没人兜——而客户不会因为"那是别人负责的维度"就原谅你。
