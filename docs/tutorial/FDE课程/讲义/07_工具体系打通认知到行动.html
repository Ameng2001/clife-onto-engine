一、10 分钟导览：这套工具到底是什么

一句话：Astra Studio 是把 FDE 方法论固化下来的一套插件，九个插件各管一段，产物首尾相接。

studio-core      工作区管理（init / status / promote / create-expert）      ← L2 / L8
studio-insight   业务分析六件套（画像/旅程/流程/画布/行为矩阵/机会）        ← L4 上半场
studio-planner   规划流水线（事件风暴→域模型→技能设计→骨架→填充）          ← L4 下半场 / L8
studio-ontology  本体编译（五要素 IR → 可运行插件）                        ← L5
studio-docs      文档交付（蓝图/写作专家/并行写作/装配/导出）               ← L6
studio-platform  平台文档套件（脑图/技术设计/项目计划/迎检话术）             ← L6
studio-design    设计转代码（截图→.pen→openspec→React）                    ← L7
studio-quality   插件校验 + MCP 接线                                       ← L8
fund-review      政府采购报价优化 + 财评预审（垂直插件）                     ← L8 选修

四条依赖：planner → core + insight；docs / platform / ontology → core；insight / quality / design 零依赖。

二、两个必须先建立的认知

① 产物即接口：层间契约比工具本身更重要

工具之间不靠内存传参，靠文件。studio/changes/{domain}/ 下的每个文件都是上一步的输出、下一步的输入。

这带来三个直接后果（L4 下半场 展开）：随时可中断 · 每步可单独跑 · 可以人工改产物再继续。

占位符即契约：你在文档里写了要引用的文件，它就必须存在。 这条纪律在 L8 有物理落点——/studio-quality:validate 会把“引用了不存在的 scripts/xxx.py”直接判 failed。

② 认知到行动 = OAG，不是 RAG

OAG ≠ RAG：RAG 是“检索得准一点”，OAG 是“越权的结果根本生成不出来”。 防幻觉在执行层（本体约束求解），不在检索层。LLM proposes, ontology enforces.

L5 会讲透这一层，并给出物理机制：guards / post_rules / HilPolicy 三道关。
