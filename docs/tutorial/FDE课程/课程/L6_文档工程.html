这一课真正在教什么

不是“用 AI 写文档”——那个谁都会。 是教“让 10 个作者写出来像一个人写的”。

康养项目可研 11 章 / 约 11 万字 / 26 图，是 35 个分节并行写作产出的。 学前教育项目可研 653KB / 44 分章，同一套打法。

并行写作的全部难点不在“写”，在“不打架”： 术语要一致、数字要同源、编号不能撞、图文引用不能断。

这门课的答案是三件东西：

  1. 蓝图（blueprint）—— 定文档骨架，谁都不许自己发挥章节
  2. 写作专家（writer）—— 定文风，让 N 个作者有同一个人设
  3. 装配期收口（assemble）—— 编号权、术语统一权归装配阶段，不归写作阶段

⭐ 第 3 条正是反例 B-2 的教训固化成的机制：康养项目 35 节并行写作时各节自行起标题层级，装配期出现编号重复与跳号。 现在这条纪律被写进了工具——写章节只管本章内部，跨章编号一律由装配重排。 这就是“平台=方法论固化物”最具体的一次兑现。

你要交出什么：写作专家 1 份 + 一节方案稿 + 一张配图占位 +（可选）导出的 docx

一、先说三栈知识：为什么这三块捆在一起

第一课说过：FDE 不是“会建模的人”，是七个专业角色的方法论合体；建模只是七分之二。

这一课一次讲三栈，因为它们共同决定了客户手里那份文件能不能签字：

栈④ 商业模式与财务  → 决定文件里"这生意怎么成立"那几章有没有内容
栈⑥ 交付物工程      → 决定这些内容能不能被组织成一份能过评审的正式文书
栈⑦ 合规治理        → 决定这份文书经不经得起一句"这个数据/文号哪来的"

多数技术出身的人不是倒在建模，是倒在这三栈——盘不出账、过不了财评、组织不起百页交付物。 本课就是这三块塌陷的正面战场。

二、栈④ 商业模式与财务

【原本是谁】 商业顾问 / 战略——负责回答“这事怎么挣钱、谁付钱、付多少、几年回本”。

这是最多技术型 FDE 完全空白的一维：能出 7 域本体，却搭不出一个能自洽的商业模式， 方案在客户那边就是“技术很好，但不知道怎么赚钱”。

商业模式设计五件套

# 框架 内核 一句话记法
① 商业模式画布 9 个模块：右侧价值面＝客户细分 / 价值主张 / 渠道 / 客户关系 / 收入来源；左侧效率面＝关键伙伴 / 关键活动 / 关键资源 / 成本结构 画一张就能和客户对齐“这生意怎么转”的通用底图
② 免费 / 交叉补贴（Chris Anderson《Free》） 四型：直接交叉补贴（剃须刀送、刀片赚）· 三方市场（用户免费、广告主付）· Freemium · 非货币市场 关键是想清楚“谁被补贴、谁来买单”
③ 互联网三级火箭 一级头部流量（免费高频入口）→ 二级沉淀用户（锁进商业场景）→ 三级商业闭环（低频高价变现） 从高频到低频；一级不赚钱，要有人扛得住
④ SaaS 指标体系 MRR/ARR · CAC · LTV · LTV:CAC ≥ 3:1 · Churn · NRR > 100% · Rule of 40 订阅制生意的专用财务语言
⑤ 增长思维 北极星指标（全公司只对齐一个）+ 四个增长关卡 “增长能力＝持续作出正确决定的能力”

⭐ 本栈最关键的洞察：财务语言随“交付模式”变

交付模式 商业模式底色 该用的财务语言 别用错
模式二 · 大平台建设+运营
（康养项目 / 草业项目 / 辣椒）		 重资产、投—建—运、多元收入 投资估算 / EBITDA / IRR / NPV / 回本周期 别用 MRR——一次性建设+运营盘不是订阅
模式一 · Token 计费 SaaS
（教育督导项目）		 轻资产、订阅 / 按量、可复制 MRR/ARR / LTV:CAC / NRR / Churn / Rule of 40 别用 IRR / 回本年——SaaS 早期没有“回本年”这回事

一句话记死： 客户问模式二的项目，你答 IRR 15.2%、第 9 年回本； 客户问模式一的 SaaS，你答 LTV:CAC 3:1、NRR 120%。

答反了，客户当场就知道你没做过这类生意。

这条直接影响你今天的写作动作：可研蓝图里的效益分析章用的是模式二语言； 如果你的命题其实是模式一 SaaS，照着可研蓝图硬写 IRR，写出来就是空的。

范本：康养项目 BP 是“交叉补贴 + 三级火箭”的活体

段 康养项目的答案 对应框架
顶层逻辑 门诊医疗引流 → 照护康养创收 → 产品增值补充 → 政企合作加速 三级火箭：门诊医疗＝一级（低毛利引流）· 会员沉淀复购＝二级 · 照护/商城/长护险＝三级（高毛利变现）
收入结构 三元支付 ＝ 老人自费 + 长护险 + 政府购买服务 本质是交叉补贴——政府/长护险补贴了老人自付不起的那部分
最小验证单元 微康养单店：峰值资金约 73 万、约 21 个月回本、单站 1.5–5 人，60 站可复制 BP 的说服力来自“一个单元跑通、可复制”，不是“整盘很大”
增长引擎 会员转化复购飞轮（中医理疗 + 长者食堂 + 康养商城三线咬合） 画布的“客户关系”
主体与分账 投—建—运分离（EPCO）、项目联合体、分账核算 ⚠️ 2026-07-20 起禁用“合资公司 / 股权 / 注册资本”

一个 Excel 财务模型里的基础概念（技术人最缺）

概念 是什么 康养项目的数
EBITDA
息税折旧摊销前利润		 营收减经营成本，但加回利息、税、折旧、摊销——衡量主业本身的现金创造能力 基准口径 约 5219 万/年（营收约 3.83 亿/年、净利约 3535 万）
IRR
内部收益率		 使净现值 NPV = 0 的那个折现率——通俗说是项目每年的“复合回报率”，必须跟一条门槛线比 运营口径 15.2%（第 9 年回本，主口径）
发改口径 8.7%（第 11 年，仍高于国企 6% 门槛）
NPV
净现值		 未来每年净现金流按折现率折回今天再求和，>0 才值得投 —
回本周期 累计净现金流由负转正的那一年 第 9 / 11 年（两套口径）

⭐ 一句话串起来（模式二重资产语言）：

营收 − 成本 = EBITDA（主业赚钱力）
  → 扣息税折旧 = 净利
  → 逐年净现金流折现求和 = NPV
  → 令 NPV = 0 的折现率 = IRR
  → 累计转正之年 = 回本

这五个数，就是 To-G 大平台项目签字前客户和财评专家盯的那几行。

⭐ 两套 IRR 口径并存不是矛盾，是财务常识——算的钱流范围不同（运营口径只看运营主体分到的，发改口径看整盘）。 ⚠️ 口径名以成品可研为准：叫运营口径，不叫“合资口径”。

看到“15.2% 和 8.7%”第一反应不该是“数据打架”然后自己去改一个——那就正好踩中 B-5。

换成模式一 SaaS 的语言

客户不问“几年回本”，问的是： 获客花多少（CAC）· 一个客户一辈子贡献多少（LTV）· 这两个比值健不健康（LTV:CAC ≥ 3:1）· 客户跑不跑（Churn）· 光靠老客户能不能增长（NRR > 100%）· 整盘够不够格（Rule of 40）。

FDE 要能在两套语言间自由切换——这就是本栈“自评到能交付”的标准。

栈④ 与财评的接口

商业模式回答“这生意成不成立”，财评回答“这笔钱算得准不准”。

  • 学前教育项目走财评这条线：484 个功能条目 → 约 27,056 功能点 → 约 22,014 人天 → 总投资 4,839 万（三重依据交叉校核）
  • 康养项目走投资回报这条线：一期 1.36 亿（依托条件，不计入本轮新增）+ 二期 3200 万（五块预算）→ 运营口径 IRR 15.2%

两条线在可研里是两章，但共用一条纪律：数字锚在单点，谁都不许在自己那节重算。

三、栈⑥ 交付物工程

【原本是谁】 方案经理 / 标书工程师——负责把一堆认知与测算，组织成一份能中标、能过评审的正式交付物。

权威参照：发改委《政府投资项目可行性研究报告》编制大纲 / 各地可研编制规范 + 招投标响应文件的组织。

本课程把它固化成三件东西：写作规范 + 锚定口径机制 + 装配质检。

项目 交付物规模 组织方式
康养项目 🟢 可研 11 章 / 约 11 万字 / 26 图 + 2 附录 docx 35 个分节并行写作，靠一份 BRIEF 统一口径；编号权归装配阶段
学前教育项目 🟢 可研 653KB / 44 分章 + 送审报价包 + 单一来源论证 同一套打法；没做本体建模、没有画像旅程，照样交付

这一栈就是把前面几栈的产物“落成客户手里那份文件”的能力—— 没有它，你脑子里有 7 域本体，客户手里什么都没有。

⭐ 并行写作的三条铁律

1. 口径单点 —— 所有数字锚在一份 BRIEF，分节作者一律引用不重算（B-5） > 反例根因：老龄化率跨节引用中 60+ 与 65+ 两个口径被混用。 > 不是笔误，是没建立“单一真相源”的纪律。

2. 编号权归装配 —— 写作阶段只管本章内部，跨章编号一律由装配重排（B-2）

3. 占位符即契约 —— slug 必须先定后画，不可事后改名（B-3，第七课会再撞一次） > 配套回收 B-1：康养项目图规格文件标题写“22 张”、表体实际 26 行——摘要与明细必须有单一真相源，现在图表编号由装配期统一分配。

三条铁律都不是“建议”，是被工具执行的——这就是“平台＝方法论固化物”在本课的兑现。

四、栈⑦ 合规治理

【原本是谁】 合规官 / 法务——负责守红线、给每条涉规论断挂可核验的官方现行依据。

权威体系：等保 2.0（GB/T 22239-2019）·《个人信息保护法》·《数据安全法》·《生成式人工智能服务管理暂行办法》，及行业国标 / 法规。

三态诚实（写作时的三选一）

情况 怎么写
查到了现行有效的 挂标准号 + 发文字号
是常识 标“通用”
查不到 留占位 + 锚定上位国标 + 转取证清单

康养项目的实数：18 处挂已核验国标 / 法规；11 处坚决保留 [本地待补文号]（7 本地文号 + 4 企业 SOP），每处锚定上位国标、转成逐项取件的清单。

内部原话：“错文号比空缺更有害。”（B-10）

⚠️ 反例 B-6 · 标准号误标

康养项目编制期两处真实误标：

  • 药食同源目录被误标为 “GB 药食同源目录”——它根本不是 GB，是原卫生部 / 卫健委发布的名单
  • 星评标准沿用了已废止的 MZ/T 标准——标准还在，版本已废止

引标准必须核到官方现行版本： “看起来像国标”不等于是国标，“标准存在”不等于“现行有效”。

已废止比查不到更危险，因为它看起来完全合规。

硬动作：用“全国标准信息公共服务平台”核现行 / 废止，用“国家法律法规数据库”核法规。

⭐ 复调：三个场景，同一条判据

诚实边界不是本课的局部纪律，它在全课程出现三次——这是复调，不是重复：

场景 说法 在哪讲

B-11 别人的数字不是你的数字——模板可复用，数字不可复用 第三课 / 本课（generate-speech 的“无其他行业项目残留术语”检查）
Mock 边界 Mock 不能说成跑通 第七课

第七课会把这条推到第四个场景——外部事实分官方 / 二手 / 未获证实三档。

你会以为“合规”只是可研最后一章的事，其实它是这门课的价值观支点。 前面几课练的是手艺，这一条练的是能不能把手艺交给你。

三个重点蓝图（HR项目 覆盖的那三本）

tender-document 招标文件（7 章 + 附件，tone formal-legal） 第四章「技术需求与服务要求」8000–12000 字是核心章。 compliance 硬指标：总分 100 分 · 资质无排他条款 · 预付款 ≤30% · 须含格式模板 · 须声明采购方式及法律依据 · 技术需求逐条编号 · 知识产权归属明确

bid-document 投标文件（3 大部分共 11 个 chapter） 「三、详细技术方案」10000–18000 字，全篇最大。 required_elements 8 项含需求响应表 / 偏离说明表 / 进度甘特图 / 人员组织架构图。

acceptance-package 验收材料（9 部分 + 附件） 含需求跟踪矩阵（招标需求→功能模块→测试用例→完成状态）。 量化门槛：跟踪矩阵 100% 覆盖 · 功能测试通过率 ≥98% 且 P1 缺陷归零 · 等保测评通过 · 培训覆盖率 100% · 决算不得超合同额

⭐ 这三本连起来，就是HR项目 那个项目的完整生命周期—— 也是全部案例里唯一覆盖「招标 ↔︎ 投标 ↔︎ 验收」的。 康养项目和学前教育项目都只到可研。

六、⭐ 写作专家：本课主教具

它是什么

「解决方案专家 — 肖作仕」（3.5KB）。领域是政府信息化项目建设方案 · 产教融合 · 人力资源数字化。

它同时是三样东西：

  1. 官方文档里的示例名（还示范了命名规则 解决方案专家-肖作仕 → solution-expert-xiao.md）
  2. 三个真实项目的作者人设：康养项目可研、学前教育项目可研（44 章 / 653KB 正文按此纲领产出）、HR项目 全套文书
  3. 你今天的现成范本

⚠️ 诚实标注：BRIEF 以它为作者人设是硬证据；但“这些 docx 逐字由该 agent 生成”无法证明（没有生成日志）。 准确说法是“按其文风纲领组织写作”。

这本身就是本课的第一课：连自己的案例都要区分“能证明的”和“听起来像的”。

Writing Style 四维（造专家时要填满）

维 填什么
① 语言标记 四字短语密度（高/中/低）· 对仗句式频率 · 递进模式（“从…到…”“由…向…转变”）· 标志性表达
② 政策引用 引用格式模板（《政策全称》（发文字号））· 偏好机关 · 引用密度
③ 段落模式 结构（论点+论据+价值阐述）· 字数区间 · 量化数据要求
④ 术语偏好 ✅/❌ 成对列举：✅信息化建设 / ❌IT建设、✅总体架构 / ❌系统架构、✅保障措施 / ❌风险应对

段落长度 每段平均字符 短 <150 · 中 150–350 · 长 >350
量化数据 每段数字/百分比计数 高 ≥2 · 中 1 · 低 <1

⭐ 工具里有一条实操提醒，值得记死： 客户说“我要一个像肖总那样的写手”时，必须索要样稿——光有名字抓不到文风。

这句话可以推广到整个 FDE 工作：客户给你一个人名 / 一个标杆，你要的是那个东西本身。

七、并行写作三段：plan → write → assemble

plan：那个确认点是本课最该认真对待的地方

拆分阈值：<5,000 字符 → 1 个任务；5,000–15,000 → 2–3 个；>15,000 → 4–6 个

覆盖度四分类：✅Full · ⚠️Partial · 📝Auto（模板可生成）· ❌Manual（如经费预算）

⏸ 硬性人工确认点：会给你「章节×产物映射表 + 并行阶段图 + 统计 + Gap 提示」，你可以 approve / 改分组 / 预先标 manual / 调字数 / 排除可选章。

这个确认点在告诉你哪些章节没有料可写。 标 ❌Manual 的那些，就是你得自己去要数据的地方—— 跟第五课的 citations 取证清单是同一个动作。

write：一条最重要的硬约束

每章写成 .parts/{chapter_id}.md，纯 markdown、无 frontmatter。同 chapter_id 重跑直接覆盖（幂等）。

自检 7 项：编号约定 · 每大节 ≥1 Mermaid（若蓝图要求）· 数据密集节有表 · 政策引用 · 字数在区间 · 标题不跳级 · [待补充：XXX] 仅用于真缺数据

⭐ 最重要的一条硬约束： 事实内容一律来自 artifacts，禁止编造统计数字、政策文号、预算。

这就是 B-10「错文号比空缺更有害」被写进工具的样子——缺数据就写 [待补充：XXX]，不许圆。

⭐ assemble：编号权在这里

收口动作 怎么做
章级编号 按蓝图约定校验并补缺重排（缺“三”则四→三顺移）
节级编号 （一）(二) / 1. 2. / (1)(2) 在每章内独立重排，校验标题不跳级
图表编号 统一在装配期分配：图 图X-Y（caption 在图下方）、表 表X-Y（caption 在表上方）
术语统一 读 writer 的术语表替换变体；不替换代码块、mermaid、「」/《》内直引
交叉引用 只校验不自动修（章/节/表/图/附录五类）

前置：required 章缺失 → 停止装配。 部分失败：装配可用部分，并在缺口处插入 > ⚠️ **本章内容待补充** 占位块 + 失败原因。

⭐ 回收 B-1：现在图表编号由装配期统一分配——摘要与明细有了单一真相源。 并行产出必须有收口回改动作，这条纪律现在是机器在执行。

质量报告

装配时间戳 · 章节清单 · 术语替换日志（含出现次数与行号）· 交叉引用校验 · 图表编号分配 · 合规清单 · 缺失章节建议

6 条合规检查：政策引用数 ≥ 蓝图下限 · required 章齐全 · 含投资/预算表 · Mermaid 数量 ≥ 下限 · 字数在区间 · 需要则有甘特

八、导出

依赖：pandoc 唯一硬依赖，缺则 STOP；mmdc 缺 → 保留 mermaid 代码块；python-docx 缺 → 只出裸 pandoc DOCX；Chrome 缺 → 跳过 PDF

DOCX：pandoc 转换后由脚本做中文公文美化——六步固定流水线：页面布局 → 标题 → 正文 → 表格 → 页眉 → 页脚。 关键实现：东亚字体通过 XML 直写（python-docx 不原生支持），行距 240×1.5=360，页边距上下 2.54cm / 左右 3.17cm，页眉取首个 Title/Heading 1 并加下边框线，页脚插 PAGE 域。

PDF：优先 pandoc → html5 → 注入中文公文 CSS（A4、仿宋 14pt/1.5、方正小标宋标题）→ Chrome headless 打印；兜底 XeLaTeX。

十、实操（90′）

序 做什么 时长 产出
1 /studio-docs:writer analyze <参考文档> 造写作专家 25′ 四维填满的 writer
2 /studio-docs:blueprint list 看内置蓝图，选一本 10′ 选定文档类型
3 /studio-docs:generate <类型> <域> 跑到 plan 确认点停下细看 25′ doc-plan + Gap 清单

三个难点：

  • 造专家优先用“分析参考文档”方式，2–3 页样本即可。没样本就去要——别凭空捏一个文风。
  • plan 确认点要认真看 Gap 清单：标 ❌Manual 的章节就是你缺数据的地方，列进取证清单，别指望写作时圆过去。
  • 关键数字一律引用不重算（B-5）。分节作者各算各的，装配期必然对不上。

十一、⚠️ 九个翻车点（照文档做会撞）

# 坑 以什么为准
1 blueprint / writer 存放路径两说 以 SKILL 为准（3 处一致 vs 1 处）

9 草业项目那份调研 docx python-docx 解析报错（WPS 导出的异常 zip） 改用 pandoc 转，实测可行
