## 一、认领你的命题

### 为什么用真实命题，不用玩具题

> **玩具题练不出 FDE。**

FDE 的难点从来不是"会不会用工具"，是**在信息不全、口径打架、有人反对的真实环境里做判断**。

所以每个命题都带了四样东西：

| 带了什么 | 为什么 |
|---|---|
| 客户背景 | 让你有上下文 |
| **客户原话（模糊意图）** | **要你自己压成结构**——这才是 FDE 的活 |
| 已知约束 | 预算、工期、政策边界 |
| **故意埋的"查不到的项"** | 逼你在第五课练"留占位不编造" |

### 五个命题

| 命题 | 行业 | 交付模式 | 对标启发案例 |
|---|---|---|---|
| **A · 微康养** 县域"助浴+喘息"服务网络 | 康养 | 🟦 **模式二** 平台建设+运营 | 康养项目（🟢 已交付） |
| **B · 园本知识库** 区域幼儿园课程知识库+保教助手 | 教育 | 🟩 **模式一** Token-SaaS | 教育督导项目（🟢 建模+方案） |
| **C · 智慧工作台** 连锁美业门店工作台 | 美业 | 🟩 **模式一** SaaS | 康养项目会员复购飞轮 |
| **D · 标准化种植** 地方特色作物大模型 | 农业 | 🟦 **模式二** 平台建设 | 辣椒 / 草业项目（🟡 方案级） |
| **E · 监管督导** 区级养老机构星级评定督导应用 | 监管 | 🟩 **模式一** SaaS（G 端） | 教育督导项目（换域同构） |

**命题刻意跨了两种交付模式**（模式一：B/C/E；模式二：A/D）。

> 这不是为了公平分配，是为了**逼你们在第六课用对财务语言**：
> 模式二讲 **IRR / 回本周期**，模式一讲 **MRR / LTV:CAC / NRR**。**答反了当场露怯。**

### 🔔 现在就做：写下一句话项目定义

**认领当场写，钉进你们组贯穿工作簿的首页。**

> **格式**：给【谁】做一个【什么】，解决【什么错配 / 痛点】。

**示例（命题 A）**：
> 给**县域失能老人家庭**做一个**"助浴+喘息"上门服务调度与结算网络**，解决**"服务供给散在各机构、家属找不到、补贴走不通"的三方错配**。

这一句在第三课会被打回来重写好几次。**现在写得糙没关系，但必须写下来**——它是后面所有产出的锚。

### 一认到底，不换

**命题一旦认领就不换。** 中途换题的组，等于把前面所有产出作废。

> **这本身就是 FDE 的一课**：需求会变，但项目不会因为你觉得难就换一个。

## 三、工具全景：Astra Studio 九个插件

### 各管一段，产物首尾相接

```
studio-core      工作区管理（init / status / promote / create-expert）    ← 第二课 / 第八课
studio-insight   业务分析六件套（画像/旅程/流程/画布/行为矩阵/机会）      ← 第四课 上半场
studio-planner   规划流水线（事件风暴→域模型→技能设计→骨架→填充）        ← 第四课下 / 第八课
studio-ontology  本体编译（五要素 → 可运行插件）                          ← 第五课
studio-docs      文档交付（蓝图/写作专家/并行写作/装配/导出）             ← 第六课
studio-platform  平台文档套件（脑图/技术设计/项目计划/迎检话术）           ← 第六课
studio-design    设计转代码（截图→.pen→openspec→React）                  ← 第七课
studio-quality   插件校验 + MCP 接线                                     ← 第八课
fund-review      政府采购报价优化 + 财评预审                             ← 第八课 选修
```

**四条依赖关系**：
`planner → core + insight`；`docs / platform / ontology → core`；`insight / quality / design` 零依赖。

### 两个必须现在建立的认知

#### ① 产物即接口：层间契约比工具本身更重要

工具之间**不靠内存传参，靠文件**。`studio/changes/{domain}/` 下每个文件都是上一步的输出、下一步的输入。

三个直接后果（第四课会展开）：

- **随时可中断**——今天跑到域图，明天接着跑
- **每步可单独跑**——不用从头再来
- **可以人工改产物再继续**——模型给的结构不满意，你直接改文件

> **占位符即契约**：你在文档里写了要引用的文件，它就必须存在。
> 这条在第八课有物理落点——**校验器会把"引用了不存在的文件"直接判 failed**。

#### ② 认知到行动 = OAG，不是 RAG

> **OAG ≠ RAG**
> RAG 是"**检索得准一点**"；OAG 是"**越权的结果根本生成不出来**"。
> 防幻觉在**执行层**（本体约束求解），不在检索层。
>
> **LLM proposes, ontology enforces.**

第五课会讲透，并给出物理机制：`guards` / `post_rules` / `HilPolicy` 三道关。

### ⭐ 平台 = 方法论的固化物

第一课讲过：`产出 = 结构化能力 × 平台固化 × 模型算力`。
**这一堆插件就是第二个因子。**

固化发生在三层：

| 层 | 固化了什么 | 例 |
|---|---|---|
| **工具层** | 做事的**步骤顺序** | planner 的 5 步流水线，不用每次想"先干哪个" |
| **结构层** | 产物的**形状** | 每个 skill 的产出路径与章节结构固定，下游能直接消费 |
| **纪律层** | **什么不许做** | 校验器的治理审计、编译红线 |

> **第三层最值钱**：工具能省时间，**纪律能防事故**。
> 而且纪律有个特点——**它在你最想违反的时候生效**。

#### 💡 活证据 · fund-review

政府采购报价优化插件，**首发案例就是学前教育项目**。

一个真实交付里反复做的动作，被沉淀成可复用插件，下个项目直接调用。**第八课会再回收一次。**

#### ⚠️ 但固化也有反面（预告）

模板可以复用，**数字不可以**。

辣椒和草业项目两份调研件是同一个模板换领域填的——结尾整段逐字相同，连"关系数 40万/200万/500万+"都一样。草业项目那三个数挂在客户 30 年真实积累上、**有主**；辣椒同样这三个数**无主**，是模板带过来的。

> 这是**反例 B-11**，第三课深讲。今天只需要记住一句：
> **固化提问结构是对的，固化答案是灾难。**

## 五、⚠️ 四个翻车点（全部是实测踩出来的）

### 1. 装完当前会话看不到新 skill —— 最真实的翻车点

**现象**：`plugin install` 明确回报成功，但技能列表里就是没有 `/studio-ontology:*`。

**原因**：**插件在会话启动时加载，装完不会热更新。**

**后果**：你会判定"装失败了"，然后反复卸载重装，**浪费十分钟还越搞越乱**。

**正确处置**：**重启 Claude Code**，重启后逐个确认命令可见。

> **别重装。重装解决不了这个问题，因为它根本没装失败。**

### 2. 不跑 `marketplace update` 就装不到 studio-ontology

studio-ontology 是**后加进 marketplace** 的，旧快照里根本没有它。

update 时会打印 `Found stale directory, cleaning up and re-cloning…`——**这是正常行为，不是报错**，别慌。

### 3. 升级不能靠重装

改版后必须 `marketplace update` + `plugin update`；**再跑一次 `install` 无效**。

兜底：

```bash
claude plugin install --force
```

### 4. ✅ 两个仓库 URL 都能用（曾以为是坑，已澄清）

`Ameng2001` 与 `VanLengs` 两个 URL，`git ls-remote` 指向**同一个 commit**——同一仓库改名后 GitHub 自动重定向。

**手册统一用 `VanLengs`。看到另一个也别慌，不是两个仓库。**

### 参考答案 · 交付模式怎么判

这是本课唯一有"标准答案"的判断题，第六课要用：

| 问自己 | 模式一（Token-SaaS） | 模式二（平台建设 + 运营） |
|---|---|---|
| **卖的是什么？** | 一个能跑的 agent 应用 | 一套平台 + 一门生意 |
| **怎么收钱？** | 按 token / 调用 / 席位 | 投建运 + 运营盘 + 多元收入 |
| **有没有运营盘？** | ❌ 没有 | ✅ 有（站点、会员、政府购买…） |
| **要不要写可研？** | 通常不要 | **必须** |
| **财务语言** | MRR · LTV:CAC · NRR | **IRR · 回本周期 · NPV** |
| **HIL 命门在哪** | 应用内的裁定 / 质检闸 | 增收闸 + 监管发布闸 + 凭证闸 |

**判反了的典型后果**：命题 C（美业工作台，模式一）的组，照着可研蓝图硬写 IRR——**写出来就是四不像**，评审一眼看穿。

## 七、带着这个问题进第三课

**你写的那句话项目定义，客户会同意吗？**

第三课第一件事就是把它打回来重写。不是因为你写得差，而是因为：

> **你现在写的是"你以为客户要什么"，不是"客户说了什么"。**
> 这两者之间的距离，就是第三课要教的东西。
