这一课在收什么口

前七课收的是手艺——装环境、采信息、萃认知、切域、建本体、设闸、写文书、做原型。

这一课收的是另一样东西：能不能把手艺交给你。

段 时长 做什么 收的口

七 · 定级 20′ 发能力等级 + 差距清单 不发合格证

⚠️ 开场就要知道的三条硬口径

  1. C1–C6 可训练，C7（客户关系 / 责任承担 / 价值判断 / 政治敏感度）只能筛选。
  2. 结课不发合格证，发能力等级 + 差距清单。
  3. ⑫ 可发版插件是加分项——做到通过校验即算达成，做不完不扣分。 评审看的是“说得出本组哪个动作值得沉淀成插件”，不是插件本身。

能力等级分三档：Lv.1 见习 / Lv.2 胜任 / Lv.3 主理。

⚠️ 编号消歧：能力等级写 Lv.1 / Lv.2 / Lv.3，与课程编号 第一课到第八课是两回事。 旧课件里若写作 “L1/L2/L3”，指的是水平，不是第几课。

多数人第一次会停在 Lv.1 见习——这是正常的，装作 Lv.2 才是危险的。

课程验收标准的原话：独立承接中等复杂度 To-G/To-B 项目认知侧全链条， “且知道自己在哪里必须叫人”。

一、能力沉淀

本节形式：讲解 + 讲师演示，各组不动手。 动手部分（跑通四步、故意制造 failed、手动 commit）是课后自选，对应交付包 ⑫ 加分项。

1.1 前七课做的是这一个项目，这一节做的是下一个项目

一个真实交付里反复做的动作，被沉淀成可复用插件，下个项目直接调用—— 这就是“平台=方法论固化物”从口号变成文件的那一刻。

三层固化回收（走完八课才集齐）

第二课讲过三层，那时它还是三个抽象名词。走完八课后回来看，每一层都有了具体落点：

层 固化了什么 在哪见到的
工具层 做事的步骤顺序 第四课的 5 步流水线、第六课的 plan→write→assemble
结构层 产物的形状 七段 IR、蓝图 structure、skill-map 的 H2、SKILL.md 的 6 个 H2
纪律层 什么不许做 第五课的 CI 红线执法、第六课的编号权归装配、本课的校验器 + “不做清单”

第三层最值钱：工具能省时间，纪律能防事故。 而且纪律有个特点：它在你最想违反的时候生效——凌晨三点赶工期时，你不会守纪律，但校验器会。

⭐ 固化三问（本节唯一要带走的心智模型）

任何一条你反复叮嘱新人的纪律，都问它三个问题—— 能不能固化？固化成什么？谁来跑？

档 例子 固化成什么 谁来跑 人力成本
全固化 “跨域不许越界写” A 结构校验器 编译期自动 零人力，永不疲劳
全固化 “SKILL.md 引用的脚本必须存在” validate_skills.py /studio-quality:validate 零人力
半固化 “关键数字锚在单点、不重算” BRIEF 单点 + 装配期一致检查 工具跑，人复核 FDE 走一道人肉闸
半固化 “SDK 能力不确定就挂账” docstring 显式挂账约定 人肉跑 FDE 走一道人肉闸
未固化 只活在你脑子里的那条 无 全靠自觉 请假即崩

纪律的固化程度，决定了它需要多少人力持续维护。 评估一个平台成不成熟，就看它把你多少条纪律固化进了校验器。

康养项目能做到 1 名 FDE + 智能体编队顶掉传统 5+ 人 / 数周，不是因为手快， 是因为绝大部分一致性纪律被搬进了编译期和装配期。

1.2 四步链路

（承接第四课的 skill-map.md）
  ↓
/studio-planner:spec-generate <plugin>   ← 零确认点，纯自动
  ↓  phase: planning → building
/studio-planner:build-skills  <plugin>   ← phase 必须 == building
  ↓  skill: draft → building → built
/studio-quality:validate <target_dir>    ← 三组脚本校验
  ↓  phase: building → approved   (skill: built → tested)
/studio-core:promote <plugin>            ← 发版 + 归档
  ↓  归档副本 phase=shipped；活动区重置 planning、iteration+1

顺带一步（有 MCP 需求时）：/studio-quality:wire-mcp → 生成 .mcp.json。 它是“给你做的插件配 MCP”，不是“给 studio 自己装 MCP”。

① spec-generate——唯一零确认点的一步

  • 前置：skill-map.md 必需（缺则打回第四课）
  • 产物严格分家：studio/changes/{plugin}/ 收 brief.md + plugin.json.draft + status.json；{target_dir}/ 收 skills/{skill}/SKILL.md 骨架 + commands/{skill}.md
  • SKILL.md 骨架的 6 个 H2：## Intent · ## Expected Inputs · ## Expected Outputs · ## Preconditions · ## Workflow · ## Out of Scope
  • traits 在这里兑现（第四课选的开关现在看到结果）： stateful → 多一个 init-workspace skill + 两个 runtime 模板； hil-gated → 在 ## Out of Scope 之前插入 ## Approval Gate（固定三选一：✅确认 / ✏️修改 / ❌拒绝）； multi-pipeline → 每条流水线一个命令；expert-scoped → 生成 agents/
  • 失败处理全是“不覆盖 + 打警告”，最重要的一条： 本轮 skill-map 未列出的 skill，不得创建、不得删除、不得重写。

这条纪律值得单记：工具不会“顺手帮你清理”没在计划里的东西。 边界之外一律不动——这正是可预测性的来源。

⚠️ 注意区分两个 HIL：这里的 hil-gated 是 skill 层的审批段（人在对话里点确认）； 第五课的 HilPolicy 是 Action 层的副作用闸（引擎冻结 effects 等人审）。 一个在交互层，一个在执行层。同一件事的两层落点，别混。

② build-skills——初稿不是成品

  • 硬门：phase 必须 == building，否则直接报错退出
  • 它做什么：不新建设计文档，就地改写 SKILL.md，把骨架填成能跑的初稿
  • 期望管理：“scaffolding with substance”，有内容的脚手架，初稿不是成品，要用 2–3 个真实场景测试后再迭代。需要迭代不是构建失败。
  • 失败模式：单个 skill 构建失败 → 该 skill 保持 draft 或标 building-failed；phase 一律保持 building，绝不自动进入 validation

这个设计要记住：工具不会自己给自己发合格证。 从 building 到 approved 必须过校验器那一关。

1.3 ⭐ 校验器查什么——“什么叫做完了”的操作定义

/studio-quality:validate <插件目录路径>

三个 Python 脚本。这张清单就是“什么叫做完了”的操作定义——动手可以不做，这张清单必须过一遍。

A. 结构（7 类）

检查 不过的后果
.claude-plugin/plugin.json 存在（找不到退而找 plugin.json.draft） 都没有 → failed；用 draft 会产生 warning：“这是开发工作区，不是最终插件”
JSON 可解析 failed
必填 name / version / description 非空 failed
name 匹配 ^[a-z][a-z0-9-]*$ failed
name == 目录名 warning（不是 failed）
version 匹配 ^\d+\.\d+\.\d+ failed
声明的 skills/commands/hooks/mcpServers 路径能 resolve failed

B. 技能（逐 skill 9 类）

检查 说明
skills/ 存在、每个子目录有 SKILL.md failed
行数 ≤ 500 超出 = warning（含实际行数）
frontmatter 可解析、name 存在 failed
description ≤ 1024 字符 超出 = failed
name == 目录名 warning
未知 frontmatter key warning。白名单只有 7 个：name, description, allowed-tools, user-invocable, disabled, trigger, model——注意 argument-hint 之类都会被判 unknown
正文引用的 scripts/xxx.py、references/xxx.md 必须真实存在 failed；例外：引用前 50 字符内出现 ${CLAUDE_SKILL_DIR} 则跳过

⭐ 最后这条是 B-3（图片路径断裂）的同类机制：占位符即契约—— 你在文档里写了要引用的文件，它就必须存在。

康养项目当年是 docx 导出丢图，这里是校验器直接判 failed。同一条纪律，两个场景。

C. 依赖（3 组）

.mcp.json（每个 server 必须有 command，重名 failed）· hooks.json（事件名白名单 6 个：SessionStart, SessionEnd, PreToolUse, PostToolUse, Notification, Stop）· dependencies[]（找不到 = warning）

报告

文件：{plugin-dir}/.validation-report.json，verdict 只有 PASS / FAIL 两值，warning 不影响 verdict。

⚠️ SKILL.md 的示例用 ✅/⚠️ emoji，实际脚本输出的是纯文本 PASS/WARN/FAIL。以脚本为准。

⏸ 唯一确认点：通过后问你要不要更新 status.json。同意则 skill built → tested、phase → approved。 规则是“只前进不倒退”。

校验器替你守纪律：两个真实的“想抄近道”

这两条不是设想出来的教学案例，是康养项目编译期真实发生的冲动与存疑。 它们证明的是：训练有素的 FDE 也会想抄近道，靠自觉挡不住。

B-8 越域写入冲动 B-9 SDK 能力想当然
冲动是什么 让一个 Action 直接写别的域的对象（一步到位，省事） 某两个符号到底导没导出，不确定但“应该支持吧”
谁挡住了它 A 结构校验器——越域写过不了校验，当场报悬空/越界 没人挡——校验器管不到运行时符号导出
最终处置 跨域发布全部写成注释和 ref，不越界 7 域统一在 docstring 里显式挂账
结果 7/7 零悬空引用 存疑白纸黑字留在代码里，不被遗忘
档位 全固化 半固化

⭐ B-8 的教学点：7/7 零悬空不是因为我们 7 次都自觉，是因为校验器不给我们自觉的机会。

⭐ B-9 的教学点：平台会告诉你它保证什么，也会暴露它不保证什么。 成熟的 FDE 要能读懂平台校验的边界，在校验器覆盖不到的地方，用 docstring 手动补一道“诚实闸”。

1.4 promote 的「不做清单」

6 条硬前置：① status.json 存在 ② phase == approved ③ 能拿到 target_dir ④ 目标目录存在且有 SKILL.md ⑤ 所有在范围内的 skill 状态为 tested ⑥ 目标目录非空

版本推进：已有 manifest → patch +1；命令行给了显式版本 → 用它；无 manifest → 用 draft 的版本

归档：studio/archive/{plugin}/{日期}-iteration-{N}/。是 copy 不是 move——活动工作区保留。 归档副本 phase=shipped；活动副本 iteration+1、phase 重置为 planning。

⭐ promote 明确不做的事（这张“不做”清单比“做”更值得记）

不拷贝实现文件 · 不 git add/commit · 不删实现文件 · 不跑校验 · 不删活动工作区 · 不把 promote 当终态

为什么不自动 commit：因为提交是人的决定。 工具把状态推进到位，但“我认可这个版本”这句话必须由人说出口。

顺带：git diff studio/ 是唯一的迭代历史来源——这也是第二课强调 studio/ 必须 git-tracked 的原因。

这张清单和校验器是一对： 校验器管“什么叫做完了”，不做清单管“做完了也不等于我认了”。 机器判 PASS，人签字发版。

1.5 💡 活证据 · fund-review：项目反向沉淀出插件

Plugins/fund-review-plugins/ —— 政府 IT 采购报价优化 + 财评预审插件。

它的来历：首发案例就是学前教育项目。 它的形态：4 个 skill（init-session / quote-optimize / quote-rewrite / quote-review）+ 2 个 agent + 两轮迭代存档

⚠️ 诚实标注：该仓 README 明写“插件实现已迁出本仓库”，实现源在 marketplace，本仓只留设计文档与客户数据。

⭐ 这就是本节的意义：

某工业城市项目要做报价优化和财评预审 → 做的过程中发现这套动作每个 To-G 项目都要来一遍 → 沉淀成插件 → 下一个项目直接 claude plugin install fund-review。

从“我做过这件事”到“我们组织有这个能力”，中间隔的就是这一步。

这是活证据，不是设想：插件不是先设计出来再找场景， 是真实项目做着做着发现“这个动作还会再做一遍”，反向沉淀出来的。

1.6 🔔 现在回答：你们哪个动作值得沉淀成插件？

本节唯一要你交付的动作（口头）。

问题：“你们这五天做的动作，哪一个值得沉淀成插件？” 追问：它是“下个项目还会再做一遍”的动作吗？还是只有你们这个命题才有？

答得好的形态： > “我们命题里反复在做’把地方标准解码成可校验的规则条目’——A 组做康养要做，E 组做督导也要做，换个客户还得做一遍。这个值得沉淀成 standard-decode 插件。”

答得不好的形态： > “我们想做一个把我们这次的域图导出成 PPT 的插件。”——这是一次性动作，不是反复动作。

判据 值得沉淀 不值得
频次 下个项目还会再做一遍 只这一次
边界 输入输出说得清、能写成 ## Expected Inputs/Outputs 说不清什么进什么出
判断含量 判断在人，重复劳动在工具 判断也想交给工具（→ 交不了）

为做插件而做插件，拿不到这个加分。

二、OPC 边界回收

呼应第一课的“一人公司 OPC”那一段：那时是概念，现在你自己走了七课，可以把线画在自己的命题上了。 这一节不鼓吹一人万能，只画那条线。

2.1 一人公司成立——这件事已经证过了，不再花时间证

康养项目实证：1 名 FDE + 智能体编队完成 102 业务事件 → 7 域限界上下文 → 3835 行插件骨架 + 21 个 YAML → 11 章可研；传统模式是 5+ 人 / 数周。

所以本节不讲“能不能一个人干完”，只讲“边界在哪”。

2.2 可替侧：智能体替你放大了什么

可替的活 康养项目落点
① 认知萃取的加速 102 事件 → 16 簇 → 7 画像 / 7 旅程 / 5 流程（人来判断归类，模型来跑整理）
② 建模骨架的生成 五要素 76/75/38/47/54；3835 行 + 21 YAML，7/7 py_compile
③ 并行写作 1 份 BRIEF 口径 → 35 节并行 → 装配 → 质检 → 约 11 万字

⭐ 三类活的共同点：判断标准清晰 · 错了可回退 · 不牵扯对外承诺。 记住它，因为下一节三条全反过来。

模型替你做完，不替你做主。

2.3 ⭐ 必须人扛侧：C7 四项，智能体接不了

不是“现在接不好、以后会好”，是结构上接不了。

C7 项 康养项目铁证 为什么接不了
客户关系 + 政治敏感度 11 处 citations 占位（7 处本地文号 + 4 处企业 SOP），全部留空转逐项取件清单 这些东西公开渠道查不到——只在某个科室的文件柜里。智能体没有身份、没有关系、进不了门。 原话：“错文号比空缺更有害。”
价值判断 站长 HIL 增收闸的置信度阈值 0.75 定 0.7 还是 0.8，差一点就是“橡皮图章”和“闸门形同虚设”的区别。模型能给分布、给历史误差，那个阈值是人对“我愿意为速度冒多大错误风险”的表态。
责任承担 脱敏纪律 + 对外一律写“赋能优化”而非“替代”的表述红线 智能体会顺着 prompt 把话说满。守红线的是人，因为承担说错话后果的是人。署名的是你，不是模型。

一句话收口： 智能体没有身份（进不了机关的门）、没有立场（拍不了 0.75）、不承担后果（守不了红线）。 边界之内，你用智能体把自己放大成五个人；边界之外，你就是一个人，而且必须是你。

2.4 边界判据三问

① 需要一个身份才能做吗？  → 客户关系 / 政治敏感度
② 需要一个立场才能拍吗？  → 价值判断
③ 做错了谁签字？          → 责任承担

任一答案指向"人" ⇒ 在必须人扛侧

验一遍：11 处文号（要能进机关门的身份）· 0.75 阈值（要愿为速度担多大错的立场）· 脱敏红线（做错了 FDE 签字）→ 全在人扛侧。 反过来：102 事件整理 / 7 域骨架生成 / 35 节并行写作 → 三问皆“否”，稳稳在可替侧。

边界会移动，但移动的是可替侧的宽度，不是必须人扛侧的存在。

2.5 🔔 现场自问（路演前）

你清单里“必须人扛”的条目，有几条其实是你懒得让智能体做、误判成人扛的？ 反过来，有几条你标了“可替”、但其实藏着一个身份 / 立场 / 签字问题？

收口：边界最常见的错误不是划错侧，是把偷懒当边界。

三、C-Life 怎么落地

前面所有课回答“FDE 是什么、怎么做、什么人能做”； 这一节只回答一个问题：下周一，谁做什么。

3.1 第一步不是找试点，是抽模板

试点已经跑完了，就是康养项目。

常规路径：设想 → 找试点 → 跑一年 → 才有样本 我们的路径：样本已在手（康养项目）→ 抽模板 → 直接复制到第 2 个项目 省掉的是最贵的一年。

模板是现成的产物：SOP · BRIEF 骨架 · 7 域本体范式 · HIL 设点判据 · citations 治理清单。

⚠️ 但要同时记住反面： “这不是一次侥幸，但它目前不可复制——因为方法在一个人脑子里，不在组织里。”

康养项目提供的是“能做成”的证据，不是“能复制”的证据——后者要靠这 90 天造出来。

战场边界（决定该接什么单）：

战场 FDE 的价值
探索 / 概念验证 / 新项目落地 ✅ 压倒性优势、不可替代——第一天对话、第二天出 Demo
规模化 / 组织推动 / 运维 ❌ 瓶颈在人、在组织，不是工具

3.2 六步路线图（有依赖顺序，不能跳）

选人 → 训练 → 平台 → 试点 → 度量 → 规模化
步 做什么 过关判据
① 选人 按能力锚筛：C1–C6 看能不能补，C7 看是不是这块料 1 名 Lv.3 + 2–3 名 Lv.1 + 1–2 名平台组到位（人头签字）
② 训练 不是上课，是在康养项目模板上过手——Lv.1 挑 1 个康养项目域重走一遍 每名 Lv.1 独立走完 1 个域并通过结构校验（零悬空）
③ 平台 把管线从“康养项目能用”固化到“换个项目也能用” 管线跑通一个非康养项目 mini 样例
④ 试点 拿一个新的中等复杂度项目，Lv.3 带 Lv.1 用模板+平台走一遍 第 2 项目事件集 + 首域 ontology-map 出仓
⑤ 度量 三个硬指标量“我们到底行不行” 三指标全部有基线读数
⑥ 规模化 达标才并联第 3、第 4 个项目 三指标达康养项目基线 + Lv.1 里有人升 Lv.2

选人错了，后面全白搭——因为 C7 筛不出来的话， 你训练的是一个永远不敢对客户说不知道的人。

3.3 90 天计划：三阶段，认领到人

阶段 天数 主要动作 里程碑 度量
一：选人 + 抽模板 0–30 筛 1 Lv.3 + 2–3 Lv.1 + 1–2 平台组；把康养项目交付逆向拆成模板包 M1 编队到位（人头签字） / M2 模板包 v1 出仓 C7 筛选通过率；模板覆盖 7 域比例（目标 7/7）
二：训练 + 固化平台 31–60 每名 Lv.1 独立重走 1 个域，对标已交付版；平台组固化管线 M3 每名 Lv.1 交一个域并过结构校验 / M4 管线跑通非康养项目样例 首个 Lv.1 独立交付一域周期（目标 ≤ 10 个工作日）
三：试点启动 + 度量 61–90 选定第 2 个真实项目启动前端认知萃取；建三指标看板 M5 第 2 项目事件集 + 首域出仓 / M6 度量看板上线 三大硬指标全部有基线读数

三条硬约束：

  1. M1 到人头签字——不是“物色中”，是“谁，确定了”
  2. 阶段二必须对标康养项目已交付版——有标准答案的训练才叫训练，否则是自嗨
  3. 阶段三只启动不完成——90 天目标是“第 2 项目跑起来且有度量”，不是交付完

3.4 度量：三个硬指标，不达标不规模化

指标 量什么 目标 康养项目锚
① 首个 FDE 独立交付一个域的周期 效率 ≤ 10 个工作日，且一期比一期短 对标“7 域同日并行编译”
② 交付物一次通过率 质量 逐期上升，规模化前稳定达标 正面 7/7 py_compile、7/7 零悬空；反面 B-1 / B-2 / B-6
③ HIL 设点覆盖率 风控 涉钱 / 涉合规 / 不可逆 / 跨组织 Action 全覆盖 54 Action 设 26 个 HIL 点

三个都达康养项目基线，才允许开第 3 个项目。 指标三最难，也最不能漏：漏一个涉钱 Action 的闸，可能就是一次赔付或一次违规。

3.5 规模化的前提与两条红线

前提：不是“招更多人”，是“第 2 项目三指标达康养项目基线 + Lv.1 里有人升到 Lv.2”。 且每个新项目必须有一个 C7 过关的 Lv.3 压阵——因为 C7 只能筛不能训。

红线一：不许跳过度量直接铺量。 老板说“康养项目都成了，赶紧复制十个”——这时候你要顶住。指标没达基线的复制，是把一次侥幸当成能力。

红线二：不许让平台组缺位去省成本。 没有平台组，Lv.3 退化成“更累的架构师”，单点或许能扛，规模化必崩。

规模化后 B-10 会被放大：单个项目里 Lv.3 靠 C7 顶住了 11 处占位； 但每个项目都有它自己的 B-10，而你只有一个 C7 过关的人—— 没有第二个敢留白的人，第二个项目的 B-10 就会被一个 Lv.1 用假文号填上。

落地的本质：把康养项目那个 Lv.3 脑子里“靠人品和经验兜住的东西”， 变成组织层面的红线、度量和平台约束——让第 N 个项目不必再靠“又碰到一个好 Lv.3”的运气。

3.6 团队编成随交付模式变（→ 交付包第 ⑩ 件）

模式一（Token-SaaS） 模式二（平台建设 + 运营）
编成 轻：1 FDE + 平台/运行时组 重：1 主理（Lv.3）+ N 见习（Lv.1）+ 平台组
FDE 吃重 认知快 + 设闸 + 产品化；文书轻 全链，尤重合规 / 可研 / 商业建模
半径要求 快跑快迭代 商业与合规半径宽得多

三个角色各自提供什么（这句是编成的本质）： Lv.3 提供判断和责任（C7 + 高阶 C1–C6），Lv.1 提供手数和成长通道，平台组提供杠杆。三者缺一，康养项目都不可复制。

平台组不是 FDE，是让 FDE 不必“更累”的人。没有平台组，Lv.3 就退化成一个更累的架构师。

⚠️ 一句冷水：能做模式二的大平台，不代表你能做模式一的 SaaS 应用，反之更是。 真正的分水岭是 C1 认知萃取的跨行业迁移力——换个你不熟的行业，沉淀归零、只剩方法，你还压得出可归域的结构吗？ 这就是 Lv.2 和 Lv.3 的分界。

交付包第 ⑩ 件就写这个：别只写“1 主理 + N 见习”六个字，要写清：谁是 Lv.3、每个 Lv.1 各认领哪个环节、平台组维护什么。

路演前自查，缺件当场标注。

11 件（应交）： ① 项目定义 + 交付模式判定 ② 事件集→画像→旅程→10 热点 ③ 限界上下文域图 ④ 五要素本体草案 ⑤ 商业模式画布 + 财务语言 ⑥ 交付 SOP 七阶段 ⑦ HIL 设点表 ⑧ citations 取证清单（含留占位）⑨ 一节方案稿 + 一张图占位 ⑩ 团队编成 + 90 天计划 ⑪ 产品 demo 原型（诚实标 Mock、非模型跑通）

⑫ 可发版插件 v0.1 —— 加分项，做不完不扣分。

口径一致性自查三条（拼包时逐条对）

  1. 同一个数字在 ⑤ 和 ⑨ 里是不是同一个数——不同就是 B-5 同类（重算漂移）
  2. ⑧ 的占位条目，在 ⑨ 的正文里是不是也保持占位——文号不许在方案稿里“顺手补上”
  3. ⑪ 的 Mock 清单，和 ⑨ 里对能力的描述是不是一致——方案写“已实现”、demo 是 Mock，就是第三条警示

⚠️ 缺件怎么办：照实标“缺”，不许现场补造。 这本身就是一次 B-10 演练——空缺可以补，编造无法挽回。

七、结课定级

三级能力锚

级 判据
Lv.1 见习 能在 FDE 指导下承接单一环节
Lv.2 胜任 能独立完成认知侧全链条，交付物需一次复核
Lv.3 主理 能主持项目、设 HIL 闸、对客户承诺负责，并能带 Lv.1

两条硬口径：

① C1–C6 可训练，C7 只能筛选。 这八课教的全是 C1–C6。C7 教不了——但这八课走一遍，能照出你在 C7 上缺什么。

② 多数人第一次会停在 Lv.1，这是正常的，装作 Lv.2 才是危险的。

C7 的锚点，全在这门课里出现过：

  • 客户关系 / 政治敏感度 → 康养项目 11 处地方文号查不到，坚决留占位不编造
  • 价值判断 → 站长 HIL 的 0.75 置信度阈值：不是算出来的，是权衡出来的
  • 责任承担 → 对外一律写“赋能优化”而非“替代”——因为承担说错话后果的是人

定级怎么定

不发合格证，发两样东西：

① 能力等级（Lv.1 见习 / Lv.2 胜任 / Lv.3 主理）
② 差距清单（逐维写：C几、差什么、下一个项目怎么补）

定级参考：

观察点 指向 Lv.1 指向 Lv.2 指向 Lv.3
全链独立性 只在别人带的环节里做对 八课能自己走完一遍，产物需复核 能带别人走，且能判别人做得对不对
C3 设闸 说得出某 Action 该不该设闸 能给全链设出 5–8 个真闸 对任一 Action 判“设不设、谁按、按错代价”
C4 诚实边界 知道要留占位 产出可交现场的待补取证清单 在客户压力下仍然留白不编造
C7 客户承诺 不涉及 不独立对客户承诺 对客户承诺负责，签字的是他
路演表现 靠队友兜 自己讲得清全链 被追问三问仍答得住

⚠️ Lv.3 不能自封： 举不出“我在客户压力下真做过留白不编造”这个例子的人，不该给自己填 Lv.3。

康养项目那 11 处占位，就是 Lv.3 的资格证。

姓名 / 组：
本次定级：Lv.__

我最弱的一维是 C__，具体表现是：
（写一个这五天里的具体时刻，不写形容词）

附 · 一页纸速查

固化三问：能不能固化？固化成什么？谁来跑？ 纪律的固化程度，决定了它需要多少人力持续维护。

工具不会自己给自己发合格证：从 building 到 approved 必须过校验器。

promote 的“不做清单”：不 commit。机器判 PASS，人签字发版。

值得沉淀的判据：频次（还会再做）· 边界（说得清输入输出）· 判断含量（判断在人，重复劳动在工具）

边界三问：要身份吗？要立场吗？谁签字？任一指向“人”，就在人扛侧。

边界最常见的错误不是划错侧，是把偷懒当边界。

三条一票警示 = 一条：空缺可以补，编造无法挽回。

不发合格证，发能力等级 + 差距清单。装作 Lv.2 才是危险的。
