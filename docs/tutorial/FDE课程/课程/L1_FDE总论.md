## 一、交付断层：东西掉在接缝上

### 先问你自己一个问题

**你上一个项目，客户最后拿到手的东西，和他当初嘴里说的那个东西，是同一个东西吗？**

大概率不是。中间掉了很多。

掉在哪儿了？**不是掉在某个人不认真，是掉在接缝上。**

需求的人把话交给设计的人，设计的人把图交给开发的人，开发的人把包交给交付的人——每交一次手，都有一部分**只在上一个人脑子里、没写进文档**的东西，永久丢失。

这个丢失点，我们叫它**交付断层**。

> **客户要的是结果，组织给的是工序。**
> 客户要的是"我的老人能被照顾好"；组织给的是需求→设计→开发→测试→交付这一串工序。

断层不是 bug，是工序制的**结构性产物**。只要你把一件事切成四段交给四拨人，断层就一定存在，**跟态度无关**。

### 为什么"文档写细一点"补不上

这是学员第一反应最常提的方案，也是最先要打消的。三条根因，每一条都堵死了这条路：

| # | 根因 | 具体表现 |
|---|---|---|
| ① | **意图无法完全文档化** | 客户说"我要一个能帮站长管好老人的系统"，这句话背后有 **102 件**他没说出口的具体业务事件。你写需求文档时凭经验补了 60 件，剩下 42 件你没意识到，下游更不可能知道 |
| ② | **每道工序都会做本位优化** | 开发拿到设计图，会为了"好实现"悄悄改口径；设计拿到需求，会为了"好画"裁掉边角。每次优化都是**局部最优，叠起来就偏离了客户那个"结果"** |
| ③ | **返工的账没人认** | 断层导致的返工发生在下游，根子在上游的接缝。组织里没有一个人为整条链的保真度负责——因为**没有一个人看得见整条链** |

### FDE 消除断层的机制，只有一句话

> **把需要跨四个人接力的判断链，压进一个人的头脑里连续走完。**

需求他做、建模他做、方案他做、交付物他做——**不是他很能干什么都会，而是这条链本来就不该切开**。切开的每一刀，都是为了适配"组织按工种分人"这件事，而不是为了把活干好。

康养项目那条链长这样：

```
102 事件 → 16 簇 → 7 画像 → 7 旅程 → 5 流程 → 10 热点 → 7 域 D1–D7
```

**每一步都是判断，不是搬运。** 换个人接手第二步，他不知道第一步为什么这么归类，只能重新判断——断层就是这么产生的。

那智能体是什么角色？

> **智能体是这一个人的手脚，不是接力赛里的另一棒。**

他用智能体把 102 个事件快速铺开、把 7 个域并行编译、把 35 节报告并行起草——**但判断始终在他一个人这里**。

### ⚠️ 一个必须现在就掐掉的误读：贯通 ≠ 求全

"一个人贯通全链"**不等于**"一个人把每件事都做到最全"。

**求全，本身就是断层的另一种表现**——它是"你没搞清客户真正要的结果"导致的过度建模。

> **【真实反例 B-7 · 旅程建模过重】**
> 康养项目长者旅程初版做的是**"夜间急救"**。场景很戏剧、很打动人——但**过重且偏离营收主线**，最后返工改成会员飞轮。
>
> **教训**：建模要服务于业务优先级，不是求全。**返工成本要记在方法论账上**，不是记在"那次运气不好"账上。

## 二、FDE = 一人公司（OPC），但边界比能力半径更重要

### 术语先锁死

我们说 **OPC（One-Person Company，一人公司）**，**不说"超级个体"，也不说"全能工程师"**。

因为后两个词把重点放在"这个人多牛"，而 OPC 的重点是——**这个交付单元的边界在哪、谁负责**。

康养项目已经证明了"一人公司成立"这件事。所以这一课**不花时间证明它成立，花时间讲它的边界**。

### 可替侧：智能体到底替你放大了什么

三类活可以交给智能体大幅加速。记住是**加速**，不是**替代判断**——模型替你做完，不替你做主。

| 可交给智能体（对应 **C1–C6**） | 具体例子 |
|---|---|
| **认知萃取的加速** | 判断在你脑子里，但落成结构化文本、补齐要素、交叉对齐，智能体比你快十倍。102 事件压成 16 簇，人来判断归类，模型来跑那一遍遍的整理 |
| **建模骨架的生成** | 7 个域的五要素（Object 76 / Link 75 / Function 38 / Rule 47 / Action 54），一个字一个字敲，一个人敲不完。管线把骨架生成出来，**7/7 py_compile 通过、3835 行 Python + 21 个 YAML** |
| **并行写作** | 11 万字可研，顺序写要写到天荒地老。锚定一份口径文件，拉起 **35 节并行**、装配、质检 |

**这三类活的共同点**：判断标准清晰、**错了可回退**、不牵扯对外承诺。

记住这个共同点——因为下面讲的"必须人扛侧"，**恰好三条全反过来**。

### 必须人扛侧：C7 四项，智能体结构上接不了

不是"现在接不好、以后会好"，是**结构上接不了**。

| C7 四项 | 为什么接不了 |
|---|---|
| **客户关系** | 谁在会上不说话但会否决 |
| **责任承担** | 这个数字错了谁签字 |
| **价值判断** | 这个季度先啃哪块硬骨头 |
| **政治敏感度** | 说"替代"还是说"赋能优化" |

下面三个例子来自康养项目，一个对应一项。看完你就懂"接不了"是什么意思。

#### 例一 · 客户关系 & 政治敏感度 → 11 处文号，查不到也不能编

康养项目可研里有 11 处要挂本地依据：**7 处本地文号**（本地 DIP 细则、助餐补贴办法这类，标 `[本地待补文号]`）+ **4 处企业 SOP 编号**（标 `[企业标准,FDE 补编号]`）。

这些东西**公开渠道查不到**——不在国务院令里，不在 GB 里，**只在某市医保局、民政局、政数局某个科室的文件柜里**。

智能体面对这种情况只有两个选择：**编一个像模像样的文号**（灾难），或者**留空**。

我们留空。转成一份逐项取件清单，让人拿着去机关一个一个要。

> **这一步是纯人的活：你得认识那个人、进得了那个门、说得上话。**
> 智能体没有身份、没有关系、**进不了门**。
>
> 内部原话：**"错文号比空缺更有害。"**

#### 例二 · 价值判断 → 站长 HIL 的 0.75 阈值，谁来拍

康养项目设了 **26 个 HIL（人在环）闸门**，其中站长 HIL（增收闸）挂了一个**置信度闸，阈值占位 0.75，待定**。

这个 0.75 是什么？是"智能体对一个增收动作有多少把握时，才允许它直接推给站长执行；多少把握以下必须人复核"。

定 0.7 还是 0.8，差一点，就是"橡皮图章"和"闸门形同虚设"的区别，背后是真金白银和信任。

> **没有任何模型能替你定这个数**——它不是算出来的，是**权衡**出来的：
> 你要权衡站长被打扰的频率、错误增收的代价、系统被信任的速度。
>
> 模型能给你分布、给你历史误差，**但那个阈值是人对"我愿意为速度冒多大错误风险"的表态。**

#### 例三 · 责任承担 → 脱敏纪律与表述红线

康养项目对外一律写**"赋能优化"而不是"替代"**——因为"AI 替代人"这个表述在 To-G 场景里是**政治事故**。

这条红线智能体不会主动守，它会顺着你的 prompt 把话说满。

守红线的是人，因为**承担说错话后果的是人**。一人公司里，对客户承诺、对政府表态、对合规兜底，**署名的是你，不是模型**。

**责任不可外包给一个不承担后果的东西。**

### ⭐ 边界判据三问（这个比记清单管用）

有人会说：文号将来能爬到、阈值将来能自动调、红线将来能写进 system prompt——**边界会不会移动？**

会移动。但移动的是**可替侧的宽度**，不是**必须人扛侧的存在**。

拿任何一件活来问这三个问题：

1. **这件事需要一个身份才能做吗？**
2. **这件事需要一个立场才能拍吗？**
3. **这件事做错了谁签字？**

**只要有一个答案指向"人"，这活就在必须人扛侧。**

对照一下：

| 活 | 需要身份？ | 需要立场？ | 谁签字？ | 判定 |
|---|---|---|---|---|
| 11 处文号取件 | ✅ 要能进机关门 | — | — | **人扛侧** |
| 0.75 阈值 | — | ✅ 愿为速度担多大错 | — | **人扛侧** |
| 脱敏红线 | — | — | ✅ FDE 签字 | **人扛侧** |
| 102 事件整理 | ❌ | ❌ | 错了能回退重跑 | 可替侧 |
| 7 域骨架生成 | ❌ | ❌ | 错了能回退重跑 | 可替侧 |
| 35 节并行写作 | ❌ | ❌ | 错了能回退重跑 | 可替侧 |

> **C1–C6 可训练，C7 只能筛选。** 这句话第八课会再回收一次。
> 一人公司不是让你逞能，是让你**清楚地知道自己什么时候必须叫人**。
>
> 一个只会往前冲、不知道边界的 FDE，**比一个慢一点但知道边界的 FDE 危险得多**——因为前者会在 11 处文号那里编一个出来，会在 0.75 那里随手填个数，会把"替代"写进 To-G 方案。

## 三、认知杠杆：从人月堆叠到杠杆

### 一次真实的实证

同一条交付链——从需求调研到 7 域本体建模、到 3835 行插件骨架、到 100+ 页对客可研：

| | 传统模式 | 本次 |
|---|---|---|
| **人力** | 产品经理 + 架构师 + 行业顾问 + 方案经理 + 美工 = **5+ 人 / 数周** | **1 名 FDE + 智能体编队** |
| **接缝** | 至少 4 道，每道都在漏 | **0** |
| **产出** | — | 7 域本体（3835 行可运行骨架）+ 11 章 / 约 11 万字 / 26 图可研 + 2 份附录 |

这不是"省了 4 个人"这么简单。是**交付的组织形态变了**——从"按工种分人、靠流程串起来"，变成"按认知链分给一个人、靠智能体扩手脚"。

### 交付物的形态也变了

很多人以为 AI 只是让你"写得快"，交付物还是老三样。**错。** 康养项目的交付物是传统模式**根本产不出**的：

**① 方案与代码同源**
传统模式里，可研报告是方案经理写的 Word，跟真正的系统是两张皮。康养项目不是——11 章可研背后是 **3835 行可运行的 Python 插件骨架 + 21 个 YAML，7/7 py_compile 通过**。方案里写的每个域，都有能编译的结构撑着。
**方案不再是"说说而已"，是"已经建好了骨架的说明书"。**

**② 结构可校验**
A 结构校验 **7/7 零悬空引用**，B source 治理 **7/7 零空 source**。
传统方案没有"校验"这个概念——**你怎么校验一份 Word 的内部一致性？**

**③ 规模与深度同时在线**
14 类知识库 / 8 个知识图谱 / 约 **350 万三元组**。这个体量，传统 5 人团队数周产不出，产出来也无法保证内部一致。

### 节奏从串行改成了并行

传统模式是**串行接力**，总时长是各段之和。FDE 模式是**并行铺开**：

- **35 个分节并行写作**，不是一节一节写
- 制图 26 张与写作**同步跑**
- 7 个域**同一天并行编译**

**这不是把串行加速，是把串行改成了并行**——质的差别。

但并行有致命风险：**各写各的，口径会散**。所以质量控制方式也变了：

| | 传统 | FDE |
|---|---|---|
| 抓错时机 | 评审会**事后**抓 | 锚定口径 + 结构校验**事前**防 |
| 机制 | 靠人细心 | 一份 `_WRITING_BRIEF.md` 当**唯一真相源**，35 节全部引用不重算，校验器兜底 |

诚实说一句：**并行不是没代价的**。散了口径就要收口。第六课会讲到康养项目栽过的跟头——图目计数漂移、章节编号冲突——**那都是并行的账**。但账是可控的，靠的是纪律，不是靠不并行。

### ⭐ 杠杆到底来自哪里（这一页钉不进去，前面白读）

```
产出 = 结构化能力 × 平台固化 × 模型算力
```

三个因子缺一不可，顺序不能反：

| 因子 | 谁提供 | 缺了会怎样 |
|---|---|---|
| **结构化能力** | **人**（把模糊意图压成可执行结构） | 模型再强，也只是把你的模糊**放大成一百页的模糊** |
| **平台固化** | Astra Studio 等工具链 | 每个项目从零起，方法留在个人脑子里 |
| 模型算力 | 大模型 | —— |

康养项目最难的一步，是把 102 个乱糟糟的业务事件收敛成 16 簇、压成 7 个域。这一步**没有任何模型能替你做判断**——模型可以帮你列出 102 件事、可以写候选归类，但"该归成 16 簇还是 20 簇、这个域的边界划在哪"，是 FDE 的结构化判断。

**模型只能加速你做完，不能替你做对。**

> **难听话**：
> **三个因子里，唯一可以花钱买到的是模型算力，而多数人以为它是全部。**

### 🎯 Vibe Coding 的真相

有人用 AI 辅助，**3 小时**手搓了一个本体引擎原型。他复盘"这 3 小时里 AI 到底干了多少活"，得出一张清单：

| AI 能干的 | AI 不能干的 |
|---|---|
| 给了明确规格后，把伪代码变 Python | 规则写入前还是后执行？ |
| 处理文件读写、生成测试、格式化输出 | 日志存快照还是只存改变？ |
| **10 分钟搞定** | Schema 用 YAML 还是 Python？ |
| **共同特征：给明确规格，快速生成代码** | 多规则违反时短路还是收集？ |
| | **共同特征：工程判断，不是编码问题** |

一句话结论，请记死：

> **AI 能把"想清楚的事"快速变成代码，但不能代替"想清楚"这件事本身。**

"想清楚"指的是：数据规模 vs 决策治理、规则 vs 前置条件、可追溯性要什么、业务人员要审查什么、边界条件怎么处理——**这些判断全部发生在写代码之前**。

所以认知杠杆的真相是：**AI 把"实现"变便宜了，但没把"判断"变容易。**

没有蓝图的 Vibe Coding 会失控——**它会很流畅地生成一堆自洽的、错的东西。一处改动带出三处 bug。你省下的思考，最后都要用返工还回来。**

> **平台越来越便宜，本体模型越来越值钱。会建模型的人，不会被替代，而是被放大。**

## 四、别人家怎么落地 FDE

### ⭐ 这一节真正要教的不是八卦，是来源标注

> **当你要把外部实践当作论据时，你标注来源的严谨程度，等于你专业的可信程度。**

**三档来源纪律**（写方案时也一样，必须写出档位，不许藏进脚注）：

| 档位 | 定义 | 例 |
|---|---|---|
| **【官方明确】** | 公司自己的博客 / 招聘页写的 | Palantir 官博对 FDSE 的定义 |
| **【二手报道】** | 分析机构 / 媒体转述 | "DS owns why/what, FDE owns how" |
| **【未获证实】** | 检索不到一手出处，或多方口径打架 | OpenAI FDE 薪酬区间 |

> 这和康养项目"11 处文号查不到就留占位"是**同一条纪律**（反例 B-10）。
> 区别只是取证对象从医保局的文号，换成了 Palantir 的招聘页。**原则一模一样。**

### Palantir：FDE 的原产地

FDE 不是 2026 年才火的新概念，它出生在 Palantir——一家长期给政府和大企业做保密数据整合分析的公司。

Palantir 的解法很反常识：**不把产品打包卖出去让客户自己用，而是把工程师直接派到客户现场长期驻场**。

**【官方明确】**（Palantir 官方博客《A Day in the Life of a Palantir Forward Deployed Software Engineer》）：

> "A Forward Deployed Software Engineer (FDSE), or 'Delta,' is a software engineer who embeds directly with our customers…"

最关键的一句，**【官方明确】**（同上）：

> 普通研发（"Dev"）focuses on creating a single capability that can be used for many customers；
> FDSE focuses on enabling **many capabilities for a single customer**。

**翻译成大白话**：普通研发是"一个能力卖给很多客户"，FDE 是"很多能力喂给一个客户"。

**这句话是 FDE 和产品经理的分水岭。**

### Delta × Echo：最值得抄的不是岗位，是配对设计

Palantir 不让 FDE 单打独斗，给他配了个搭子：**Deployment Strategist（部署策略师），内部代号 Echo**。

**【官方明确】**（Palantir 官方博客《A Day in the Life of a Palantir Deployment Strategist》）：

| 角色 | 负责 |
|---|---|
| **Delta**（FDE） | 技术上的 **construction power（建造力）** |
| **Echo**（DS） | **what should be built**（该建什么）· **why it is important**（为什么重要）· **to whom and how it should be delivered** |

**【二手报道】**（招聘平台 Paraform 博客）的精炼总结：

> "The deployment strategist owns the 'why' and 'what,' while the forward-deployed engineer owns the 'how.'"

⚠️ 这句标二手，因为**不是 Palantir 官网原话，是招聘中介的提炼**——和官方口径一致，可以用，但**要说清楚它是二手**。

⚠️ 另外：Palantir 招聘页同时挂着 "Forward Deployed Software Engineer" 和 "Forward Deployed AI Engineer" 两类岗位——**【官方明确：岗位存在】**。但两者职责的细粒度差别，**检索时页面对自动抓取返回 403，未能取到正文全文**，所以**具体差异标：未获证实**。

> **这里故意不脑补。这就是示范。**

### 我们自己对 Palantir 的一手对照

上面是**外部事实**。下面这张表换个来源——**我们自己方法论文集里的一手观点**（`clife-onto-engine · methodology 06`）。这不是检索来的，是我们自己写的，所以不标"未获证实"，标它是**我们的立场**：

| 维度 | Palantir FDE | 新型 FDE（这门课要的） |
|---|---|---|
| 依赖的平台 | Foundry（**需采购**） | 基本工具链 + 其余靠辅助编程完成 |
| 核心技能 | 深度理解 Foundry + 领域建模 | **第一性原理建模 + AI 执行力 + 业务领域知识** |
| 交付速度 | 受平台部署周期限制 | **第一天对话，第二天出 Demo** |
| 适用战场 | 已采购 Foundry 的客户 | 探索 / 概念验证 / 新项目落地 |
| 瓶颈 | 平台能力边界 | 数据治理、组织推动的时间 |

三个判断直接进这门课：

1. **新型 FDE = 领域建模 + 判断力 + AI 执行力**
2. **"本体不是 Palantir 的专利，它是一种工程方法论"**——所以我们不必买 Foundry，也能做 Palantir 做的事（第五课的 clife-onto-engine）
3. **战场边界**：探索/验证/新项目落地 ✅ 不可替代；规模化/组织推动/运维 ❌ 瓶颈在人不在工具——**这就是 C7 和能力半径**

### 前沿实验室：OpenAI / Anthropic

**OpenAI**——**【官方明确：岗位存在】** 招聘页设 "Forward Deployed Engineer (FDE)"，有 SF、NYC、Tokyo、Gov 等多个坑。职责概括：把前沿模型 "from a demo into a live, working production system"，own 从 discovery、scoping、system design、build 到 production rollout 全过程。

### 国内：为什么"交付即研发"普遍水土不服

**结论先给**：国内在"招 FDE"这件事上有真实动作，但在"FDE 模式能否跑通"这件事上，**公开信息普遍悲观，且很多细节查不到**。

**有动作的部分【官方岗位存在 / 二手】**：腾讯云确实在招"前线部署工程师（FDE）"这类岗位，多篇报道与其开发者社区文章提及。
⚠️ 网传上海 FDE 岗 35–65K×15 薪——**标【未获证实】**，出处是知乎/招聘平台转述，非官方薪酬公告。

**悲观判断的部分【二手报道 · 观点】**（虎嗅《万字解读 FDE 为什么在中国是扯淡的》，作者 AI Humanist）：

- **商业模式相反**：标准技术服务项目采用最低评标价法，客户只愿为成品付费——探索/试错成本默认由乙方承担
- **人才鄙视链**：文章称应届生交付岗年薪仅 10–15 万，同级别大厂研发 30–55 万
- **甲方不真信 AI**：文章引"95% 的企业 AI 试点失败"等数字
  ⚠️ **这些具体百分比未能核到原始出处，标【未获证实】**。引用时必须连同"这是文章里的数字、我没核到源"一起说

还有一类声音直接把中国版 FDE 等同于老概念——"国内从早年的 ERP 实施、驻场顾问到驻场开发，已经做了 30 年 FDE 的核心业务，只是一直把这个工种叫外包"（**【二手报道 · 业界普遍认为】**）。

> **这一节的检索纪律**：岗位在招是真的（可查到挂牌），但**薪资数字、成败结论、具体百分比大量属于二手甚至未获证实**。
> **你越是想用一个数字支撑观点，越要先问"这个数字的一手出处在哪"。**

### 收口：三条共性，三条差异

**共性（可借鉴）**：

1. **现场嵌入、产品级交付**——都不是"写报告给建议"，而是把东西真正跑进客户生产环境。三家口径一致【均官方明确】
2. **把现场经验反哺回产品/方法**——Anthropic 的 "codify repeatable patterns"，和康养项目沉淀 BRIEF/SOP 同构
3. **强调现场取证、不臆造客户环境**

**差异（不能照抄）**：

1. **客户体量**：他们主打 Fortune 500、政府、战略级大客户，钱多、能配双人（Delta+Echo）。我们是 To-G 康养，甲方是地级市国资/民政/医保，**预算受最低价约束，只能一人分饰多角靠平台补**
2. **人 vs 平台的比例**：他们靠堆高薪人才驻场；我们靠 Astra Studio **把 Delta 那半固化**，用更少的人扛更长的链条
3. **薪资与人才市场**：硅谷 FDE 能和研究岗抢人；国内交付岗在鄙视链底端。这决定了**不能靠"招现成 FDE"，只能靠"选人 + 训练 + 平台"自造**

> **Palantir 教我们 FDE 该有哪两组肌肉（Echo+Delta）；前沿实验室教我们大模型时代 FDE 交付什么（production + 反哺）；国内的水土不服教我们哪条路不能走（堆人驻场）。**
> **三者合起来，指向唯一可行的路——工程化平台 + 一人多角。**

## 五、能力模型：你现在在哪一级

### 先说三类"看起来最像 FDE"的人，为什么都不是

你的简历上，很可能正写着这三个词之一。

| 角色 | 他从哪儿开始工作 | 缺了哪一段 |
|---|---|---|
| **解决方案架构师** | 从"一个技术方案"开始，交一份架构图 | 起点是"系统怎么搭"，不是"客户的模糊话什么意思"。**把一句"帮站长管好老人"拆成 102 个业务事件这一步，他通常直接跳过**——因为他默认需求已经有人整理好了 |
| **交付架构师** | 从"一个已经定型的方案"开始，负责落地集成上线 | 价值在"把定好的东西做出来"，**而 FDE 的价值恰恰在"定"之前那一段**——从 16 簇收敛到 7 域，那是判断，不是集成 |
| **需求分析师** | 会做访谈、写需求文档 | **离 FDE 最近，也最容易自我感觉良好。** 交付物是"一份需求清单"，交给下游就结束了；他不为"这份需求能不能编译成 7 域 / 38 Function / 47 Rule / 54 Action"负责，更不为"哪个 Action 要设闸、按错了谁赔"负责 |

三个人都真、都强、都有用。**但他们各自只握住 FDE 这条链的一段。**

> **FDE 不是这三个人里最好的那个，FDE 是这三段本来就不该切开的那条链。**

还有一维最见人品——**失败归因**。三类角色出问题，话术都是"别人的锅"；FDE 没有这个话术，因为**全链是他一个人走的，接缝数为零，断层无处推**。
这不是道德要求，是**结构决定的**：你把四段合成一段，就再也找不到"上一棒没交好"这个借口了。

### C1–C7 七维

| 维 | 能力项 | 康养项目实践中的对应动作 | 在哪一课练 |
|---|---|---|---|
| **C1 认知萃取** | 事件风暴 · 画像 · 旅程 · 热点分层 | 102 事件 / 7 画像（**368 份问卷校准**）/ 7 旅程 / 5 流程 / 10 热点 | 第四课上半场 |
| **C2 结构建模** | DDD 限界上下文 + 五要素 | 7 域 D1–D7；Object 76 / Link 75 / Function 38 / Rule 47 / Action 54 | 第四课下 + 第五课上 |
| **C3 风险设闸** | HIL 设点原则 | **26 个 HIL 点**；站长置信度闸 + 民政 DP-H 闸 | 第五课下半场 |
| **C4 合规治理** | 标准取证 · citations · 诚实边界 | 18 处挂国标；**11 处占位转取证清单** | 第五课下 + 第六课 |

| **C7 人的部分** | 客户关系 · 责任承担 · 价值判断 · 政治敏感度 | 脱敏纪律；**"赋能优化"而非"替代"的红线** | **无法用实操训练**（第一课讲透 · 第八课回收） |

**训练 FDE，不是把某一维练到顶，是把六维的短板逐一补齐。**
三类角色各有一两维起点不低，**但没有一类六维齐全**——这正是"像 FDE 但不是 FDE"的结构原因。

### C7 为什么只能筛不能训

C7 不是"练一练会变好"的技能，是"**你这个人是不是这种人**"的底色：

- **客户关系**——不是会说话，是**客户信不信你敢对他说"这个我不知道"**。一个改不掉"不能在客户面前露怯"这个本能的人，永远做不到留 11 处占位
- **责任承担**——"无处甩锅"能不能扛得住，是天性不是培训
- **价值判断**——什么时候该踩刹车，是价值观在判断，不是流程在判断
- **政治敏感度**——To-G 项目里一句话措辞不当就可能引火烧身。这个雷达，**有的人天生有，有的人怎么教都装不上**

> **选拔 FDE：C1–C6 看能不能补，C7 看是不是这块料。**
> **C7 不合格，前六维再强也不能让他对客户承诺负责。**

### 三级能力锚

> ⚠️ **注意编号**：能力等级写 **Lv.1 / Lv.2 / Lv.3**，与课程编号（第一课到第八课）**是两回事**。
> 旧课件里如果看到 "L1 见习"，指的是能力等级。

| 能力等级 | 含义 |
|---|---|
| **Lv.1 见习** | 能在 FDE 指导下承接**单一环节** |
| **Lv.2 胜任** | 能独立完成认知侧全链条，**交付物需一次复核** |
| **Lv.3 主理** | 能主持项目、设 HIL 闸、**对客户承诺负责**，并能带 Lv.1 |

**真正的分水岭是 C1 认知萃取的跨行业迁移力**：康养你可能靠行业沉淀蒙对了，**换个你不熟的行业（学前督导、辣椒育种、草原修复），沉淀归零、只剩方法**，你还压得出可归域的结构吗？

**这就是 Lv.2 和 Lv.3 的分界。**

### 团队编成随交付模式变

不是"招一堆全能 FDE"——那是幻想。答案是**非对称编队**：

| | **模式一**（Token 计费智能体 SaaS） | **模式二**（大型平台建设 + 运营） |
|---|---|---|
| 代表 | 教育督导项目 | 康养项目 / 草业项目 / 辣椒 |
| 编成 | 轻：**1 FDE + 平台组** | 重：**1 主理 Lv.3 + N 见习 + 平台组** |
| FDE 吃重 | 认知萃取要快 + 设闸 + 产品化 | 全链，尤重合规 / 可研 / 商业建模 |

三个角色的分工本质：

- **主理（Lv.3）** 提供**判断和责任**（C7 + 高阶 C1–C6）——是编队的"判断中枢"和"甩锅终点"
- **见习（Lv.1）** 提供**手数和成长通道**——承接单一环节，不独立对客户承诺，但在真实项目里练六维
- **平台组** 提供**杠杆**——不是 FDE，是让 FDE 不必"更累"的人。维护建模管线，把方法论固化成工具

> **三者缺一，康养项目都不可复制。没有平台组，Lv.3 也会退化成一个更累的架构师。**

### 难听话（现在就说，不留到结课）

> **多数人第一次会停在 Lv.1，这是正常的。装作 Lv.2 才是危险的。**
> 结课**不发合格证，发能力等级 + 差距清单**。

## 六、⭐ FDE 怎么工作：SOP 七阶段（本课落点）

前面五节讲"FDE 是什么"。**这一节讲你接下来五天要按什么流程走。**

### 七阶段

```
S1 认知萃取 → S2 结构收敛 → S3 域切分 → S4 本体建模+设闸
                  → S5 合规治理 → S6 交付物工程 → S7 HIL 运行留痕（横切）
```

| 阶段 | 干什么 | 收口标准 | **对应哪一课** |
|---|---|---|---|
| **立项** | 把客户模糊意图变成可接住的输入 | 交付模式判定得出来 | **第三课 · 采集信息** |
| **S1 认知萃取** | 事件 → 画像 → 旅程 → 热点 | 画像按行为切、有数据校准 | **第四课 上半场** |
| **S2 结构收敛** | 事件归簇 | 簇能对应到域 | **第四课 下半场** |

| **S5 合规治理** | 挂标准 / 留占位 / 转取证清单 | **查不到的一律留占位** | **第五课下 + 第六课** |
| **S6 交付物工程** | 并行写作 → 装配 → 导出 | 口径一致、编号不撞 | **第六课 + 第七课** |
| **S7 HIL 运行留痕** | 谁按的、按错什么代价 | 可审计 | **横切，第五课起贯穿到结课** |

**这七个阶段就是你后面五天要走的路。**

> 今天记住一件事就够了：**这条路上每一步都有一个"必须由人做的判断"。找到它，就是你要学的东西。**

### 三条贯穿全程的纪律（今天立，管五天）

1. **每一步都必须真跑工具，产物落盘。**
   不许"听懂了就跳过"——**产物没落盘就是没做**。
2. **案例只做标尺、不做模板。**
   "康养项目做对了长这样，但你的城市/切口/规模不同，**照结构做、别抄数字**。"
3. **查不到的一律留占位、不编造。**
   这是结课路演的**一票警示**——现在就说清楚。

### ⚠️ 一个必须先打的预防针：第五课之后是分叉，不是流水线

```
第四课 域图 + skill-map ─┬─ 第五课 本体 + 设闸   （要"可执行的规则与闸"）
                         ├─ 第六课 文书          （要"可评审的文档"）
                         └─ 第七课 原型          （要"看得见的应用形态"）
```

**活证据**：学前教育项目**没做本体建模、没有画像和旅程**，照样交出 653KB 可研 + 完整送审报价包。

> 排课顺序是**教学顺序**（由内到外），**不是依赖顺序**。
> 真实项目按**交付模式**决定先走哪条：模式二 To-G 大盘 → 第六课那条线优先；模式一 SaaS → 第五、七课优先。

| 3 | 认知杠杆公式的三个因子？ | 说得出三个，**并知道唯一能买的是模型算力** | 以为杠杆来自模型 |
| 4 | 三档来源纪律是哪三档？ | 能复述，**知道"未获证实"要说出口** | 觉得那是免责声明 |
| 5 | 你现在大概在哪一级？差什么？ | 说得出等级 + 至少一维具体差距 | 自评为 Lv.2 却说不出差距 |
| 6 | **复述 SOP 七阶段 + 对应课次** | **完整复述** | 记不住——**本课唯一硬指标** |

### 参考答案

**1. 三条根因**
① 意图无法完全文档化（102 件没说出口的事）；② 每道工序做本位优化（局部最优叠成全局偏离）；③ 返工的账没人认（没有一个人看得见整条链）。
**关键点**：三条都是**结构性**的，不是"某个人不认真"。所以"写细一点"这个方案在根因①面前就失效了——**你不知道的东西，写不细**。

**2. 必须人扛的事 · 参考三例**

| 事 | 三问判据 |
|---|---|
| 11 处本地文号取件 | 需要"能进机关门的身份" → 人扛 |
| 站长 HIL 的 0.75 阈值 | 需要"愿为速度担多大错"的立场 → 人扛 |
| "赋能优化"而非"替代"的表述红线 | 做错了 FDE 签字担责 → 人扛 |

**答成这样也算达标**：只要你举的例子能用三问中至少一问论证清楚。
**不达标的典型**："写代码必须人来"——这条恰好在可替侧（不需身份、不需立场、错了能回退）。

**3. 三因子**
结构化能力（人）× 平台固化（工具链）× 模型算力（可买）。
**关键点**：**顺序不能反**。结构化能力是零，模型放大零还是零。

**4. 三档来源**
【官方明确】【二手报道】【未获证实】。
**关键点**：为什么必须说出口——因为**你标注来源的严谨程度，等于你专业的可信程度**。藏进脚注等于没标。
**进阶**：Anthropic 那个 base $200–300K vs total comp $350–550K 的例子，说明**同一个事实的两个数字都对，错的是不写口径**。

**5. 自评**
没有标准答案，但有**达标形状**：能说出"我 C1 大概 Lv.2、C3 是 Lv.1，因为我从来没为'按错谁赔'这件事做过判断"。
**不达标形状**："我觉得我都还行。"

**6. SOP 七阶段**

```
立项       → 第三课
S1 认知萃取 → 第四课上    S5 合规治理   → 第五课下 + 第六课
S2 结构收敛 → 第四课下    S6 交付物工程 → 第六课 + 第七课
S3 域切分   → 第四课下    S7 HIL 留痕   → 横切，第五课起贯穿
S4 本体+设闸 → 第五课
```

## 八、带着这三个问题进第二课

1. **你手上正在做的项目，是模式一还是模式二？**（第二课认领命题时要用）
2. **那个项目里，有哪一件事是"必须由你扛、不能交给任何工具"的？**（第五课设闸时要用）
3. **如果现在让你一个人做完它，卡在哪一步？**（这一步大概率就是你最弱的那一维）

> **下一课起，每一课开场讲师都会回到 SOP 七阶段这张图上，指一下"我们现在在这里"。**
> **如果哪一课你不知道自己在图上的哪个位置，当场举手问——这是你的权利。**
