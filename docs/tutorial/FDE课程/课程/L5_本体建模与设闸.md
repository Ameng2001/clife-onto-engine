# 上半场 · 本体建模

## 一、开场第一句：这不是编译器

你看到 "compile" 会以为有个确定性编译器。**没有。**

> 运行时仓自己的文档写得很直白：`map → compile → validate` 三个技能是
> **"LLM-as-compiler" 的 prompt + spec，无确定性编译器、无代码、无测试**。
> 产出是**插件骨架**，内容 finishing 全靠人工。

**为什么开场就要说这句**：因为本课的全部价值都建立在这个认知上——

> **机器负责把结构立起来，人负责把判断填进去。**
>
> 康养项目留了 **121 处 `NotImplementedError`**，这不是没做完，
> 是**明确划出"机器到此为止、人从这里接手"的界线**。
>
> **一个不敢留 NotImplementedError 的 FDE，会让模型把它猜的业务规则写成看起来能跑的代码——那才是灾难。**

## 二、四个命令，和一处最好的权限教学

| 命令 | 干什么 | 强制人审 |
|---|---|---|
| `/studio-ontology:map {id}` | 业务分析 → 七段 IR | 无 |
| `/studio-ontology:compile {id}` | IR → 插件骨架 | 无（已存在不覆盖，只告警） |
| `/studio-ontology:validate {id}` | 四段校验 | 无（只诊断） |
| **`/studio-ontology:model {id}`** | **map → ⏸ 你审 IR → compile** | **★唯一有强制停点** |

> **课堂用 `model`，不要分开跑**——那个停点是本课最重要的教学时刻。
> 审 IR 时审四项：**对象边界 / edge_semantics / 规则的 severity·backing·出处 / Action 的 writes·HIL**。
> **你可以直接改 md 文件再继续。**

### ⭐ 三个技能的权限差异：工具的权限就是它的职责

| skill | allowed-tools | 说明 |
|---|---|---|
| `ontology-map` | Read, Write, Glob, Grep, **Agent** | **有 Agent** → 能调专家做头脑风暴与复核 |
| `ontology-compile` | Read, Write, Glob, Grep | **无 Agent** → 纯机械翻译，**不许自由发挥** |
| `ontology-validate` | Read, Glob, Grep, **Bash** | **无 Write** → **物理上不可能改你的插件**；有 Bash → 能跑引擎 |

> **校验器无权改代码**——这是"纪律靠机制不靠自觉"最干净的一个例子。
> **它只能告诉你哪里不合格，不能替你把不合格的地方抹平。**

## 三、建模时真正要用的三样东西

> **本章只留填 IR 时会用到的判据。** 引擎为什么这么设计（OAG ≠ RAG、三层架构、五条设计红线、
> 内核↔插件契约）**全部在专题课 S1 / S2**——那些是判断力，不是今天的操作步骤。
> **没上过专题课不影响你今天动手**，下面三样够用。

### ① 五要素判据表（拿不准时逐条问自己）

| 要素 | 定义 | 判据 |
|---|---|---|
| **Object** | 业务实体，有独立生命周期 | 有独立生命周期 / 独立属性 / 被引用？ |
| **Link** | 有向关系，带边语义 | 有方向吗？能带属性吗？ |
| **Function** | 只读派生量，**无副作用** | 是**算**出来的，不是**记**下来的？ |
| **Rule** | 全局不变式，违反则回滚 | **所有入口都要成立、且是操作后校验** |
| **Action** | 受审计业务动作 | 有名字吗？要审计吗？带业务意图吗？ |

> ⚠️ **`links` 为 0 是本课的一票警示**——只建对象不建关系，本体就退化成一张数据字典
> （第十一章 `chili` 就是这个反面）。

### ② ⚠️ Rule ≠ 前置条件（填 §4 时最容易写错的一处）

**前置条件只判本次调用；Rule 是全局不变式，在所有入口、且在操作之后都要成立，违反就回滚。**

> **你写规则段时最常见的错，就是把前置条件当规则写上去。**
> 判据一句话：**"别的入口绕过来，这条还该成立吗？"** 该 → Rule；不该 → guard。

### ③ Action 的写路径五步（决定你怎么填 §5 的 `writes` 与 `hil`）

```
guard（前置 declarative）
  → stage_write（内存变更）
  → post_rules（写后强制，违反即确定性回滚）
  → 提交 / 回滚
  → 审计快照 + 置信度 + 证据
```

> **规则在写入之后执行**——这条今天先记住怎么用，**为什么这么设计在 S2 讲透**。
> 它直接决定一件事：**你在 §5 填的 `writes` 写错了，第 3 步会把整笔操作回滚，不会留半截数据。**

## 五、七段 IR

> ⚠️ **命名陷阱**：规范文件标题写「**五段式**中间表示」，正文却是 **0 号 Header + 七段**。
> **"五"指五要素，"七"指七段**，不是笔误。

| 段 | 内容 | 表格列 |
|---|---|---|
| 0 | Header | `ontology_id / bounded_context / target_dir / source_artifacts / iteration` |
| 1 | **Objects** | `name / primary_key / properties / lifecycle / source` |
| 2 | **Links** | `name / from / to / cardinality / edge_semantics / properties` |
| 3 | **Functions** | `name / reads / returns / intent` |
| 4 | **Rules ★** | `name / severity / backing / evaluation / on_actions / intent / source / citations / check`（**9 列**） |
| 5 | **Actions** | `name / params / guards / post_rules / writes / hil / validate`（**7 列**） |
| 6 | Mapping Hints | `object / store / table / key / columns / materialization` |
| 7 | CQ | YAML：`- q:` + `expect:` |

### 三组关键取值域

**`edge_semantics` 三值**（决定多跳推理停在哪，IR 里最难的一处判断）：

| 值 | 含义 |
|---|---|
| `root_cause` | **命中即终止追溯**——找到根因了，别再往上查 |
| `hypothesis` | **继续查**——这条边只是"可能相关" |
| `derivation` | 纯结构派生——不参与因果推理 |

**`source` 三态**（治理教学的关键）：

| 写法 | 审计结果 |
|---|---|
| 具体标准号（如 `GB 38600-2019`） | ✅ 通过 |
| `通用` | ✅ **通过**——自明常识是合法值，审计放行 |
| `TODO(FDE): 补依据` | ⚠️ **被拦**，计入治理缺口 |

> **"通用"这个值的存在很重要**：它让"**我知道这是常识、不是我忘了查**"能被表达出来。
> **留白和"承认这里是常识"是两件事。**

**`expect` 三值（CQ）**：`query` / `action(<动作名>)` / `rejected(<规则名>)`

### 段末完整性自检（7 条）

① 每个 Object 有主键、被写入的都已声明
② Link 的 from/to 都已声明、edge_semantics 已判
③ 每条 Rule 标了 severity + backing + evaluation
④ 每条 Rule 有 source
⑤ Action 的 guards / post_rules / writes 都存在
⑥ **合规 / 对外凭证类 Action 都设了 hil**
⑦ CQ 至少覆盖一查一做一拦

## 六、declarative vs function：一句话判据

> **判定所需的全部信息，是不是都在 `ctx.params` + `ctx.actor` 里？**
> **是** → `declarative`（可从 `check` **全自动生成代码**）
> **否**（要 `ctx.get` / `ctx.find` / `ctx.search_around`）→ `function`（**只能生成骨架，你来填**）

规则工程师 agent 的原话，值得记住：

> **"never mark a rule `declarative` if it secretly needs to look up a registry/threshold/inventory — that's `function`"**
> —— **偷偷需要查名录 / 阈值 / 库存的，不是 declarative。**

**偏好倾向**：合规、安全、方法学类的规则，默认往 **`hard` + `post_write` + `function`** 三档靠。
**因为那才是回滚机制的用武之地。**

### ⚠️ declarative 的取反逻辑（最容易写反的地方）

IR 的 `check` 写的是**合法条件**，生成代码时**取反成违反条件**：

```
IR:    check = budget is None or budget >= 0

生成:  if not (budget is None or budget >= 0):
           return RuleResult.fail(...)
       return RuleResult.ok()
```

> **记住：写"什么情况下是对的"，不是"什么情况下要拦"。**

## 七、编译产物：机器给你到哪一步

`compile` 产出 4 个文件：

| 文件 | 内容 |
|---|---|
| `{target_dir}/__init__.py` | 主体：ONTOLOGY 常量 + Object/Link 注册 + Function/Rule/Action handler + seed 桩 |
| `mappings/objects.yaml` | ← IR §6，对象→物理表 / 列 / 物化策略 |
| `cq/golden.yaml` | ← IR §7 |
| `plugin.yaml` | 清单 |

### 四类 `NotImplementedError` 的来源

| # | 触发条件 | 生成物 |
|---|---|---|
| 1 | **function-backed 规则** | 装饰器 + docstring + `# TODO(FDE): 查…` + 可用方法提示 + `raise` |
| 2 | **每一个 Action handler** | stage_write 骨架注释 + `set_confidence` + `raise` |
| 3 | **Function 口径不明** | `# TODO(FDE): 实现派生量计算（只读，无副作用）` + raise |
| 4 | `seed_reference_data` | **不 raise**，函数体 `pass` + TODO docstring |

> **declarative 规则是唯一被"全自动生成函数体"的**——
> 这就是为什么规则三问的第二问要问"只看入参能不能判"：**答对了，机器就能替你写完。**

### ⚠️ SPI 七槽位的真相（文档不准）

文档说编译产物"正好填满 SPI 的 7 个槽位"。**实测不是。**

| 槽位 | 编译产物覆盖？ |
|---|---|
| 1 Schema 包 | ✅ |
| 2 映射注册表 | ✅ |
| 3 Function/Rule 实现 | ⚠️ **只出骨架** |
| 4 Action handlers | ⚠️ **只出骨架** |
| 5 记忆词典 / 术语表 | ❌ **完全不生成** |
| 6 Agent 角色 + HIL 关口声明 | ❌ **完全不生成** |
| 7 CQ 验收集 | ⚠️ 产 YAML，但**格式与引擎不匹配** |

> **教学价值**：这张表本身就是"**别信文档，去看代码**"的活教材。

## 八、两仓分工（不讲清楚你会把数据写进插件）

```
建模仓（astra-studio 工作区）           运行时仓（clife-onto-engine）
studio/changes/{id}/ontology-map.md  →  plugins/{ontology_id}/  ← 本体定义/规则/动作（行业级，租户无关）
                                        tenants/{tenant}/       ← 该租户的实例与参考数据
```

- **`plugins/{ontology_id}/`，不是 `plugins/{tenant}/`** —— grass 与 chili 在**同一进程同一 registry 里按 namespace 共存**
- **名录数据、实例数据属于 `tenants/`**，不属于插件
- **IR 文件不在运行时仓**，跨仓复制

> **你把名录数据写进 `plugins/`，违反的不是习惯，是红线**（五条红线的第 1 条和第 5 条）。

## 九、⚠️ FDE 收尾清单：6 项机器帮不了的

**编译完成 ≠ 可用。这 6 项必须人做**：

| # | 做什么 | 在哪做 |
|---|---|---|
| 1 | **填 function-backed 规则体** | `ctx.get()` 取对象 → `ctx.find()` 查名录 → 比对 → `RuleResult.fail(msg, suggestion=)` / `ok()` |
| 2 | **填 Action handler 回写** | `ctx.stage_write()` / `ctx.stage_link()` / `ctx.emit_effect()` / `ctx.set_confidence()` / `ctx.add_evidence()` |
| 3 | **填 seed 参考数据** | `seed_reference_data(store)`；真实落地走 `tenants/{tenant}/` |
| 4 | **把 CQ 翻成 Python** | ⚠️ 引擎**只认 `cq.py` 的 `CQ_SUITE` 元组**，全仓**没有任何代码读 `cq/golden.yaml`** |
| 5 | **改 `plugin.yaml` 成引擎格式** | ⚠️ 模板产 `ontology_id:` + `provides:{...}`，引擎读的是 `doc["ontology"]` + `schema/mappings/glossary/agents`，**完全不认 provides**。还要补 **glossary + agents** 两段 |
| 6 | **补 `Evaluation` 的 import** | ⚠️ 编译规则的固定头部**漏了它**，照着生成会 **NameError**。SDK 确实导出，加上即可 |

> **第 4、5 两项是硬落差**：不做，**编译产物根本跑不起来**。
> **这不是你做错了，是工具链的已知缺口。**
>
> ⭐ 顺便回收 **B-9**：康养项目当初对某个符号是否导出存疑、**统一留 docstring 挂账没敢往前推**——**今天证明那个判断是对的。不确定就挂账，别赌。**

### 六处「文档 vs 代码」落差（本课最贵的实测资产）

| # | 文档怎么说 | 代码实际怎样 |
|---|---|---|
| ① | README 说 intake 是 **11 段** | 模板实际 **§0–§11 共 12 段** |
| ② | 规范标题写「**五段式**中间表示」 | 正文是 **0 号 Header + 七段** |
| ③ | 说编译产物"**正好填满 SPI 7 槽位**" | **槽位 5、6 完全不生成，3、4 只出骨架，7 格式不匹配** |
| ④ | 编译产 `cq/golden.yaml` | 引擎**只认 `cq.py` 的 `CQ_SUITE`**，全仓无代码读该 YAML |
| ⑤ | 模板产 `plugin.yaml` 用 `provides:` | 引擎**不认 provides** |
| ⑥ | 编译规则的固定 import 头部 | **漏了 `Evaluation`**，照抄会 NameError |

> **这六条不是吐槽工具，是教学法。**
> FDE 每天面对的就是这种"**文档说 A、代码是 B**"。
> **唯一可靠的动作是去读代码、去跑一遍。**

### 红线是两层

| 层 | 手段 | 强度 |
|---|---|---|
| 建模端 | prompt 指令"只从 SDK import，不碰内核内部" | **软约束，无机械检查** |
| **运行时端** | CI 两个脚本必跑 | **硬执法** |

- `check_kernel_purity.py` —— **反向执法**：扫内核代码，命中行业词黑名单即 exit 1

> **这正是 B-8 的物理对应**：你在凌晨三点想抄近路直接摸内核私有方法，**CI 会挂给你看**。
> **结构纪律靠校验器，不靠自觉。**

## 十五、★★ 两道闸：本课最容易混、也最值钱的一节

你默认以为"HIL = 拦住不让写"。**错的。** 这两道闸完全不同：

| | **写入闸** | **副作用闸（HIL）** |
|---|---|---|
| 谁触发 | `hard` 级 post_write 规则被违反 | `HilPolicy.predicate` 返回 true |
| 效果 | **`overlay.clear()` 确定性回滚，数据不落地**，返回 StructuredRejection | **数据照常写入**；decision 标记为 `pending_hil` |
| 拦的是 | **错误的状态** | **对外的动作** |
| 具体表现 | 写操作被撤销 | **`scheduled` 副作用被清空** —— 工单、凭证、通知**不派发**，等人审 |
| 谁来兜底 | 引擎（确定性，**无人参与**） | 人（`reviewer_role`） |

> **一句话**：**写入闸拦的是"写错了"，HIL 拦的是"这事该不该真的发出去"。**
>
> 康养项目的民政 DP-H 闸就是典型的副作用闸——**数据可以先算出来，但"对外发布"这个动作必须人点头。**

### HIL 在各层怎么表达

| 层 | 写法 |
|---|---|
| Intake §5「需人工审批？(谁)」 | `是·乡土草种合规官` |
| IR §5 Action 的 `hil` 列 | `乡土草种合规官 / confidence<0.75`（**角色 / 条件**，斜杠分隔） |
| 编译产物 | `hil=HilPolicy(reviewer_role="...", predicate=lambda confidence, touched_hard: confidence < 0.75)` |
| 运行时置信度 | handler 内 `ctx.set_confidence(...)` |
| 判定 | `should_route_hil` → `decision="pending_hil"` + **冻结 effects** + 审计带 reviewer |
| 声明式 | `plugin.yaml` 的 `agents:` 段（`role / reviews / description`） |

**只有 Action 有 `hil` 字段。** Object / Link / Function / **Rule 都没有**。

### ⚠️ 三个必须知道的 HIL 陷阱

**1. 光写 `reviewer_role` 等于没设闸。**
`HilPolicy.predicate` 的**默认值是恒 `False`**。
`HilPolicy(reviewer_role="合规官")` 不给 predicate，**永远不会触发**。

**2. 置信度不会自己出现。**
编译只生成硬编码的 `ctx.set_confidence(0.8)`。真实插件的写法是：

```python
ctx.set_confidence(ctx.params.get("_confidence", 0.82))
```

——**上游意图编译器把 LLM 的置信度经 `_confidence` 参数注入**，handler 拿不到就用插件默认值。

> **插件文档完全没写这一句。不补这一步，你做出来的"置信度闸"是个永远不动的摆设。**

**3. `severity_touched==hard` 这个 predicate 基本不会触发。**
因为 `touched_hard=True` 时，引擎**先回滚 + 拒绝就返回了**，根本走不到 HIL 判定那一行。

> 它只在"违反的是 soft 规则、但你想以此要求人审"这种场景下才有意义。
> **需要组合条件（如"低置信或碰了硬规则"）得手写 lambda——引擎允许，IR 语法没定义。这是表达力上限，也是逃生舱。**

## 十六、⭐ HIL 设点四判据 + 一条置信度兜底闸

> **口径纪律**：是 **"四条硬判据 + 一条置信度兜底闸"**，**不是"五条硬判据"**。
> **四判据看动作性质，兜底闸看模型把握。两者不是同一类东西。**

### 四条硬判据（看动作性质 · 满足任一即须插人）

| 判据 | 含义 | **一句话测试** | 康养项目实例 |
|---|---|---|---|
| **① 不可逆** | 动作做了收不回来 | "撤销这个动作，代价大到不可接受吗？" | 急救四级联动升级（D4）、监管数据对外发布（D6） |
| **② 涉钱** | 直接产生 / 改变金钱流向 | "这一步之后有钱动了吗？" | 增收订单生成（D1→D3）、DIP 结算入账（D2）、补贴拨付（D6） |
| **③ 涉合规** | 触发监管 / 法律义务 | "监管来查，这一步要留痕解释吗？" | 数据授权 / 最小必要（D6）、DIP 控费入账前阻断（D2） |
| **④ 跨组织** | 后果落到别的主体身上 | "做错了，是别人替我承担后果吗？" | AI 方案转订单卖给会员、补贴发布 |

### 置信度兜底闸（看模型把握 · 横切）

- 四条判据是"**看动作性质**"；兜底闸是"**看模型有多确定**"。
- **即便一个动作四条都不命中，只要模型对它的置信度低于阈值，同样落人工。**
- 康养项目固化为 D1 的**置信度闸**：`hard · function · pre`，**阈值占位 0.75**，
  **建模时刻意设成 pre（前置）**——**在动作发生前拦，不是发生后补**。
- 这条是防"**高频低置信**"决策悄悄溜过去的最后一道网。

> **为什么是"满足任一即插人"，不是"满足多数"？**
> 因为这四条**每一条单独成立就够伤**。**涉钱一条就够了**——一笔错误增收决策，客户的钱亏了，**赖不到模型头上，赖到你头上**。
> 所以是**或**，不是**与**。**宁可多设几道闸拖慢一点，不可漏一道闸出一次事。**

> ⚠️ **但"任一即插人"必须先过下面的第一道筛**：这个动作**能不能固化成硬规则**？
> **先问"能不能自动"，再问"该不该插人"——顺序反了就会闸设满。**

## 十七、闸为什么必须分两层

> 否则你会把 HIL 当成唯一的闸，**闸设满、人变橡皮图章**。

### ① 软约束不是工程约束

你在提示词里写"发起采购前必须检查认证有效期"——这是**软约束**，有三个结构性缺陷：
**会被遗忘**（多轮对话后早期指令权重下降）、**会被稀释**（上下文塞满后约束被挤出）、**会被绕过**（提示词注入让模型"忘记"约束）。

> **"自觉遵守不是工程约束。"**

| 层次 | 机制 | 强度 | 可绕过性 |
|---|---|---|---|
| 提示词层 | 靠 LLM 自觉 | 最弱 | 高（注入即破） |
| API 网关层 | 校验请求参数格式 | 中 | 中（参数可伪造） |
| **本体层** | 校验业务状态 + 全局不变式 | **最强** | **低（引擎强制，无旁路）** |

### ② 第一层是"自动闸"——引擎确定性回滚

被拒的 Agent 收到的不是 500 错误，而是**结构化拒绝三件套**：
`triggered_rule`（为什么不行）+ `current_state`（当时的世界快照）+ `suggestion`（可以怎么调整）
→ Agent 据 suggestion 改选、重试成功。

这就是 **OAG 闭环：发现 → 调用 → 被拒 → 调整 → 重试**，全程在约束内、**没绕过**。

> **能固化成硬规则的，就交给自动闸，别浪费人力。**

### ③ 第二层才是"人工闸"——HIL

什么时候才上 HIL？两种：

- **机器判不了的价值判断**——涉钱 / 涉合规 / 跨组织的拍板
- **机器"没把握"**——AI 原生系统里每个断言都是概率的（`balance_sufficient = (False, confidence=0.78)`），**置信度太低时，基于它的决策不该是最终结论**

> 这就是康养项目**站长置信度闸 0.75** 的方法论根据：
> **不是拍脑袋定的阈值，是"低置信必须转人"的工程共识。**

### ④ HIL 留痕 = 审计快照，不是日志

留的不是"操作日志"，是**决策快照**——"记录上下文，而不只是记录结果"。

康养项目强制留 `signer_id / reviewed_at / decision / edits_before_after`，就是为了回答那个问题：

> **"三个月后，合规团队问'AI 当时凭什么觉得能下单'，你能不能当天答上来。"**

### 一句话收口

> **"你能把多大的权力交给一个系统，取决于设计时边界定义在哪里，
> 以及越界时——是被它自己拦下，还是被现实拦下。"**

自动闸 + HIL，就是"被它自己拦下"；
两样都没设，就是等着"**被现实拦下**"——**那时赔的是钱、是合规、是客户关系。**

## 十八、validate 四段校验

```
/studio-ontology:validate {id}
```

| 段 | 时机 | 查什么 | 不过的后果 |
|---|---|---|---|
| **A 结构完整性** | 静态 | Action 的 guards/post_rules/writes 是否都已声明；Link 的 from/to；**五要素无悬空引用** | **BLOCKER** |
| **B 治理审计** | 静态 | ① **每条 Rule 必须有 source**（空或 `TODO(FDE)` → 缺口；`通用` → 放行）② function / 合规类应有具体 citations ③ **合规 / 对外凭证 / 定级定价类 Action 应设 hil** | ① **BLOCKER**，②③ 告警 |
| **C 剩余 FDE TODO** | 静态 | 扫仍 `raise NotImplementedError` 的规则与 handler；`seed` 仍为 `pass` | 告警 |
| **D 行为 CQ** | **动态** | 逐条跑 CQ：`query` 应能查通；`action(X)` 应 committed；`rejected(R)` 应被规则 R 回滚 | 未填的标 SKIPPED 而非 FAIL |

**交付判据**：**A、B 必须全过才可交付；D 在填完后全绿才算闭环。**

> B 段的定位很关键：它等价于运行时的"无引用规则审计"，**但在交付前就拦**。
> 这就是康养项目"**18 处挂已核验国标、11 处坚决保留占位**"能守住的机制原因——
> **不是靠自觉，是有个东西在交付前拦你。**

## 二十、反例主场：B-1 / B-2 / B-5 / B-10

> 别的环节一步一个反例，本节**一次给四个**——因为**交付物工程和合规治理是出错高发区**，这四个坑我们全踩过。

**B-1 图目计数漂移**
- **怎么发生的**：图规格文件标题写"22 张图"，表体实际列了 **26 行**。后期补的图追加到表尾，**头部那个计数没人回去改**。
- **根因**：**摘要与明细必须有单一真相源；并行 / 追加式产出必须有一个显式的"收口回改"动作。**
  漂移不是因为谁粗心，**是因为没有一步流程负责在追加后回改头部计数。**

**B-2 章节编号冲突**
- **怎么发生的**：35 个分节**并行**写作，各节作者自行起标题层级，装配期出现**编号重复 / 跳号**。
- **根因**：**编号权归装配阶段，不归写作阶段。**
  **并行的东西，全局唯一性只能在收拢点解决，不能指望各分支自己协调。**

**B-5 数据张冠李戴**
- **怎么发生的**：老龄化率跨节引用中错配——**60+ 口径和 65+ 口径混用**。
- **根因**：**关键数字必须锚在 BRIEF 单点，分节作者一律引用不重算。** 这正是锚定口径机制的**反面**。

**B-10 · 11 处地方文号坚决不编造（全课程价值观支点）**
- **怎么发生的**：**7 处本地文号 + 4 处企业内部 SOP 编号**，**公开渠道查不到**。
- **诱惑在哪**：编一个"看起来对"的文号，**合规件就完整了，交付显得漂亮**。
- **怎么处理的**：**11 处坚决保留占位不编造**，每处**锚定上位国标**，转成一份**逐项取件清单**，标注"该找谁、取哪份文件"。**判定为非 BLOCKER，不阻断交付。**
- **根因（原话）**：

> **"错文号比空缺更有害。"**
>
> **空缺是诚实的，能被后续补上；错误的文号是有毒的**——它会以"看起来完整"的样子骗过审核，**在迎检时爆炸**。
>
> **留占位 + 锚上位国标 + 转取证清单**——这套动作就是把"我不知道"变成"**专业的不知道**"。

## 二十一、沉浸：康养项目 26 个 HIL 点

| 域 | HIL | 判据实证 |
|---|---|---|
| D1 康养智能体中枢 | 2 | 站长 HIL（增收，**涉钱 + 跨组织**）+ 健管师复核 |
| D2 政策结算枢纽 | **0\*** | ⭐ 见下面的星号 |
| D3 会员营收飞轮 | 1 | 涉钱但多为**可逆**营销动作，只在关键转化点设 1 闸 |
| D4 居家健康照护 | 6 | 含**急救四级联动指挥（不可逆！）**，多处涉人身安全 |
| D5 机构运营 | 5 | 入住 / 退费 / 医嘱涉钱涉合规涉人身 |
| D6 民政治理 | **8** | **最多**——DP-H 闸（**涉合规 + 涉钱 + 跨组织三条全中**） |
| D7 知识库 | 4 | 版本发布被全域引用，**发错版本影响全局** |
| **合计** | **26** | **风险在哪，闸就在哪** |

### ⭐ 这张表最该学的是 D2 那个星号

结算域**涉钱最狠，显式 HIL 却是 0**。新手觉得矛盾——涉钱怎么不设闸？

因为 FDE 做了个更高级的判断：

> **把合规拦截前置到规则层，比事后拉个人来点确认更可靠。**
>
> **人工闸是最后手段，不是唯一手段。**
> 能用确定性规则挡住的，就别靠人肉点确认——**人肉点确认点多了，就变成橡皮图章。**

### 两大闸门 + 按错的代价

**闸门① · 站长 HIL（增收闸 · 置信度闸 0.75 防橡皮图章）**

- **机制**：AI 生成增收方案后，**必须站长在审核台点确认才能转成订单**
- **判据命中**：涉钱 + 跨组织 + 置信度兜底
- **为什么设置信度闸**：不是走形式。设成 `hard · function · pre`，**目的就是防橡皮图章**——AI 高置信的方案快速过、**低置信的强制站长细看**
- **⚠️ 按错的代价**：如果阈值调成 0（或站长养成"一律点同意"的习惯），**闸门在，但等于没有**。AI 给一个低置信的、对长者不合适的高价套包，站长机械点过，卖出去了——**钱是长者的、口碑是客户的、责任是我们的**。微康养做的是熟人生意（**熟人获客 77.59%**），**卖错一单，毁的是整个片区的信任飞轮**
- **根因**：**闸门的价值不在"有没有"，在"会不会真拦"。阈值是活的，谁调阈值谁负责。**

**闸门② · 民政 DP-H（监管发布闸）**

- **机制**：**任何对外发布的监管数据 / 补贴决定，必须民政经办拍板留痕**
- **判据命中**：涉合规 + 涉钱 + 跨组织，**三条全中**
- **⚠️ 按错的代价**：AI 把一份未经核验的数据、或一笔补贴资格认定直接对外发布——**违反数据授权最小必要（个保法）、可能错发 / 漏发补贴（涉公帑）、政府信用受损**。这是**不可逆的**：数据发出去了收不回来；**补贴发错了，追缴是政治事件**
- **根因**：**跨组织 + 涉合规的动作，人工闸是法律义务不是可选项。谁发布谁签字。**

> **两句话记住**：
> **站长闸防的是"钱按错"**——闸门在但退化成橡皮图章，等于没有。
> **民政闸防的是"合规越界"**——跨组织发布是法律义务，谁签字谁背书。

## 二十二、⭐ 现场演示：让"设闸"变成看得见的东西

```bash
python scripts/smoke_cq.py
```

**它做了什么**：造一个**删掉「乡土合规」post_rule** 的版本，然后拿同一套 CQ 去跑——
「非乡土草种应被拦」这条 CQ **立刻从 pass 变 fail**。

> **这一下就把"设闸"讲活了**：
> **闸不是写在文档里的一句承诺，是一条能被自动验证会不会失效的机制。**
> 删掉它，验收门当场抓住。

**给你的问题**：
> **你们命题里那些"我们会严格审核"的承诺，有哪一条能像这样被自动验证？**
> **验证不了的，就还只是愿望。**

其余可跑命令：

```bash
python -c "import plugins.{id}"              # 最低验收线：能 import
python -m pytest tests/test_cq.py -q         # CQ 回归
python scripts/check_kernel_purity.py        # 红线门禁 1
python scripts/check_plugin_capabilities.py  # 红线门禁 2
python scripts/export_okf.py                 # 治理导出
```

## 附 · 一页纸速查

**⭐ 上半场七步走查**（详见第十章）

```
0 定 ontology_id（= 插件目录名）
1 补完 12 段契约 §3–§9              ← 第三课的补作业
2 /studio-ontology:model {id}       ← 别 map/compile 分开跑
3 ⏸ 停点审 IR 四项 ★★ 本课最重要的 35′
     对象边界 · edge_semantics · 规则三问 · Action 的 writes/hil（先留位）
4 继续 → compile → plugins/{id}/ 4 个文件
5 grep -c NotImplementedError       ← 数出来的就是你要接手的活
6 对照收尾 6 项，标"谁填、何时填"
7 /studio-ontology:validate → 看 A 段（B 段治理项下半场补）
```

**卡住四条**：IR 段缺 → 回查契约哪段空 ｜ `links`=0 → 你只写了实体没写关系 ｜
compile 说已存在 → 先删旧目录别叠加 ｜ **完全没头绪 → 打开 `plugins/grass/` 对照**

---

**这不是编译器**：机器立结构，人填判断。**121 处 NotImplementedError 是界线，不是没做完。**

**规则三问**：① 拦不拦（severity）② 只看入参吗（backing）③ 依据是谁（source）

**declarative 判据**：判定信息全在 `ctx.params + ctx.actor` 里吗？**偷偷要查名录的，是 function。**

**check 写"什么情况合法"，不是"什么情况拦截"。**

**source 三态**：标准号 ✅ / `通用` ✅ / `TODO(FDE)` ⚠️被拦

**两道闸**：写入闸拦"写错了"（回滚，数据不落地）；HIL 拦"该不该真的发出去"（数据写了，副作用冻结）

**四判据 + 一兜底**：不可逆 / 涉钱 / 涉合规 / 跨组织，**任一即插人**；外加**置信度兜底闸**

**顺序**：**先问"能不能自动"，再问"该不该插人"**——反了就会闸设满

**只写 reviewer_role 等于没设闸**（predicate 默认恒 False）

**错文号比空缺更有害。**

④ `export_okf.py` + `serve.py` → **`/viz/{你的 id}`**（给业务方看的那张牌；`smoke_cq` 是给工程师看的）
