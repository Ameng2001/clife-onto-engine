《C-Life FDE 实战工作坊》· 授课流程手册（八课 · 5 天 + 选修专题课）

拿着这一份，就能从第一分钟讲到结课。 每个时段写明：讲师做什么 / 学员做什么 / 产出什么 / 会卡在哪。 本文件是时间轴；每课的完整内容在 课程/L*.md；结构定义见 00_八课总纲.md；口径查 _WRITING_BRIEF.md。 v0.3 八课制（2026-07-27）：L1 纯讲解建立认知，L2 领项目装工具，L3–L7 每课一个工作环节，L8 收口。 专题课 S1「本体论」（2026-07-31 新增）是选修半天，定位为 L5 的方法论前置，开不开见第二章的三条判据。

〇、三句话说清这个工作坊

  1. 先给地图，再上路。 L1 用一整个上午把「FDE 是什么」讲透，包括 SOP 七阶段和它对应后面哪一课——学员知道自己在练什么。
  2. L3–L7 每课同一个骨架：目的 → 启发 → 沉浸（真实案例）→ 实操（本组命题，产物落盘）→ checkout。
  3. 验收不看"讲得好不好"，看学员能不能独立走完认知侧全链条，并且知道自己在哪里必须叫人。

二、D0（选修）· 专题课 S1–S3

专题课是选修的，共三门 × 180′ = 540′。 开不开、开几门，按下面的判据决定—— 不是"时间够就加"，是"这批学员需不需要"。 教材来源与八课不同，三门各不相同——口径隔离见 _WRITING_BRIEF.md 第八节。

三门课是一条线，不是三个散课

回答 教材 形式
S1 · 本体论 本体是什么、为什么必须有 《工程师的本体论》方法论文集 纯讲解 180′
S2 · 本体引擎的工程实现 怎么造出来 clife-onto-engine 源码 + 内核"宪法" 讲解 + 当场读码 180′
S3 · 建模端如何支撑引擎 怎么给它编译应用（架构图右下角那个橙色框） 我们自己的 studio-ontology（一档）+ 信通院分析（二档，一节） 讲解 + 管线走查 180′

终点是 L5：S2 讲运行时端，S3 讲建模端，L5 把两端接起来，学员亲手交一个能跑的插件。

顺序上不能破的三条：S2 在 S3 前（S3 要回扣 S2）· S3 在 L5 前（S3 第十一章是交棒章）· S1 在 L5 前且尽量相邻。

判据 开 不开

⭐ 四句今天必须说出口的话：

⭐ 一个现场动作（效果最好，别省）

卡点

症状 处置
"我们已经有数据中台了" 别否定——先肯定"这件事做成了"，再讲边界：只管数据的流动，不管业务的逻辑

八、应急预案

时间不够，砍什么

优先砍 理由
L7 原型开发 原型可课后做
L8 的能力沉淀段（50′） 沉淀可延后，但"哪个动作值得沉淀"这个问题要留
L6 的"写 2 章"降为"写 1 章" plan 的 Gap 清单必须留，那才是教学点
L1 的"别人怎么做"内容部分 但三档来源纪律必须留
绝不砍 L5 唯一产出"机器会强制执行的东西"的一课
绝不砍 L1 的 SOP 七阶段那 40′ 砍了它，后面每一课学员都不知道自己在哪

压缩档（3 天）：D1（L1+L2+L3）/ D2（L4+L5）/ D3（L6 或 L7 择一 + L8）　·　专题课 S1 不开 分散档（8 周）：每周一课，配合在手真实项目——L5/L6 的产出需要真实项目承载，这一档最理想　·　S1 放第 0 周

专题课 S1 是选修的，砍它不影响八课完整性——但如果学员里有"我们已经有数据中台了，为什么还要这个"这类疑问， 砍了它，这个疑问会在 L5 中途冒出来，那时候更难回答。
