## 一、为什么讲"交付模式"，而不是"行业案例"

新手看这四个项目，看到的是四个行业：康养、学前督导、辣椒、草业。
FDE 要看到的是**两种交付模式**——它们决定了**交付物形态、商业模式、交付周期、团队编成、FDE 能力侧重**的根本不同。

**选错模式的代价**：用做大平台的重法（百页可研+投建运+运营盘）去做一个本该轻量按量计费的 SaaS 应用 → 又慢又贵、客户不买单；反过来，用做 SaaS 应用的轻法去接一个 To-G 大平台 → 撑不起可研评审、财务测算、监管合规，中不了标。
**FDE 的第一个判断，往往不是"怎么做"，是"这是哪种模式的活"。**

## 二、两大 FDE 交付模式（主轴）

### 模式一 · Token 计费智能体 SaaS 应用

- **一句话**：交付物就是**可运营的智能体应用本身**，按调用量/token/席位计费。Agent 即产品。
- **特征**：轻、快、产品化；不需要百页可研；靠"能用的 agent + 可信的 HIL"赢单；迭代以周—月计。
- **代表案例**：**教育督导项目**（某市某城区智慧督导 SaaS——标准解码→Gap 诊断→OKR 下钻→材料实时质检的智能体应用，卖给区教育局，平台赋能/按用量）。
- **该模式下 FDE 吃重**：S1 认知萃取要快、S4 本体设计+设闸、产品化/demo 交付；**S6 的"可研交付物工程"基本不吃重**（不需要百页文档）。
- **HIL 命门**：落在**应用内的裁定/质检闸**——教育督导项目的三闸（区局 OKR 审核、园长材料复核、警告下强制提交）就是这一模式的典型。
- **团队编成**：轻——1 名 FDE + 平台/运行时组（维护 agent 运行时与知识库）即可起步。
- **⚠️ 诚实注**："Token 计费 SaaS"是 C-Life 对该模式的**商业定位**；教育督导项目源材料描述其为"游学平台并行外挂/平台赋能"，**未见具体计价表**，引用时讲"定位为按量 SaaS"，不编具体单价。

### 模式二 · 大型平台建设 + 生态运营项目

- **一句话**：交付物是**可研 + 平台建设 + 生态运营**的整套，投—建—运一体，To-G 大盘。
- **特征**：重、长周期（可研→建设→运营，季—年计）；多元收入（运营盘/碳汇/交易佣金/数据要素）；赢单靠可研评审+财务测算+监管合规+战略叙事。
- **代表案例**：
  - 🟢 **康养项目**（1.36 亿城市级康养平台 + 微康养运营网络 60 站，**已交付**：本体编译 3835 行 + 11 万字可研）——**模式二标杆**。
  - 🟡 **草业项目草业**（内蒙古草业集团草业大平台 + 生态修复 + 碳汇变现 + 3–5 年平台规划，**方案+demo 级**）。
  - 🟡 **辣椒大模型**（辣椒精准种植全产业链平台建设方案，**方案级**）。
- **该模式下 FDE 吃重**：**全链 S1–S7**，尤其 S5 合规（挂国标/评估细则）、S6 交付物工程（百页可研）、商业建模（投资/IRR/多元收入）。
- **HIL 命门**：增收闸 + 监管发布闸（康养项目 26 HIL：站长增收闸 + 民政 DP-H）/ 凭证发布闸（草业项目碳汇、辣椒溯源）。
- **团队编成**：重——1 主理 FDE（**Lv.3**，对客户承诺负责+设闸）+ N 见习（**Lv.1**）+ 平台组，且需要更重的商业/财务/合规能力半径。

## 三、两模式对照表

| 维度 | 🟩 模式一 · Token 计费智能体 SaaS 应用 | 🟦 模式二 · 大型平台建设 + 生态运营 |
|---|---|---|
| **交付物形态** | 可跑的 agent 应用 + 本体/RAG + HIL 质检；轻文档 | 百页可研 + 平台建设 + 运营方案 + 财务测算 + 本体 + 多端系统 |
| **商业模式** | 按 token/调用/席位计费的 SaaS 订阅；无自营运营盘 | 投—建—运一体；运营盘 + 多元收入（碳汇/交易/数据要素） |
| **交付周期** | 短（周—月迭代） | 长（季—年：可研→建设→运营） |
| **赢单靠什么** | 能用的 agent + 可信 HIL + 快 | 可研评审 + 财务测算 + 监管合规 + 战略叙事 |
| **FDE 吃重阶段** | S1（快）+ S4 本体/设闸 + 产品化；S6 轻 | 全链 S1–S7；重在 S5 合规 + S6 可研 + 商业建模 |
| **HIL 命门** | 应用内裁定/质检闸 | 增收闸 + 监管发布闸 + 凭证闸 |
| **团队编成** | 轻：1 FDE + 平台/运行时组 | 重：1 主理 FDE(**Lv.3**) + N 见习(**Lv.1**) + 平台组 |
| **典型客户** | 区县级机关/机构（买"能用的应用"） | 地市级政企大盘（投建运/生态运营） |
| **代表案例（成熟度）** | 教育督导项目（🟢 建模全套+方案+47页真数据 Mock demo，本体未编译） | 康养项目🟢全域编译交付 · HR项目🟢建模+7类文书 · 学前教育项目🟢可研满配·建模半配 · 草业项目🟡方案+Mock demo+pilot本体 · 辣椒🟡方案+pilot本体·无demo |

> **一句话记忆**：模式一交付的是"**一个能用的智能体**"，模式二交付的是"**一套能自我运转的平台+生态**"。FDE 都能做，但**起手判断模式，决定你后面所有动作的轻重**。

## 四、逐案例卡片（案例=模式实例，成熟度据实分层）

### 🟩 模式一实例 · 教育督导项目（saihan-preschool，Token-SaaS 应用）

- **一句话**：某市某城区学前教育智慧督导——标准解码→全区 Gap 诊断→OKR 下钻区/园/师→材料上传实时质检的闭环智能体应用，目标提升全区评估名次。
- **事实成熟度**：充分，且**此前被本矩阵低估**（2026-07-27 复核上调）。用**与康养项目同一套 studio 管线**建模（event-storm 33 事件/3 画像李科长·张园长·王老师/7 热点 → domain-map 2 插件 13 skill → opportunity-brief，material-qc/standard-decode/gap-diagnose 为 P0），另有区教育局工作方案、79 园数据报告、区级督导平台产品方案、48KB PRD。**另有可运行 demo：47 个 `page.tsx` + 18 张成品截图。** 本体 OAG **未编译**（`status.json` phase=planning、无 compiled 目录）——须如实讲。
- **⭐ demo 可信度（本案例最有教学价值的一点）**：教育督导项目 demo 的 **AI 是 Mock（关键词路由），但数据是真的**——`lib/data.ts` 用 `fs.readFileSync` 直接读 79 园真实 CSV（7 张表：basic-facts/evaluation/checkpoints/puhui-status…），还支持多城市切换。**与草业项目的"全仿真数据"正好构成对照组**：同样是 Mock demo，可信度不是一档。讲 L7 时两个并排放，教学员分辨"壳假数据真" vs "壳假数据也假"。
- **⚠️ 数据口径**：全区园所数源内**不一致**（event-storm 99 所 / 热点·机会评估 124 园 / 数据样本 79 园），一律标"待区教育局核实"，不随手选一个当权威（B-5 活体）。
- **为什么是模式一**：交付物是**能用的督导 agent 应用**，卖给区教育局按用量赋能，不做自营运营盘、不需要百页可研。它的 HIL 命门（3 处裁定/质检闸）正是模式一的典型——**闸在应用内、判据仍是四条**。
- **课程角色**：模式一标本 + "同套建模管线跨行业成立"（康养→学前督导，方法不变、领域知识从医保 DIP 换成评估细则）+ 源材料自带诚实缺口（"预测置信度低""判例冷启动 30 例""数据未谈拢用 Excel 后备"）=跨案例 B-10 复调。

### 🟦 模式二标杆 · 康养项目（meizhou-kangyang，已交付）

- **一句话**：一名 FDE + 智能体编队完成 102 事件建模 → 7 域限界上下文 → 3835 行本体骨架 → 11 万字可研，传统需 5+ 人/数周。
- **事实成熟度**：**完整·全域本体已编译**（7 域 3835 行 py_compile 过）——**所有案例中唯一"全域编译并交付"的**。⚠️ 措辞注意：草业项目/辣椒也有 pilot 级编译本体，所以不能说"只有康养项目编译过"，要说"**只有康养项目编译到全域并交付**"。**3835 行口径 = compiled 下纯 .py**（连 yaml 一起数是 4303 行，两个数别混用）。
- **为什么是模式二**：1.36 亿城市级平台 + 微康养运营网络 60 站，投—建—运一体、有运营盘（三元支付/单店 21 月回本）、多端系统 + 百页可研。全链 S1–S7 都吃重。
- **课程角色**：贯穿十讲的深度主线；所有量化链条、SOP、HIL 判据、反例 B-1~B-10 均取自此案例。模式二"怎么做全"的标杆。

### 🟦 模式二实例 · 草业项目草业（app-grass，"某草业集团"，方案+demo 级）

- **一句话**：内蒙古草业集团（某草业集团）"草业大模型"——草种国产化 + 生态修复 + 碳汇变现的草业垂类大平台。产品名"草业项目"（"一问得方案"的问）。
- **事实成熟度**：**方案 + Mock demo + pilot 级编译本体**。1.0/2.0 两版方案（2.0 达 1698 行）+ **OAG/RAG 本体订正稿**（188 行，厘清"防幻觉靠 OAG 约束求解而非 Graph-RAG"）+ **11 页 Next.js demo**（7 角色可切换、带证据溯源块）+ deck + 投资 OnePager。规划 5 智能体（草育/草修/草易/草机/草碳）。

### 🟦 模式二实例 · 辣椒大模型（app-pepper，方案级）

- **一句话**：C-Life 辣椒大模型——"育-种-水-保-控-易-溯"辣椒精准种植全产业链垂类大平台。

- **一句话**：产教融合人力供需智能撮合平台（"龙城"即某工业城市别称），广西人才集团承建、自治区国资委主管、依托某工业城市公共技能实训中心，建设期 24 个月。素材在 `~/Codes/hr-dlink-plugins/`。
- **事实成熟度**：**完整建模 + 7 类文书全生命周期**（本体未编译、无 demo）。studio 套件齐全（event-storm / event-clusters / domain-model / domain-canvas / behavior-matrix / persona-insight / hotspot-ranking / 4 个 processes）+ **9 个插件的 skill-map**（linxi-core / policy-parser / data-harvester / talent-matcher / training-recommender / employment-monitor / major-advisor / outreach-optimizer / insight-report），9 个插件目录已落骨架。
- **⭐ 为什么必须进矩阵**：**全部案例中唯一覆盖「招标 ↔ 投标 ↔ 验收」闭环的**——7 类政府文书各有 md/docx/pdf 三格式：项目建议书(46KB)/可研(96KB)/建设方案(227KB)/初步设计(65KB)/**招标文件(61KB)/投标文件(88KB)/验收材料(71KB)**。康养项目和学前教育项目都只到可研，接不到投标与验收这两段。
- **课程角色**：L4 下半场教"业务域怎么切成插件"（9 个 skill-map 是最清楚的样本）；L6 教招投标文书族（配肖作仕写作专家，该 agent 定义就住在这个仓的 `studio/agents/writers/`）。

### 🟦 模式二实例 · 学前教育项目（liuzhou-preschool，可研满配·建模半配）· 2026-07-27 新增

- **一句话**：某工业城市学前教育数智服务平台 —— 政府投资类可研 + 单一来源采购论证 + 财评送审报价包（园所公益侧 / 家庭商业侧隔离）。素材在 `Plugins/liuzhou-preschool-plugins/`。
- **事实成熟度**：**S6/S7 端满配，S1–S4 端半配**。可研 **653KB / 44 分章** + docx(14.3MB) + pdf + figures manifest；**送审报价包 Z00–Z04 五件套 + 内部财评包 N01–N07 + NESMA 功能点估算表 + 基准清单差异报告 + 单一来源论证**；一手工勘调研表 + 4 份发明专利 + 1 份软著。
- **⚠️ 建模端的真实缺口（必须如实讲）**：**没有 `studio/` 目录**，只有 `可研报告/建模/event-storm.md`（≈42 事件 / 26 角色 / 5 闭环 / 7 热点）和 `本体建模总纲.md`（6 个限界上下文 D1–D6 + 3 道 HIL 闸）。**persona / journey / behavior-matrix / domain-canvas / ontology-map 全部不存在，本体也未编译。**
- **⭐ 它证明的一件事（L4 下半场结束时讲）**：**这个项目没做完整建模、没编译本体，照样交出了 653KB 可研和完整送审包。** 这是"L5/L6/L7 是分叉不是流水线"最硬的活证据——别让学员以为"不编译本体就不能写方案"。
- **课程角色**：L6 教"百页可研工厂"（44 章分章 + `_PLAN.md` + `_WRITING_BRIEF.md` 含 12 条合规红线 + figures manifest，是全部项目里最干净的样本）；L8 教财评/报价合规（唯一有"报价→财评预审→应答"完整闭环的案例）；`event-storm` 里把"园内营销"建模为 🚩 违规红旗、禁止建模为正常流程，是"合规红线怎么进模型"的现成教具。**但绝不能拿它教 L4 上半场 · 认知萃取——素材不支持。**

### ⭐ 模式二内洞察 · 通用底座 → 垂类特化（L2 实证）

辣椒与草业项目**不是各造一套**，而是**共用同一套通用智慧农业底座** `smart-agriculture`（12 域插件候选：agri-knowledge-base/field-sensing/soil-care/crop-growth/pest-disease/remote-sensing…）。底座 Persona 是通用农业角色（grower/agritech/admin），域名不含"辣椒/草/碳汇"字样；两垂类各自 fork 母范式、只在应用层特化（辣椒→7 智能体、草业→5 智能体）。
**这是 L2「平台 = 方法论的固化物」的活体**：模式二越重，越依赖把方法一次固化成底座、多垂类复用，FDE 才不必每个项目从零起。⚠️诚实补注：该底座本身也仅有 studio 规划件（skill-map/brief），**无 SKILL 实现、无编译本体**，同样停在规划态——别把"有底座规划"说成"底座已建好"。

## 五、这张矩阵教什么（按八课回收，用模式语言）

| 课 | 用矩阵的哪一块 | 教学点 |
|---|---|---|
| **L1** FDE 总论 | 两模式定义 + 整张矩阵的分层标注 | FDE 的第一个判断是"这是哪种交付模式"；断层形态跨模式一致、接缝落点不同。**矩阵自身即 B-10 示范**：据实分层、方案目标 vs 实测严格分区、Mock 不当产品、口径不一如实标 |
| **L2** 项目与工具 | 通用底座洞察 | 模式二越重越靠平台复用：smart-agriculture 底座 → 辣椒/草业项目特化；但**底座本身也停在规划态**，别把"有规划"当"已建好" |
| **L4 上半场** 认知萃取 | 辣椒/草业项目卡片 + 教育督导项目三件套 | 认知萃取跨行业可迁移；**该区园所数 99/124/79 三源不一是 B-5 活体** |
| **L4 下半场** 领域建模 | HR项目 9 插件 skill-map | 业务域怎么切成插件；每个插件都要能在项目描述里找到出处 |
| **L5** 本体 + 设闸 | 两模式 FDE 吃重行 + HIL 命门行 + grass/chili | **SOP 跨模式通用、可任意阶段停**（辣椒方案 / 草业项目方案+demo / 教育督导项目建模 / 康养项目编译）；**HIL 命门随模式迁移（应用内质检闸 → 增收/发布/凭证闸）但四判据不变**；chili 的 links=0 是"只建对象不建关系"的反面教具 |
| **L6** 文档工程 | 学前教育项目 653KB 可研 + HR项目 招投标全套 | 模式二额外吃重商业建模 + 合规栈（可研/财务/碳汇方法学）；**HR项目 是全部案例中唯一覆盖「招标↔投标↔验收」闭环的** |
| **L7** 原型开发 | ⭐**教育督导项目 vs 草业项目可信度对照组** | **别把外壳当交付**：草业项目 11 页 demo 跑的是 UI、智能是 Mock；教育督导项目同样 Mock AI，但数据是 79 园真实 CSV——**同一句"这是 Mock"，含金量差一档**。当场并排打开两份 `lib/data.ts` |
| **L8** 总结与沉淀 | 团队编成行 + 两模式商业化 | 模式一轻编成（1 FDE + 平台组）vs 模式二重编成（主理 + 见习 + 平台组 + 更重的商业/合规半径）；**C1 迁移力是 Lv.3 分水岭**。两模式对应两条商业化路径：SaaS 应用快跑起量 vs 平台大盘长周期赢单 |

> **L3 不用这张矩阵教案例成熟度**，它用的是三份**一手调研件原件**（某草业集团 / 辣椒 / HR项目）——**B-11 主场**看的是输入端的污染，不是产出端的成熟度。
