FDE 工作坊 · 工具实操主干总纲（T1–T8）

版本 v0.2 · 单轨（2026-07-27 由双轨合并而来） 定位：本文件是工作坊的唯一执行主干。主持形态见 00_FDE实战工作坊_主持手册.md；口径唯一真相源见 _WRITING_BRIEF.md；能力模型与反例库见 00_课程总纲.md。 一句话：九步十册，一册就是一次课。 讲师上课只开一份文件。

一、为什么是一轨，不是两轨

v0.1 的双轨结构（已废止）

v0.1 把课程分成两轨：执行轨（T1–T8 工具实操）+ 知识注入轨（旧 10 讲讲义）。

这个结构不是教学设计的结论，是资产妥协的结果——旧十讲已经存在（讲义 + 工作坊脚本 + 13 个课件 + 质检报告），双轨让旧资产原地不动就能接上新主干。

它自己坍缩了

写八份手册时，每份都把知识注入的要点复述了一遍（T4 的 DDD 三判据、T5 的 HIL 四判据、T8 的 L1/L2/L3 能力锚）。结果是同一份知识有了两个副本：手册里的摘要 + 讲义里的全文。

这正是本课程自己反对的 B-5（口径不单点，早晚漂移）。

而且从讲师视角看，代价很具体：上 T5 那一节要同时开三个文件（T5 手册 + 讲 6 讲义 + 讲 4c 分册）。一次课就该是一份东西。

v0.2 的合并原则

合并单位是“一次课”，不是“一份文档”。

量化依据：10 份讲义约 2400 行，其中要点/板书/证据/反例手册里大多已有，真正不可替代的只有 41 段「讲述脚本」（讲师原话级口播稿）。所以合并动作是： - 讲义的知识要点 → 并入对应册的「知识（讲什么）」节 - 讲义的口播稿 → 并入对应册的「讲师包 · 口播稿」节（原文照搬，不改写） - 讲义本体 → 归档到 讲义/_legacy/ - 13 个 slides 课件保留不动，在每册“讲师包”里写明本步调用哪几个

每一册的统一结构

一册 = 一次课 = 五段
 〇 本步一览      目标 / 前置 / 产出 / 时间盒
 一 知识（讲什么）  ← 吸收自旧讲义的要点、板书、康养项目证据、反例
 二 案例（看什么）  ← 真实项目"做对了长什么样"
 三 实操（做什么）  ← 命令 / 产物路径 / 验收
 四 checkout      ← 达标 / 警示对照表
 五 讲师包        ← 口播稿（原话级）+ 时间盒 + 用哪几个课件

三、各册在哪、教什么

总纲不复述各册内容——那正是 v0.1 双轨留下的“两个副本”问题。 每一步的命令、产物路径、验收表、翻车点、口播稿，全部只在对应册里，是唯一真相源。

见上方「十册索引」。每册自带：

〇 本步一览 → 一 知识（讲什么）→ 二 案例（看什么）
→ 三 实操（做什么）→ 四 checkout → 五 讲师包（口播稿 + 时间盒 + 课件指引）

讲师备课只需要读三样：本册手册 · _WRITING_BRIEF.md（口径）· 案例矩阵_跨项目对照.md（成熟度分层）。

四、排期建议（集训 5 天）

十册合计 ≈1020′（17h） + 每组 20′ 路演。一册 = 一次课，不要把两册压进同一个时段。

天 上午 下午

D2 T3 认知萃取（120′） T4 领域建模（120′）

  • 压缩档（3 天）：D1（T2+T1+T3）/ D2（T4+T5a+T5b）/ D3（T6 或 T7 择一 + T9 路演）。T8 降为演示、不动手。
  • 分散档（9 周）：每周一册 + 各组命题线上推进，配合在手真实项目——T5b/T6/T8 的产出需要真实项目承载，这一档最理想。

压缩时砍什么：优先砍 T7（原型可课后做）与 T8（沉淀可延后）。 T5a+T5b 绝不拆开跨天，更不能压缩——它是唯一产出“机器会强制执行的东西”的一步。
