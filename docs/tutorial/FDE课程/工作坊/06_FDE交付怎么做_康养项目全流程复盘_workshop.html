〇、开场（教练宣读，4′）

📌 本组命题推进（贯穿沙盘）：本讲请用本组认领的命题（见 _贯穿沙盘_分组命题.md）推进一步——产出 本组命题的七阶段交付 SOP + HIL 设点表（沙盘核心产出），沉淀进本组「贯穿工作簿」。下方的 💡 启发范例是标尺、不是模板：康养项目/教育督导项目/辣椒/草业项目做对了长这样，但你的命题城市/切口/规模不同，照结构做、别抄数字。

🎯 本坊目标：针对一个真实项目，产出 ① 套完七阶段的交付 SOP（每阶段有收口标准） + ② 一张 HIL 设点表（5–8 个真闸，每闸标：判据/谁按/按错代价）。

🧭 过程方法论（本坊用的 FDE 方法）：七阶段交付 SOP · HIL 四判据+一兜底闸 · 闸分两层（自动闸=引擎回滚 / 人工闸=HIL）。

📏 工作坊纪律（教练宣读） 1. 启发-执行：每步先点开“💡启发”看康养项目范例，再动手；不空想。 2. 时间盒：铃响即停，个人发言/小组讨论都守时。 3. 终止铃：教练铃响，讨论立即停，进下一步。 4. 停车场：争不出的挂 parking lot，会后再议，不占时间盒。 5. checkout：每阶段末对照输出与验收。

🙌 工作坊宣言（齐读）：完成大于完美 · 团队大于个人 · 共识大于对错。

二、输入材料（可直接发学员）

2.1 项目二选一

  • 选项 A（自选·强烈推荐）：你手上正在做/即将做的真实 To-G/To-B 项目——产出的 SOP 能立刻用上。
  • 选项 B（指定脱敏件）：暂无在手项目的用 2.2。

2.2 指定脱敏件：《某地级市“长者助餐+居家照护”数字化平台 · 客户诉求纪要（脱敏）》

脱敏说明：对标医养运营商 / 某地级市，无真实品牌地名，数字为教学设定。

客户背景：某地级市民政局 + 本地国资运营方，建“长者助餐+居家照护”平台，服务全市约 8 万 60 岁以上老人，一期覆盖 40 个社区助餐点。

客户原话（模糊意图，需你压成结构）： 1. “老人在助餐点吃饭能自动核销补贴，别让老人垫钱再报销。” 2. “独居高龄老人，想有个’预警’,出事了能及时知道。” 3. “民政要能看到全市助餐点运营情况，最好做个’一张图’。” 4. “有些老人多头补贴（高龄津贴+助餐+护理），想防重复。” 5. “补贴资格是动态的——老人去世/搬走，得及时停发。” 6. “AI 能不能给每个老人推荐合适的照护套餐，提升点营收？” 7. “数据要合规，老人信息不能乱用，民政发布的东西不能出错。”

已知约束：补贴涉财政资金、资格认定涉公安人口库比对；民政发布数据对社会公开、出错是政治事件；老人信息受个保法约束；运营方想用 AI 推荐提升营收，但熟人社区口碑敏感。

故意查不到的项（埋 B-10 场景）：该市“老年助餐补贴办法”本地文号、“政府购买居家养老服务清单及单价”文号、运营方内部“反重复报销风控 SOP”编号——都查不到。

2.3 随身工具卡（照抄可用）

  • 七阶段速记：S1 认知萃取 → S2 结构收敛 → S3 域切分 → S4 本体建模+设闸 → S5 合规治理 → S6 交付物工程 → S7 HIL 运行留痕（横切）。
  • HIL 四判据 + 一兜底（命中任一即插人）：①不可逆 ②涉钱 ③涉合规 ④跨组织 ⑤置信度兜底（模型不够确定，阈值占位 0.75）。
  • 闸分两层：能固化成硬规则的 → 自动闸（引擎确定性回滚）；判不了/涉钱涉合规的 → 人工闸 HIL。

三、分阶段脚本（每步：🔔任务 / 🔔输出 / 🔔难点 + 💡启发范例）

阶段一 · 套七阶段交付 SOP（24′）

步骤① · 选项目、定交付（3′）

🔔 任务：A/B 二选一定下来，一句话写清“这个项目要给谁交付什么”。 🔔 输出：一句话项目定义（如“给某市民政局交付一个助餐+居家照护平台的可研+建设方案”）。 🔔 难点/注意：别写成愿景口号，写成“交付物 + 收件人”。

💡 启发 · 点开看康养项目范例

康养项目一句话定义：“给嘉城数联合资公司交付一份康养行业大模型+微康养生态运营平台可行性研究报告（11 章/26 图）+ 7 域可运行本体骨架，用于立项与二期建设。”——收件人明确、交付物形态明确、用途明确。

步骤② · 逐阶段套七阶段 SOP（21′）

🔔 任务：用模板 4.1，逐阶段填你项目的具体内容 + 收口标准（做到什么才算这阶段完）。 🔔 输出：七阶段 SOP 表，每阶段都有一条可打勾判定的收口标准。 🔔 难点/注意：收口标准是评分重点，别写“做好为止”这种不可判定语。S2 想清“营收/价值命门是谁”；S3 想清“共享根实体是谁、真相源域是谁”。

💡 启发 · 点开看康养项目范例（S1/S3/S4 三段）
  • S1 认知萃取：站点端五角色+机构长+民政 七视角事件风暴；一手数据=368 份问卷校准画像；价值命门事件=E59 站长 HIL 增收。收口标准：102 事件可归域、每个画像特征指得到数据来源。
  • S3 域切分：切成 7 域 D1–D7；共享根=Elder（canonical 在 D4，单写入点）；真相源=D2 结算枢纽。收口标准：A 结构 7/7 零悬空引用、无 Action 越域直写他域对象。
  • S4 本体建模+设闸：五要素 76/75/38/47/54；设 26 个 HIL 闸。收口标准：HIL 设点表成型 + py_compile 通过。

阶段二 · 建 HIL 设点表（30′，本讲核心交付物）

步骤③ · 列决策点、逐个过五判据（25′）

🔔 任务：用模板 4.2，把项目里所有“该插人”的决策点列出来，每个逐列填：命中哪几条判据 / 谁按 / 按错代价。先问“能不能固化成自动闸”，固化不了、要价值判断的才上 HIL。 🔔 输出：HIL 设点表 5–8 行，判据打勾、责任岗位具体、按错代价写到场景。 🔔 难点/注意：“按错代价”要具体到场景+受害主体+可逆性，不能写“会出错/有风险”。别漏涉钱/涉合规的关键闸，也别给无风险动作滥设闸。

💡 启发 · 点开看康养项目/脱敏件范例（两行）
决策点 判据命中 谁按 按错代价
AI 套餐推荐转订单 涉钱 + 跨组织 + 置信兜底(0.75) 站长/健管师 低置信方案被机械点过 → 卖错套餐给熟人 → 毁片区信任飞轮（可逆但伤口碑）
民政数据对外发布 涉合规+涉钱+跨组织 三中 民政经办签字背书 未核验数据发出 → 违反个保法最小必要/错发补贴 → 不可逆、政府信用受损（DP-H 场景）

看范例的两个要点：① 判据可多中，命中越多越危险；② 代价写清“谁受害 + 可不可逆”。

步骤④ · 标最危险的闸 + 自查兜底闸（5′）

🔔 任务：在表末标注“如果只能保住一个闸，保哪个、为什么”；并自查有没有一个“四判据都不强命中、靠置信兜底设的”闸。 🔔 输出：最危险闸 + 兜底闸自查结论。 🔔 难点/注意：判据命中最密的通常就是最危险的闸；一个兜底闸都没有，往往是漏了“高频低置信”动作。

💡 启发 · 点开看康养项目范例

康养项目最危险闸 = 民政 DP-H 发布闸（涉合规+涉钱+跨组织三中，且发布不可逆）。兜底闸 = 站长置信度闸 0.75（hard·function·pre）——AI 增收方案四判据里“涉钱”命中，但真正拦住“高频低置信机械点过”的是那道置信兜底，防橡皮图章。

阶段三 · 两两互评 checkout（8′）

步骤⑤ · 换桌互评（8′）

🔔 任务：和同桌交换 SOP + HIL 表，用第四节 checkout 对照表互评，各自记下对方指出的最大一个漏洞。 🔔 输出：互评记录 + 我要回去补的最大漏洞 1 条。 🔔 难点/注意：互评别客气，重点盯“漏了哪个涉钱/涉合规的闸”“哪条按错代价是空话”。

四、checkout（验收对照表 · 原评分卡转“达标/警示”）

每阶段末 + 收尾各对照一次。四维，每维看“达标线”与“一票警示”。

维度 ✅ 达标线 ⚠️ 警示（踩了要回炉）
D1 SOP 完整可套用 七阶段全、收口标准可打勾判定、换项目也能套 阶段缺失，或收口写成“做好为止”这类不可判定语
D2 设闸判断质量（核心） 5–8 个真闸、判据命中准、能说清“哪些该自动闸/哪些该 HIL” 漏掉涉钱/涉合规关键闸，或给无风险动作滥设闸
D3 按错代价具体性 代价写到 场景+受害主体+可逆性（像两大闸门那样） 代价写成“会出错/有风险”空话
D4 诚实边界与收口纪律 查不到的项留占位转取证清单、点出至少一处并行收口风险(B-1/B-2/B-5) 编造文号/数据、无任何收口纪律意识

评级参照：四维全达标 = L2 胜任（可独立设闸、交付物一次复核）；主要闸设到但需复核 = L1 见习；漏关键闸或踩 B-10 编造 = 回炉。 一票警示：查不到的文号编了一个 —— 无论其他维多好，本坊不通过（这是 C7 价值判断的现场测验）。

五、复盘研讨（3 题，教练收口，36′）

  1. （设闸判断） 你表里有没有“四判据都不强命中、但你还是设了闸”的决策点？为什么？一个都没有，是不是把置信兜底闸忘了？
  2. （橡皮图章） 假设某个闸的责任人每次都点“同意”，这闸还有用吗？怎么从机制上防它退化成橡皮图章？（提示：置信度闸/抽检/留痕追责）
  3. （诚实边界） 查不到、核不实的文号/数据，你会编一个让交付显得完整，还是留占位转取证清单？怎么跟客户解释这个空缺？

教练收口锚点：题 1 指向“高频低置信”用置信兜底（康养项目 0.75）；题 2 闸的价值在“会不会真拦”（康养项目 hard·pre+0.75）；题 3 回收 “错文号比空缺更有害”——敢留占位是 L2 潜质，想编的当场点名（C7 训不出、只能筛）。

六、参考答案要点（讲师版 · 标“讲师专用勿发学员”）

⚠️ 讲师专用，勿发学员。以脱敏件（选项 B）为例，学员自选项目按同逻辑评判。

七阶段 SOP 参考骨架：S1 民政/运营/助餐点/家属四视角事件风暴，价值命门=独居预警升级+AI 套餐转单｜S2 P1 助餐核销+防重复、P2 居家预警、P3 AI 增收、P4 民政一张图｜S3 助餐结算域(真相源=D2)、居家照护域(Elder canonical=D4)、民政治理域(发布闸=D6)、AI 推荐域(D1/D3)、政策库(D7)，共享根=老人 elder_id 单写入｜S4 补贴核销/预警升级/资格停发/防多头/套餐转单/数据发布，设 6+ 闸｜S5 挂 DIP/长护/个保法/数据安全法/助餐行动方案（可核），本地助餐办法/政府购买清单/内部反重复 SOP 文号→查不到→留占位转取证清单（B-10 考点）｜S6 锚定口径文件必有，收口无口径/编号/计数漂移｜S7 预警升级/数据发布设 pre 前置闸。

HIL 设点表参考解（6 个应出现的闸，缺一扣 D2）：

决策点 判据命中 谁按 按错代价
补贴自动核销 涉钱+涉合规 助餐点站长/财务复核 错核销→财政资金错付→追缴是政治事件
独居预警升级 不可逆+跨组织 健管师/应急指挥 漏升级→老人出事不可逆；误升级→挤占应急资源
资格动态停发 涉钱+涉合规+跨组织 民政经办(需公安库比对) 该停未停→继续错发公帑；误停→老人断补贴投诉
防多头补贴拦截 涉钱+涉合规 前置规则层+民政经办抽核 漏拦→重复领补贴→审计问责（对标康养项目反重复引擎前置）
AI 套餐推荐转单 涉钱+跨组织+置信兜底 站长/健管师 低置信机械点过→卖错套餐→毁熟人口碑（橡皮图章场景）
民政数据对外发布 涉合规+涉钱+跨组织三中 民政经办签字背书 未核验数据发出→违个保法/错发补贴→不可逆、政府信用受损（DP-H）
  • 加分点：识别“防多头补贴”应像康养项目 D2 前置到规则层/自动闸（不是纯人工点）；识别“民政发布”是判据最密的闸、应作“最危险的闸”。
  • 常见扣分点：民政发布只标涉合规一条（实为三中）→ D2 扣；按错代价写空话 → D3 扣；查不到文号编了一个 → D4 一票警示、当场引 B-10；收口标准写“做好为止” → D1 扣。
