〇、开场（教练宣读，4′）

📌 本组命题推进（贯穿沙盘）：本讲请用本组认领的命题（见 _贯穿沙盘_分组命题.md）推进一步——产出 本组命题走一遍管线，产出一节方案稿 + 一张配图占位，沉淀进本组「贯穿工作簿」。下方的 💡 启发范例是标尺、不是模板：康养项目/教育督导项目/辣椒/草业项目做对了长这样，但你的命题城市/切口/规模不同，照结构做、别抄数字。

🎯 本坊目标：走完五道层间交接口，产出 一条贯通记录 —— 从 1 个事件，经流程节点 → 本体五要素 → 一节营收正文（约 200 字）+ 1 个合法图占位，且自检无 B-3 式 slug 断裂、无 B-8 式跨域越写。

🧭 过程方法论（本坊用的 FDE 方法）：五道层间交接口（认知→流程→本体→正文→呈现）· 跨域纪律（画像 canonical 在 D4 / 结算汇 D2 / 越域一律 ref）· 图占位契约（slug 先定后画）· 两条质检线（内容质检有校验器帮一半 / 格式质检只能 FDE 亲走）。

📏 工作坊纪律（教练宣读） 1. 启发-执行：每步先点开“💡启发”看康养项目范例，再动手；不空想。 2. 时间盒：铃响即停，个人跑通/同桌互检都守时。 3. 终止铃：教练铃响，讨论立即停，进下一步。 4. 停车场：争不出的挂 parking lot，会后再议，不占时间盒。 5. checkout：每阶段末对照输出与验收。

🙌 工作坊宣言（齐读）：完成大于完美 · 团队大于个人 · 共识大于对错。

本坊要你亲手当一次“层间接口的唯一负责人”：数据从 event 一路流到图占位，任何一道接口掉了数据，最终交付物就断在那里。

二、输入材料（可直接发学员）

2.1 mini 场景（取自康养项目会员飞轮真实入口，已缩小）

场景：长者食堂获客到店转化。 康养站点办“长者食堂/助餐”（对应康养项目事件 E45/E46），是三大到店获客入口之一（另两个是义诊 E38、老带新 E03）。一位长者因助餐首次到店，站点希望把他从“仅体验”转化为“会员并交叉复购”（中医理疗 / 康养商城器械）。本场景归属 D3 会员营收飞轮域。

2.2 你可以直接借用的康养项目真实结构（照抄口径，勿另造）

  • 会员飞轮流程决策点（6+1，每个 = 一个 skill 边界）：D1 命中试做 · D2 转化 or 流失 · D3 分层定价（≤200 走量 vs 500–1500 溢价）· D4 交叉推荐命中 · D5 持续复购 · D6/D6b 进召回。
  • 三条营收线咬合：中医理疗（E40）+ 长者食堂/助餐（E45/E46）+ 康养商城/器械（E52/E53/E54）。
  • 三元支付口径：自费为主，仅助餐 E45/E46 挂政府购买补贴。
  • 跨域纪律：画像 canonical 在 D4 不分裂；结算一律汇 D2；越域一律 ref/发布，不越界 stage_write。
  • D3 本体参考规模：10 Object / 11 Link / 6 Function / 6 Rule / 7 Action（你只需产出其中很小一部分）。

2.3 图占位契约（必须遵守，否则当场制造 B-3）

  • 写法：![图7-X 图名](../figures/fig-7-X-<slug>.png)，下一行 **图 7-X 图名**，再 2–4 句图说。
  • slug 先定后画：你在正文里声明的 slug，必须和你在交付物末尾“图清单”里登记的 slug 逐字一致。本演练不实际画图，但 slug 契约要对得上——这是你现场规避 B-3（图片路径断裂） 的动作。

三、分阶段脚本（每步：🔔任务 / 🔔输出 / 🔔难点 + 💡启发范例）

阶段一 · 个人跑通五道交接口（25′）

步骤① · 接口 0 认知捕获 · event（5′）

🔔 任务：从场景里抽出 1 个核心业务事件，写成“E编号 + 一句话”（可复用 E45 助餐到店，或自拟一个），记下它属于哪个获客入口。 🔔 输出：接口 0 一行——事件 E编号 + 一句话 + 获客入口（义诊/老带新/助餐三选一）。 🔔 难点/注意：事件要是一个可被后续挂到流程决策点的具体动作，不是一句愿景。

💡 启发 · 点开看康养项目接口 0 范例

E45 长者助餐到店，入口 = 助餐（三大到店获客入口之一，另两个义诊 E38、老带新 E03）。这就是一条 mini 链的起点——从义诊/助餐到店 E38/E45，一路走到可研一节，就是本讲“认知到行动 = OAG”的缩影。

步骤② · 接口 1 event → 流程节点（6′）

🔔 任务：把事件挂到会员飞轮流程上，用 2.2 的 6+1 决策点，指明它触发了哪些决策点（至少落 2 个），说明每个决策点为什么是一个 skill 边界。 🔔 输出：接口 1 两条——≥2 个决策点 + 每个“为什么是 skill 边界”的理由。 🔔 难点/注意：skill 边界的判据是“逻辑与数据源不同、可独立演进”，不是“看起来是两步”。

💡 启发 · 点开看康养项目接口 1 范例

E45 触发 D2 转化or流失（判断这位长者是转会员还是仅体验流失）+ D4 交叉推荐命中（助餐画像 → 推中医理疗）。二者是 skill 边界，因为一个管“转化判定”、一个管“交叉推荐引擎”，逻辑与数据源不同，切成两个 skill 可独立演进。

步骤③ · 接口 2 流程 → 本体五要素（8′）

🔔 任务：把决策点落成 D3 域的本体要素——至少产出 1 Object + 1 Action + 1 Rule。Action 若涉及转化/下单，遵“结算汇 D2、画像读 D4”的跨域纪律，用 ref 不越域写。 🔔 输出：接口 2 三要素——Object（带属性）+ Action（标清跨域 ref 落点）+ Rule（挂 citations/口径）。 🔔 难点/注意：这是最容易撞 B-8 的一步——图省事让 Action 直接 stage_write D2 结算对象或 D4 画像对象，就制造了越界。画像 canonical 在 D4 不分裂、结算汇 D2，越写就是悬空/越界。

💡 启发 · 点开看康养项目接口 2 范例（守住跨域纪律）
  • Object = MembershipTrialVisit（属性：elder_id ref→D4、entry=助餐、trial_date）；
  • Action = convert_to_member（转化成功→发布 ServiceOrder 给 D3、结算 ref→D2、画像 ref→D4，绝不 stage_write D2/D4 对象）；
  • Rule = 分层定价双档（≤200 走量 / 500–1500 溢价，按片区画像动态，挂三元支付口径）。

7/7 零悬空就是这么一条条守出来的——跨域一律 ref/发布，你越写就制造了 B-8。

步骤④ · 接口 3 本体 → 一节正文（6′）

🔔 任务：从本体要素写出可研营收章节的一节正文，约 200 字，把“三条营收线咬合”的结构讲清楚。每个论断后跟一个康养项目数字或口径。 🔔 输出：接口 3 正文约 200 字，须体现“三条营收线咬合 / 三元支付 / 分层定价双档”至少一项作为数字锚。 🔔 难点/注意：别写空话。“通过精细化运营提升转化”这类没有康养项目数字的句子，就是证据密度红线的反面。每个论断挂一个口径。

💡 启发 · 点开看康养项目接口 3 数字锚清单

正文里可当数字锚的口径：三条营收线咬合（理疗 E40 + 助餐 E45/E46 + 商城器械 E52/E53/E54）；三元支付（自费为主、仅助餐挂政府购买补贴）；分层定价双档（≤200 走量 / 500–1500 溢价）；付费意愿可引 368 份问卷校准。至少出现其中一项，正文才算“有证据密度”，否则 D4 判低分。

步骤⑤ · 接口 4 呈现（图占位 + 图清单登记）（融入步骤④）

🔔 任务：在正文合适处插入 1 个合法图占位（遵 2.3 契约），并在末尾登记图清单，slug 逐字一致。 🔔 输出：接口 4 图占位 + 图说 2–4 句 + 图清单 slug 登记，正文占位 slug 与图清单 slug 逐字相同。 🔔 难点/注意：slug 先定后画。正文写 fig-7-1-飞轮转化、图清单却登记成 fig7-1-飞轮 或事后改了图名，就是 B-3——真实导出这里静默丢图，docx 照样生成、管线全绿，客户翻到这页才发现。

💡 启发 · 点开看康养项目接口 4 范例

![图7-1 会员飞轮三入口转化](../figures/fig-7-1-飞轮转化.png)，下一行 **图 7-1 会员飞轮三入口转化**，图清单登记 slug = fig-7-1-飞轮转化，与正文占位逐字一致。占位符即契约——slug 先定后画，这就是现场规避 B-3 的动作。

步骤⑥ · 自检两条质检线（融入末尾）

🔔 任务：过一遍“内容质检”和“格式质检”（见 2.4 模板末尾），确认无 slug 断裂、无跨域越写。 🔔 输出：两条质检线打勾，标出哪些是校验器能帮的、哪些只能靠眼睛。 🔔 难点/注意：内容质检有校验器帮你一半，格式质检一个字都没人帮你——slug 一致、导出验图、Word 主题色不覆盖浅色配图（B-4），只能 FDE 亲眼看。

💡 启发 · 点开看两条质检线的标准清单
  • 内容质检线（部分可被校验器覆盖）：数字锚单点不自造（防 B-5）、跨域 ref 不越写（防 B-8，quality 结构校验能抓）、引用 citations 挂对（能核）。
  • 格式质检线（校验器守不住，只能 FDE 亲走）：占位 slug 与文件名一致（防 B-3）、导出后逐张验图不丢、Word 主题色不覆盖浅色配图（防 B-4）、排版/字体对齐客户模板。
  • 收口一句：“内容质检有校验器帮你一半，格式质检一个字都没人帮你——26 张图你得亲眼看 26 遍。这就是为什么 FDE 是层间接口的唯一负责人。”

阶段二 · 同桌互检层间接口（10′）

步骤⑦ · 换手互检（10′）

🔔 任务：和同桌交换贯通记录，逐道接口对照第四节 checkout 互检，重点盯“哪道接口掉了数据”“有没有越域写”“slug 对不对得上”，各自记下对方最大一处断层。 🔔 输出：互检记录 + 我要回去补的最大一处断层 1 条。 🔔 难点/注意：互检别客气，专抓 B-8 越域写和 B-3 slug 断裂这两处“当场制造反例”的动作。

阶段三 · 全班挑 2 组过链路（9′）

步骤⑧ · 公开过链路（9′）

🔔 任务：教练挑 2 组，从接口 0 到接口 4 完整口述一遍链路，全班对照 checkout 找断点。 🔔 输出：两条链路公开复盘 + 每条一个可迁移的教训。 🔔 难点/注意：口述时重点验“数据可追溯地从 event 流到正文+图占位，无断层”。

阶段四 · D7 产品 demo 原型（60–120′，可延伸/课后）

承接阶段一的 D5 交付物成文（一节稿 + 图占位）——再往产品化前推一步：把本组命题做成一个可点开的交互原型/外壳，让方案有“应用形态”。但这一步最容易翻车：demo 跑通的是 UI，不是模型；把外壳当成“产品跑通了”去演示，就是骗客户。本阶段的核心纪律就是诚实标 Mock。

步骤⑨ · 搭本组命题的可点开 demo 外壳（50–110′）

🔔 任务：把本组命题做成几屏可点开的交互原型——模式一（Token-SaaS 应用，如教育督导项目/草业项目类）做应用主界面几屏（会员/督导/工作台/证据溯源…）；模式二（大平台）做关键几屏/驾驶舱（一张图/核心闭环）。工具不限：低代码 / Pencil / AI 生成 HTML 原型均可。屏与屏之间能点跳转即可，别追求真数据。 🔔 输出：一个可点开的 demo 原型（3–6 屏）+ 一句诚实说明——白纸黑字写清“这是交互外壳、AI 为 Mock（关键词路由/写死数据）、非模型跑通”。 🔔 难点/注意：别把外壳当交付——demo 跑通的是 UI 不是模型。演示时必须先说清哪些是 Mock（哪屏的“AI 回答”是写死的、哪块数据是假的），再展示交互。把 Mock 藏起来当真跑通演示 = 撞讲 7 反面警示 + 讲 9 诚实边界，一票警示。

💡 启发 · 点开看 demo 成熟度标尺（草业项目）+ 诚实注（教育督导项目）
  • 标尺（草业项目 🟡 方案 + Mock demo）：草业项目做了 11 页 Next.js demo，7 个角色可切换、界面里带证据溯源块（点开能看“这条结论挂了哪些来源”）——完成度足以让客户点着走一遍流程。但它的 AI 是 Mock：关键词路由 + 写死回答，不是真模型跑通。这就是你的目标形态：外壳做到能点、能演一条完整用户流，同时诚实标 Mock。
  • ⚠️ 诚实注（教育督导项目 🟢 建模 + 方案·无 demo）：教育督导项目只做到“产品方案 + 数据报告”，并没有可跑通的 demo。所以别拿“教育督导项目都做了产品”当借口把外壳吹成产品——我们各组做的也只是“交互外壳（Mock）”，成熟度诚实标：外壳 ≠ 模型跑通。
  • 一句话：demo 的价值在“让客户看见应用长什么样”，不在“证明模型能跑”——这两件事说混了，就从演示变成了欺骗。

四、checkout（验收对照表 · 原评分卡转“达标/警示”）

每阶段末 + 收尾各对照一次。四维，每维看“达标线”与“一票警示”。

六、参考答案要点（讲师版 · 标“讲师专用勿发学员”）

⚠️ 讲师专用，勿发学员。

一条标准贯通链示范（供对照，学员不必完全一致）： - 接口 0：E45 长者助餐到店，入口 = 助餐。 - 接口 1：触发 D2 转化or流失（判断这位长者是转会员还是仅体验流失）+ D4 交叉推荐命中（助餐画像 → 推中医理疗）。二者是 skill 边界，因为一个管“转化判定”、一个管“交叉推荐引擎”，逻辑与数据源不同，切成两个 skill 可独立演进。 - 接口 2：Object = MembershipTrialVisit（属性：elder_id ref→D4、entry=助餐、trial_date）；Action = convert_to_member（转化成功→发布 ServiceOrder 给 D3、结算ref→D2、画像ref→D4，绝不 stage_write D2/D4 对象）；Rule = 分层定价双档（≤200 走量 / 500–1500 溢价，按片区画像动态，挂三元支付口径）。 - 接口 3：正文须出现“三条营收线咬合（理疗+助餐+商城器械）”“三元支付：自费为主、仅助餐挂政府购买补贴”“分层定价双档”至少一项作为数字锚。 - 接口 4：![图7-1 会员飞轮三入口转化](../figures/fig-7-1-飞轮转化.png)，图清单登记 slug 与之逐字一致。

必须抓的三类现场错误： - 越域写（撞 B-8）：学员图省事让 convert_to_member 直接写 D2 结算对象或 D4 画像对象。当场用第 5 讲 B-8 纠正：“跨域一律 ref/发布，画像 canonical 在 D4 不分裂、结算汇 D2，你越写就制造了悬空/越界，7/7 零悬空就是这么守出来的。” - slug 断裂（撞 B-3）：正文占位写 fig-7-1-飞轮转化，图清单登记写成 fig7-1-飞轮 或事后改了图名。当场演示：“真实导出这里就静默丢图，docx 照样生成、管线全绿，客户翻到这页才发现——这就是 B-3。占位符即契约，slug 先定后画。” - 空洞无证据（撞证据密度红线）：正文写“通过精细化运营提升转化”这类没有康养项目数字的空话，判 D4 低分。要求每个论断挂一个口径（三元支付/分层定价/368 份问卷校准出的付费意愿等）。

两条质检线的标准清单（发给学员当模板）： - 内容质检线（部分可被校验器覆盖）：数字锚单点不自造（防 B-5）、跨域 ref 不越写（防 B-8，quality 结构校验能抓）、引用 citations 挂对（能核）。 - 格式质检线（校验器守不住，只能 FDE 亲走）：占位 slug 与文件名一致（防 B-3）、导出后逐张验图不丢、Word 主题色不覆盖浅色配图（防 B-4）、排版/字体对齐客户模板。 - 收口一句：“内容质检有校验器帮你一半，格式质检一个字都没人帮你——26 张图你得亲眼看 26 遍。这就是为什么 FDE 是层间接口的唯一负责人。”
