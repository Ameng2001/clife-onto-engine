# 动手环节设计 · 目标反推（先定产出，再对齐工具与课件）

> ⚠️ **本文件是 v0.2 时期的设计推导记录**（"先定交付物、再倒推需要哪些步骤"），**不是现行授课口径**。
> 内部仍按 **T1–T8** 编号——**刻意保留**：改成 L 编号会篡改历史，让人误以为当时就是按八课设计的。查阅时按 `00_课程总纲.md` 第九节的对照表换算。
> 它记录的是**决策过程**（为什么 T2 没有交付物却不可省、为什么 v1 的 D2 被拆开），改课时值得先读一遍再动结构。

> 方法：不按"每讲配一个动手"，而是从**工作坊最终交付物**倒推——先定"每组结课要交什么"，再看**哪个工具产出它**、**哪一讲供给做它所需的知识**。
>
> **版本说明**
> - v1（2026-07-26）：结论是 **7 个动手环节 D1–D7 + 认领 + 路演**，动手挂在讲 4/6/7/8/10 上，其余五讲作研讨。
> - **v2（2026-07-27）· 现行**：改按**双轨重构**——执行主干换成 **T1–T8 八步工具实操**，旧 10 讲整体降为**知识注入**。
>   **变化的本质**：v1 是"在十讲里挑出哪几讲能产出交付物"，v2 是"**按工具链排主干，让十讲去供给它**"。倒推方法没变，被倒推的对象从"讲"变成了"工具步骤"。

## 一、工作坊目标 → 最终交付物

**目标**：每组把**本组命题**走完一遍 FDE 交付流程，结课交出一份「**迷你 FDE 交付包**」。

| # | 交付物 | FDE 阶段 | **由哪一步产出** |
|---|---|---|---|
| 1 | 一句话项目定义 + **交付模式判定** | 立项 | **T1** |

| 3 | **限界上下文域图** | S3 域切分 | **T4** |
| 4 | 一个核心域的**五要素本体草案** | S4 本体建模 | **T5** |

> 同样一句"这是 Mock"，含金量差一档——T7 手册第五节有三档自评表。

## 二、反推结果：八步各产出什么

> 判据没变：**一个步骤存在，当且仅当它产出交付包里的某几件，或它是后续步骤的必要前置。**

| 步 | 产出（进交付包） | 覆盖 | 时间盒 |
|---|---|---|---|
| **L3 信息采集** | 一句话定义 + 交付模式判定 + `domain-intake` 契约 | ① | 90′ |
| **L2 项目与工具** | —（**必要前置**：可用工具链 + `studio/` 工作区） | — | 60′ |
| **L4 上半场 · 认知萃取** | 画像 ≥3 / 旅程 ≥2 / 流程 ≥2 / 热点分层 | ② | 120′ |
| **L4 下半场 · 领域建模** | 限界上下文域图 + `skill-map`（喂 L8） | ③ | 120′ |
| **L5 上半场 · 本体建模** | 五要素本体草案（七段 IR + 编译骨架 + 收尾 6 项清单） | ④ | 90′ |
| **L5 下半场 · 设闸与治理** | HIL 设点表 + 取证清单 + SOP 成文 | ⑥⑦⑧ | 90′ |
| **L6 文档工程** | 写作专家 + 商业模式与财务语言 + 一节方案稿 + 配图占位 | ⑤⑨ | 150′ |
| **L7 原型开发** | 3–6 屏可点开原型 + **Mock 清单** | ⑪ | 120′ |
| **L8 能力沉淀** | 团队编成草案；可发版插件（加分） | ⑩a⑫ | 150′ |
| **L8 结课路演** | 90 天启动计划 + 拼合 11 件、20′ 答辩（含 demo 演示 + 诚实说明） | ⑩b + 全 | 120′ + 每组 20′ |

**= 8 个步骤，交付包 11 件全部有归属、不重不漏，另加 1 件加分项。**

**与 v1 的两处实质差异**：
1. **T2 没有交付物但不可省** —— v1 的判据"不产交付物就不设动手"会把它筛掉，但**它是所有后续步骤的前置**。判据因此补了半句"或它是后续步骤的必要前置"。
2. **v1 的 D2 被拆开了** —— 原本"结构与本体"合在一个环节（域图 + 本体草案），现在分给 T4（域图）与 T5（本体）：**用的是两个不同的工具，中间还隔着一个分叉点**（见下）。

## 三、⭐ T4 之后是分叉，不是流水线

```
T2 → T1 → T3 → T4 ─┬─ T5 本体+设闸    （要"可执行的规则与闸"）
                    ├─ T6 文书          （要"可评审的文档"）
                    ├─ T7 原型          （要"看得见的应用形态"）
                    └─ T8 插件沉淀      （要"下个项目能复用的能力"）
```

**它们并行、不互为前置。**

**活证据**：**学前教育项目**项目**没做本体建模、没有 persona/journey**，照样交出 653KB 可研 + 完整送审报价包 + 单一来源论证。

> 所以排课顺序 T5→T6→T7→T8 是**教学顺序**（由难到易、由内到外），不是依赖顺序。
> 真实项目按**交付模式**决定先走哪条：模式二 To-G 大盘 → T6 优先；模式一 SaaS → T5+T7 优先。

## 四、对齐知识注入：哪一讲供给哪一步

| 步 | 主供知识（沉浸） | 案例启发标尺 |
|---|---|---|
| T2 | **讲5**（平台=方法论固化物，压缩 20′） | fund-review：某工业城市项目反向沉淀出插件 |
| T1 | **讲1 交付断层 + 讲2 认知杠杆** | HR项目（模板A）/ 辣椒·草业项目（模板B）；**B-11 主场** |
| T3 | **讲4 栈①**（Persona/旅程/机会矩阵） | **教育督导项目**（persona/journey/process 三件唯一齐全） |
| T4 | **讲4 栈②**（DDD） | 康养项目 7 域 / **HR项目 9 插件切分** |
| T5 | **讲4 栈③（OAG）+ 讲6（SOP+HIL，180′ 重心）** | 康养项目 26 HIL / grass 完整插件 / chili 反面（links=0） |
| T6 | **讲4 栈⑥⑦**（交付物工程 / 合规治理） | **肖作仕**写作专家 / 学前教育项目 653KB 可研 / HR项目 招投标全套 |
| T7 | **讲7 残余 + 讲9 诚实边界** | 教育督导项目（数据真）vs 草业项目（全仿真）**可信度对照组** |
| T8 | **讲5 回收（三层固化）+ 讲8 团队编成** | fund-review → 插件；L1/L2/L3 能力锚 |
| 路演 | **讲3 OPC 边界 + 讲10 C-Life 落地** | — |

**旧 10 讲的去向**：讲 1/2 → T1；讲 3 → 路演前收口；讲 4 四分册 → 拆入 T3/T4/T5/T6；讲 5 → T2 开场 + T8 回收；**讲 6 → T5（保留 180′ 核心地位）**；**讲 7 → 被 T1–T8 全面吃掉，降级为一页「工具全景导览」**；讲 8 → T8；讲 9 → T7；讲 10 → 路演。
