〇、开场（教练宣读，2′）

📌 本环节为研讨环节（不产交付包物件）——本讲就本组命题做启发式研讨，产出记进工作簿的“思考”区即可，不强塞交付物。下方的 💡 启发范例是标尺、不是模板：康养项目/教育督导项目/辣椒/草业项目做对了长这样，帮你把研讨聊到点子上、照结构想，别抄数字。

🎯 本坊目标：就本组命题研讨清楚 ① 这条交付链的断层出在哪（信息衰减接缝在哪、掉了什么、返工与账记谁头上）+ ② “一个人贯通”能消哪几道断层、哪几道消不了只是搬成时间压力——产出是研讨观点 / 一句话共识，记进工作簿“思考”区，不必交出成型物件。

🧭 过程方法论（本坊用的 FDE 方法）：全链贯通视角 · 交付断层三类根因（A 意图未全文档化 / B 工序本位优化 / C 求全式断层）· 保真度跌落折线 · FDE 反事实推演。

📏 工作坊纪律（教练宣读） 1. 启发-执行：每步先点开“💡启发”看康养项目范例，再动手；不空想、不跳过范例。 2. 时间盒：铃响即停，个人绘制/两两互检都守时。 3. 终止铃：教练铃响，讨论立即停，进下一步。 4. 停车场：争不出的挂 parking lot，会后再议，不占时间盒。 5. checkout：每阶段末对照输出与验收标准。

🙌 工作坊宣言（齐读）：完成大于完美 · 团队大于个人 · 共识大于对错。

二、输入材料（可直接发学员）

2.1 康养项目对照样例（正例：贯通消除断层）

康养项目平台的认知侧交付链，由 1 名 FDE + 智能体编队走完，无跨人接缝：

客户模糊意图
  └─(同一大脑)→ 102 业务事件 → 16 事件簇 → 7 角色画像
     → 7 用户旅程 → 5 业务流程 → 10 热点(P1–P5)
     → 7 域限界上下文 D1–D7 → 3835 行插件骨架
     → 11 章/~11 万字/26 图 可研报告
接缝数 = 0，断层数 = 0，跨人交接 = 0 次

对照传统模式：同样的链条需要 产品经理 + 架构师 + 行业顾问 + 方案经理 + 美工 = 5+ 人 / 数周，产生 ≥4 道跨人接缝。（康养项目 🟢 已交付·本体已编译，数字引用不重算）

2.2 断层样例卡（一道断层长什么样——脱敏虚构，供格式参照）

字段 示例填法
接缝位置 需求 → 设计 之间
掉了什么 客户口头强调的“站长要能一眼看出哪个老人今晚有风险”，需求文档只写了“健康监测”，风险分层的口径丢失
谁发现的 / 何时 开发联调期，晚了 3 周
返工次数 2 次（设计返工 1 + 开发返工 1）
账记谁头上 无主——设计说需求没写清，需求说这是常识
根因归类 意图未全文档化（隐性知识蒸发）

2.3 三类根因标签（画图时给每道断层贴一个）

  • A 意图未全文档化（隐性知识在交接处蒸发）
  • B 工序本位优化（下游为“好实现/好画”改了口径）
  • C 求全式断层（某段做过重，客户其实不要那么全 —— 对应反例 B-7）

三、分阶段脚本（每步：🔔任务 / 🔔输出 / 🔔难点 + 💡启发范例）

阶段一 · 研讨交付主链 + 找断层（16′，本讲研讨核心）

步骤① · 选项目、就交付主链研讨（6′）

🔔 任务：选你近 2 年深度参与、且真实发生过返工的一个项目；就本组命题在组内口述/白板梳理它的实际工序（不是理想流程），一起指认每道跨人交接点（换了负责人 = 一道接缝）。 🔔 输出：一条研讨结论——这条链有哪几道跨人接缝（接缝①②③…），组内说得清即可，不必成图。 🔔 难点/注意：太顺利的项目不聊（多半是你没看见断层）；聊的是“实际发生的”链条，不是流程规范里的理想图。

💡 启发 · 点开看康养项目范例

正例（康养项目，接缝 0）：客户模糊意图→102 事件→16 簇→7 画像→7 旅程→5 流程→10 热点→7 域 D1–D7→3835 行骨架→可研，全程同一个 FDE 大脑，跨人接缝 = 0。

你要画的是它的反面（传统链条，有接缝），示范画法：

[客户口述] ─接缝①→ [产品经理:需求文档] ─接缝②→ [架构师:设计] ─接缝③→ [开发:系统] ─接缝④→ [方案经理/美工:交付PPT]

每换一个负责人就画一道接缝——这四道接缝正是传统 5+ 人模式里信息衰减的发生地。选题启发：断层图要丑、要有血；选“顺得没故事”的项目等于交白卷。

步骤② · 逐道接缝研讨断层（10′）

🔔 任务：就每道接缝，参照 2.2 样例卡的追问角度研讨：掉了什么、谁何时发现、返工几次、账记谁头上、根因该贴哪类（A/B/C）。挑至少 2 道真实断层聊透。 🔔 输出：研讨观点 ≥2 处——每处能说清“掉了哪句意图/哪个口径 + 根因归哪类”，组内达成共识即可。 🔔 难点/注意：断层要精确落在“接缝”上，不是笼统怪某人；“掉了什么”要聊到具体丢失的那句意图/那个口径，不是“沟通不畅”。区分 C 类（求全式）——某段做过重不是敬业，是断层（B-7）。

💡 启发 · 点开看康养项目/脱敏件范例

照 2.2 样例卡填一道断层（脱敏，格式即范本）：

字段 填法
接缝位置 需求 → 设计 之间
掉了什么 客户口头强调“站长要一眼看出哪个老人今晚有风险”，需求文档只写“健康监测”——风险分层口径丢失
谁/何时发现 开发联调期，晚了 3 周
返工次数 2 次（设计 1 + 开发 1）
账记谁头上 无主（设计说需求没写清，需求说是常识）
根因 A 意图未全文档化

两个要点：① 断层精确落在“需求→设计”这道跨人接缝上，不是骂“设计不行”；② “掉了什么”落到具体口径（风险分层），不是空话。C 类范例见反例 B-7——康养项目长者旅程初版把“夜间急救”做过重，后返工改会员飞轮，那是“认真地做错方向”，也是一道断层。

阶段二 · 研讨保真度跌落 + FDE 反事实（4′）

步骤③ · 研讨保真度跌落 + FDE 反事实（4′）

🔔 任务：以需求端 100% 为起点，就本组命题研讨每道接缝后保真度大约跌到多少（如 100→80→65→55）、每段跌落丢的是哪部分意图；再研讨一个 FDE 反事实——若由 1 名 FDE 贯通，哪几道断层能消除、哪几道消不了（只是压成同一个人的时间压力）。 🔔 输出：研讨结论——每段跌落说得出丢了哪部分意图 + 一条反事实共识（区分“可消除”与“只是转成时间压力”）。 🔔 难点/注意：跌落不能随口打分，每段要能说出丢了哪部分意图；反事实别神化 FDE——A/B 类接缝断层可消，C 类方向性/求全断层消不了，只是搬成同一人的时间压力。

💡 启发 · 点开看康养项目范例

保真度折线（示范）：需求 100 →产品经理转写丢“风险分层口径” 80 →架构师为“好实现”改口径（B 工序本位）65 →开发按字面实现 55。每一跌都挂得住是丢了哪段意图。

FDE 反事实（康养项目锚）：由 1 名 FDE 贯通，A 类（隐性知识蒸发）、B 类（本位优化）断层可消除——同一大脑不跨人重判，口径不在接缝处蒸发（康养项目接缝 0 即证）。C 类（方向性/求全）消不了：引反例 B-7——康养项目长者旅程初版做“夜间急救”过重、返工改会员飞轮（🟢 已交付项目的真实失误）。即使一个人贯通，方向判断错仍要返工，只是压成同一人的时间压力，不再是跨人接缝。诚实结论：可消的是“交接信息衰减”，消不了的是“判断本身的难度”。

阶段三 · 两两互评研讨深度（8′）

步骤④ · 换组互评 + 收口共识（8′ 互评 / 6′ 收口）

🔔 任务：与邻座交换各自的研讨观点，互相挑战“这道真的是断层吗？还是你事后归因？”；各自记下对方点出的最值得深挖的一点，据此把本组共识收口成一句话。 🔔 输出：互评记录 + 我要回去再想的 1 点 + 一句话共识。 🔔 难点/注意：互评别客气，重点盯“这道断层是真发生的、还是把’某人不行’当断层”“那段跌落说得出理由吗”。

四、checkout（研讨深度对照表）

每阶段末 + 收尾各对照一次。本环节不产交付物，checkout 看的是研讨有没有聊深——四维，每维看“聊到位”与“一票警示”。

维度 ✅ 聊到位 ⚠️ 警示（没聊进去）
D1 落到本组命题 研讨真锚在本组命题的真实项目上，断层有具体时间、具体返工、追得到“谁何时发现” 空谈原理、或套范例数字，没落到本组命题
D2 定位精度 断层精确落在跨人交接点，根因（A/B/C）说得对 把“某人不行”当断层，没找到接缝，或根因说反
D3 有自己的判断 保真度跌落每段说得出丢了哪部分意图，是自己的观点不是照搬启发范例 随口打分说不出理由，或整段照抄康养项目范例
D4 反事实诚实度 明确区分“可消除”与“只是转成时间压力”，不神化 FDE 一律“FDE 全能解决”，或反事实聊不出

研讨深度参照：四维都聊到位 = 看得见全链、能诚实推演反事实（L2 潜质）；断层聊到了但反事实偏乐观 = 还差一层；把命题聊成理想流程图 = 没进去。 一票警示：全程套范例数字、没有一句自己的判断，或根本没落到本组命题 —— 无论聊得多热闹，都算没进去。真实的断层研讨一定是“丑的、有血的、账算不清的”。

五、复盘研讨（3 题，教练收口，18′）

  1. （反事实边界） 你图上最深的那道断层，若换成“一个人贯通”，真的能消除吗？还是只是把压力搬到了这个人身上？
  2. （求全即断层） 你项目里有没有“求全导致的断层”（C 类）——某段做得过重、客户其实不要那么全？举不出，是真没有，还是你把“求全”当成了“敬业”？
  3. （谁为全链负责） 你们组织现在为“全链保真”负责的是谁？如果答案是“没有这个人”，这说明了什么？

教练收口锚点：题 1 区分“交接信息衰减（可消）”与“判断难度（消不了，只是转成时间压力）”，学员若答“FDE 全能”判为不及格认知，引出第 2 讲——智能体是扛“判断转成的时间压力”的杠杆，判断仍在人这里。题 2 用 B-7（夜间急救过重返工）点破“求全是没想清客户要的结果”。题 3 回收——组织答不出“谁为全链保真负责”，说明靠流程+文档补断层（补不住），FDE 补的是“对结果负责”的空位。

六、参考答案要点（讲师版 · 标“讲师专用勿发学员”）

⚠️ 讲师专用，勿发学员。

  • 研讨题 1：正确答案要区分两件事。“一个人贯通”消除的是交接信息衰减（隐性知识蒸发、本位优化），消除不了的是判断本身的难度。学员若答“FDE 能解决一切”，判为不及格认知——引出第 2 讲：智能体正是用来扛住“判断难度转成的时间压力”的杠杆，但判断仍在人这里。
  • 研讨题 2：多数学员举不出 C 类例子。讲师要点破：举不出往往不是没有，是把“求全”当成了“敬业”。用康养项目 B-7（长者旅程初版做“夜间急救”过重，返工改会员飞轮）佐证——最专业的团队也会栽在“认真地做错方向”。求全是“客户要的结果没想清”的症状。
  • 研讨题 3：标准答案——组织若答不出“谁为全链保真负责”，说明现在靠流程+文档补断层（补不住，见讲义三点论证），而非靠一个看得见全链的人。FDE 补的正是这个“对结果负责”的空位，不是多一个能干的人。
  • 评分校准：最常见的高分误判是“图很漂亮很完整”——漂亮完整恰恰可疑，真实断层图一定是“丑的、有血的、账算不清的”。评分锚定维度 D1 真实性，宁给丑图高分，不给完美流程图高分（对应“一票警示”）。
  • 与康养项目基线的对照口径：正例数据一律引用讲义/BRIEF 单点（102 事件 / 7 域 / 3835 行 / 11 章 26 图 / 5+ 人对 1 人），不重算、不改口径（防反例 B-5）。
