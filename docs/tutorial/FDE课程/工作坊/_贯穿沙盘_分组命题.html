FDE 课程 · 贯穿式分组沙盘（Capstone）与命题库

用途：把工作坊从“孤立练习”升级为“一条命题贯穿全程”。4–5 个小组，每组领 一个命题（模拟真实业务），用六个真实案例（康养项目/教育督导项目/HR项目/学前教育项目/辣椒/草业项目）启发，按 FDE 流程边学边做；全部课程结束时，每组同时完成该命题的 FDE 全流程与对应产出——一份“迷你 FDE 交付包”。 授课形式遵 _工作坊授课规范.md（敏捷引导式：启发→执行）。口径遵 _WRITING_BRIEF.md。

一、沙盘机制（怎么玩）

  1. 分组：4–5 组，每组 4–6 人。开课第一天各组认领一个命题（见第四节命题库），一认到底、不换。
  2. 一命题贯穿：L1–L8 每一课，各组都用自己那个命题跑真实工具——不是每步换一个练习题，是同一个项目往前推一段。
  3. 启发来自真实案例：每步的 💡 启发 范例，用康养项目/教育督导项目/HR项目/学前教育项目/辣椒/草业项目的真实产物做标尺；各组照着“做对了长什么样”，对自己的命题产出同类物。
  4. 增量沉淀：每组维护一个贯穿工作簿，八课的产出逐页累加，最后拼成交付包。工具产物落在各组自己的 studio/changes/{命题-slug}/ 下，工作簿只记判断与结论。
  5. 结课路演：最后一讲后，各组用 20 分钟路演本组命题的迷你 FDE 交付包，按第五节评审卡互评 + 讲师评。

元示范：这套“一命题贯穿、增量沉淀、单点口径”本身就是 L5 下半场教的“锚定口径 + SOP 复用”——各组的贯穿工作簿，就是他们自己项目的 _WRITING_BRIEF。

二、命题贯穿地图（L1–L8 八课 → 交付包 11 件）

2026-07-27 体系化重排（v0.3）：L1 纯讲解建立认知（不产交付物）→ L2 领项目装工具 → L3–L7 每课一个工作环节 → L8 收口。详见 00_八课总纲.md。

三、命题设计原则（为什么是这几个）

  • 模拟真实业务：每个命题都有客户背景、客户原话（模糊意图，需组自己压成结构）、已知约束、故意埋的“查不到的项”（练 B-10 诚实边界）。
  • 各对标一个课程真实案例做启发标尺，但不是抄：命题的城市/切口/规模都与蓝本不同。
  • 刻意分布在不同交付模式上（L3 判模式）：有模式二大平台、有模式一 Token-SaaS 应用，逼各组用对财务语言（IRR/回本 vs MRR/LTV:CAC/NRR）。
  • 难度相当、切口不同：四个命题跨康养/教育/美业/农业四个行业，验证“FDE 方法跨行业可迁移”（L1 讲 C1 迁移力）。

四、命题库（5 个命题，4–5 组各认领一个）

覆盖康养/教育/美业/农业/监管五行业；刻意分布在两种交付模式（模式一 SaaS：B/C/E；模式二 平台：A/D），逼各组用对财务语言。

命题 A · 微康养 ｜「县域’助浴+喘息’微康养服务网络」（康养）

  • 对标启发案例：康养项目微康养（🟢 已交付）——但康养项目是地级市大平台，本命题收窄到县域单切口，不许照抄。
  • 交付模式定位：🟦 模式二 · 大平台建设+运营（有站点、有运营盘）→ 财务语言用 投资/EBITDA/IRR/回本。
  • 客户背景：某县民政局 + 县属国资平台公司，想在全县建一张“助浴 + 喘息服务”为切口的微康养站点网，服务全县约 3.2 万失能/半失能老人，一期铺 15 个乡镇/社区站点。
  • 客户原话（模糊意图，组自己压结构）：
    1. “很多失能老人一年洗不上几次澡，我们想让’上门助浴’能约、能追踪、能核销补贴。”
    2. “长期照护老人的家属太累了，想有个’喘息服务’——家属能临时把老人托管几天。”
    3. “县里想知道钱花在哪、服务到没到位，别站点报个假数。”
    4. “能不能顺便帮家属推荐点付费的康复辅具租赁，增加点收入？”
    5. “老人身体状况变了（比如评估等级变了），补贴和服务额度要跟着变。”
  • 已知约束：助浴/喘息挂长护险与政府购买；服务真实性要留痕核验（防刷单）；老人能力评估等级驱动服务额度；县域预算紧、单站要能自负盈亏。
  • 故意埋的“查不到项”（B-10）：该县“居家养老助浴补贴标准”文号、“喘息服务政府购买单价”文号、平台内部“服务真实性核验 SOP”编号——查不到。
  • 该组要点透的：助浴/喘息=服务履约闭环（约→派→做→核销留痕）；辅具租赁=交叉补贴增收；评估等级=资格动态调整（对标康养项目 Elder 画像单写入 + 资格降级）。

命题 B · 园本知识库 ｜「区域幼儿园’园本课程知识库 + 保教助手’」（教育）

  • 对标启发案例：教育督导项目（🟢 已建模+方案）——教育督导项目是“督导评价”，本命题偏“园本课程知识沉淀 + 一线保教助手”，切口不同。
  • 交付模式定位：🟩 模式一 · Token 计费智能体 SaaS 应用（卖给区教育局/园所的应用）→ 财务语言用 MRR/ARR/LTV:CAC/NRR/Churn。
  • 客户背景：某区教育局 + 一家幼教服务商，想做一个“园本课程知识库 + 保教助手” SaaS：把各园零散的优质教案/观察记录/主题活动沉淀成可检索、可复用的知识库，并给一线教师一个“一问得方案”的保教助手。区内约 60 所园、900 名教师。
  • 客户原话：
    1. “好教案都在老教师脑子里和各自电脑里，人一走就没了，想沉淀下来。”
    2. “新教师写观察记录、设计主题活动没抓手，想有个能一问得建议的助手。”
    3. “各园水平差距大，想把优质园的做法’可复制’到薄弱园。”
    4. “教育局想看到全区教研活跃度、知识复用率。”
    5. “AI 给的建议不能出格——不能违反《3-6 岁儿童学习与发展指南》，也不能瞎编。”
  • 已知约束：内容要合规（挂《指南》等教育标准）；AI 建议要可溯源、不能幻觉（本体约束）；教师数据与儿童信息受个保法约束；SaaS 要按园/按席位计费、看留存。
  • 故意埋的“查不到项”（B-10）：该区“园本课程评审细则”本地文号、“保教质量结果应用办法”文号、服务商内部“AI 内容安全审核 SOP”编号——查不到。
  • 该组要点透的：知识库=D7 式版本化知识地基 + RAG 取证；保教助手的“不出格”=OAG 约束求解（合规候选集内生成、越权 reject，对标草业项目）；SaaS 指标（NRR=老师用不用得下去）。

命题 C · 智慧工作台 ｜「连锁美业’门店智慧工作台’」（美业）

  • 对标启发案例：康养项目会员复购飞轮（🟢）+ SaaS 指标——美业是会员/复购/顾问生意，飞轮机制高度可迁移。
  • 交付模式定位：🟩 模式一 · SaaS 应用（卖给连锁美业总部/门店）→ 财务语言用 MRR/LTV:CAC/NRR/客单价/复购率。
  • 客户背景：一家有 80 家门店的连锁美业（美容+轻医美），想做一个“门店智慧工作台”：整合会员、项目、顾问、库存/耗材、预约，并用 AI 帮顾问做“千人千面”的项目推荐与复购提醒，提升连带率与复购。
  • 客户原话：
    1. “顾问全靠经验推项目，好顾问一走业绩就掉，想把’怎么推’沉淀成系统能力。”
    2. “会员做完一次就不来了，想有个’该回访、该复购’的智能提醒。”
    3. “耗材（针剂/护理品）经常压货或断货，想让消耗和预约挂上钩。”
    4. “医美项目涉及资质和合规，推荐不能乱推、不能夸疗效。”
    5. “总部想看每店的坪效、顾问人效、会员复购率。”
  • 已知约束：医美项目推荐涉《医疗广告》《医疗美容服务》合规红线（不得夸大疗效、需资质）；会员敏感信息受个保法；连带/复购推荐涉钱涉信任（推错毁口碑）；SaaS 按门店/席位订阅。
  • 故意埋的“查不到项”（B-10）：该连锁内部“医美项目话术合规清单”编号、“顾问提成与推荐分离风控 SOP”编号、某地“生活美容与医疗美容边界”地方监管口径文号——查不到。
  • 该组要点透的：会员复购飞轮（对标康养项目“患者→会员”三线咬合）；医美推荐的“不能夸疗效”=HIL 涉合规闸 + 本体规则拦截；顾问推荐转单=涉钱+置信兜底闸（防橡皮图章式硬推）。

命题 D · 标准化种植大模型 ｜「地方特色作物’标准化种植 + 产销’大模型」（农业）

  • 对标启发案例：辣椒（🟡 方案级）/ 草业项目（🟡 方案+Mock demo）——同为农业产业链，成熟度诚实：本命题也只到方案/调研级，产出标“目标值非实测”。
  • 交付模式定位：🟦 模式二 · 大平台建设（全产业链平台，早期）→ 财务语言用 投资估算/功能点（若含平台建设），兼谈产品化收入。
  • 客户背景：某县农业农村局 + 龙头合作社，想为本县一种地理标志特色作物（如某地道地中药材/水果，脱敏为“××作物”）做一个“标准化种植 + 品质分级 + 产销对接”大模型，服务散户/合作社/加工/收购/监管五类用户。
  • 客户原话：
    1. “散户种得五花八门，品质不稳，想有个’一地一方’的标准化种植方案。”
    2. “收购时靠眼看手摸定价，想有个客观的品质快检分级。”
    3. “想做地理标志的产地溯源，卖出溢价。”
    4. “农业局想监测种植面积、品质趋势，做产业决策。”
    5. “最好能对接销路，别丰产不丰收。”
  • 已知约束：种植方案挂农业标准/地方品种审定；品质分级需客观指标（不能主观）；溯源凭证涉信任与合规；数据来源“空-天-地”多源；效益数字（降本/提质/溢价）此阶段是目标值、非实测。
  • 故意埋的“查不到项”（B-10）：该县“××作物地方种植技术规程”文号、“地理标志产品保护管理办法”本地实施细则文号、合作社内部“品质分级标准”编号——查不到。
  • 该组要点透的：一地一方=场景化方案生成；品质快检分级=本体规则+置信度；产地溯源=版本化知识+凭证（对标辣椒椒溯/草业项目草碳）；全程用“方案目标值”口径，不吹成实测。

命题 E · 监管督导型 ｜「区级’养老机构星级评定’智慧督导应用」（监管）

  • 对标启发案例：教育督导项目（🟢 已建模+方案）——教育督导项目是“幼教保教质量督导”，本命题换域到养老机构星级评定督导，切口不同、机制同构。
  • 交付模式定位：🟩 模式一 · Token 计费智能体 SaaS 应用（卖给区民政局的督导应用，G 端为主、无运营盘）→ 财务语言用 MRR/ARR/席位，且要说清“政府项目按用量/按席位而非回本年”。
  • 客户背景：某区民政局，想做一个“养老机构星级评定 + 日常监察”的智慧督导 SaaS：把星级评定标准结构化，帮机构自评自查、帮民政做全区 Gap 诊断与整改跟踪，服务全区约 40 家养老机构。
  • 客户原话（模糊意图，组自己压结构）：
    1. “星级评定标准又厚又专业，机构看不懂、也不知道自己缺什么，想有个’一问就懂、一查就知差在哪’的东西。”
    2. “评定材料反复报、反复退，想让机构上传前就能实时自检。”
    3. “民政想看到全区机构的短板分布、整改进度，做个’一张图’。”
    4. “评定结果要能追溯——为什么给这个机构三星不是四星，得说得清、经得起复查。”
    5. “有些机构材料造假，想有办法交叉核验。”
  • 已知约束：星级评定挂《养老机构等级划分与评定》GB/T 37276-2018 等标准；评定结论一经发布不可逆、涉合规追责；机构与老人数据受个保法约束；G 端项目无运营盘、按用量/席位计费。
  • 故意埋的“查不到项”（B-10）：该区“养老机构星级评定实施细则”本地文号、“评定结果与补贴挂钩办法”文号、服务商内部“评定结论复核 SOP”编号——查不到。
  • 该组要点透的：标准解码=知识库+RAG；材料实时自检=质检前置（对标教育督导项目 material-qc）；评定结论发布=命门 HIL 闸（涉合规+不可逆，非增收）；结论可追溯=决策血统（方法论 10）；这是模式一里“命门在裁定/发布闸而非增收闸”的最好实证（对标教育督导项目三闸）。

五、结课路演评审卡（各组互评 + 讲师评）

维度 ✅ 达标线 ⚠️ 警示
① 认知萃取到位 客户模糊原话被压成可归域的事件/画像/旅程/热点，画像有“数据校准”意识 停在复述客户原话、画像拍脑袋
② 结构与本体 切出限界上下文、一个核心域的五要素本体草案自洽、跨域 ref 不越界 域切错/对象被两域直写/五要素混乱
③ 交付模式与财务语言用对 判对模式一/二、用对财务语言（IRR/回本 vs MRR/LTV:CAC/NRR）、能用交叉补贴/三级火箭拆商业模式 模式二讲 MRR 或模式一讲回本年（答反露怯）
④ HIL 设点 5–8 个真闸、判据准、按错代价具体、分得清自动闸/人工闸 漏涉钱/涉合规闸，或滥设闸
⑤ 诚实边界 查不到的项留占位转取证清单、方案级数字标“非实测” 编造文号/把目标值当实测 = 一票警示
⑥ 交付物成形 一节方案稿+一张图占位+90 天计划，口径一致无漂移 拼凑、口径打架、无落地计划
⑦ 产品 demo（延伸） 有可点开的交互原型（3–6 屏）+ 诚实说明“交互外壳、AI 为 Mock、非模型跑通” + Mock 清单（grep 出的 TODO） 把 demo 外壳吹成“跑通的产品” = 一票警示；或说不出自己在“数据真”还是“数据也假”那一档
⑧ 工具链走通（加分项） L1–L8 八课都在本组命题上真跑过，产物在 studio/changes/ 里可查；说得出本组哪个动作值得沉淀成插件 只在 PPT 上走完流程、工具没真跑（不扣分，但拿不到加分）

一票警示（三条）： ① 编造查不到的文号（B-10）——留占位、转取证清单才是对的； ② 把别处模板的数字当自己的（B-11）——复用模板可以，复用数字不行； ③ 把方案目标值 / Mock demo 说成已实现——包括说不出自己的 demo 是「数据真」还是「数据也假」。 无论其他维多好，命中任一条路演不通过。 三条其实是同一条：空缺可以补，编造无法挽回。 这是全课程价值观的最终检验（demo 能做出可点开外壳是本事，吹成产品是骗客户——L7/L8）。

六、给讲师的运行提示

  • 认领即固化：第一天各组认领命题后，发一张“命题卡”（第四节对应条），并要求各组当场写下“一句话项目定义”，钉进本组贯穿工作簿首页。
  • 每一步都必须真跑工具：不许“听懂了就跳过”。L1–L8 每课末尾做 checkout（各课手册有对照表），产物没落盘就是没做。
  • L2 会卡住人：装环境必然有人因网络/权限/Node 版本卡住。别让全班等——装好的先读命题卡、想一句话项目定义，教练单独捞人。
  • 启发范例只做标尺、不做模板：反复强调“康养项目做对了长这样，但你的县域/园所/门店/作物不一样，照着结构做、别抄数字”。
  • 诚实边界贯穿到底：四个命题都埋了“查不到项”，讲师要盯各组留占位不编造——这是结课路演的一票警示，从第一讲就要立规矩。
