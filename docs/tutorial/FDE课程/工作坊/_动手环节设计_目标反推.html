动手环节设计 · 目标反推（先定产出，再对齐工具与课件）

⚠️ 本文件是 v0.2 时期的设计推导记录（“先定交付物、再倒推需要哪些步骤”），不是现行授课口径。 内部仍按 T1–T8 编号——刻意保留：改成 L 编号会篡改历史，让人误以为当时就是按八课设计的。查阅时按 00_课程总纲.md 第九节的对照表换算。 它记录的是决策过程（为什么 T2 没有交付物却不可省、为什么 v1 的 D2 被拆开），改课时值得先读一遍再动结构。

方法：不按“每讲配一个动手”，而是从工作坊最终交付物倒推——先定“每组结课要交什么”，再看哪个工具产出它、哪一讲供给做它所需的知识。

版本说明 - v1（2026-07-26）：结论是 7 个动手环节 D1–D7 + 认领 + 路演，动手挂在讲 4/6/7/8/10 上，其余五讲作研讨。 - v2（2026-07-27）· 现行：改按双轨重构——执行主干换成 T1–T8 八步工具实操，旧 10 讲整体降为知识注入。 变化的本质：v1 是“在十讲里挑出哪几讲能产出交付物”，v2 是“按工具链排主干，让十讲去供给它”。倒推方法没变，被倒推的对象从“讲”变成了“工具步骤”。

一、工作坊目标 → 最终交付物

目标：每组把本组命题走完一遍 FDE 交付流程，结课交出一份「迷你 FDE 交付包」。

1 一句话项目定义 + 交付模式判定 立项 T1

6 交付 SOP 七阶段（含各阶段收口标准） SOP 讲 6 教 → T5 成文

8 citations 取证清单（挂国标 + 查不到留占位） S5 合规 T5
9 一节方案稿 + 一张配图占位 S6 交付物 T6

⚠️ 诚实边界（务必守）：各组做的 demo 只是“交互原型/外壳”，路演时必须说清“这是交互外壳、不是模型跑通”。 真实案例成熟度参照：草业项目 11 页 demo、AI 是 Mock 关键词路由、数据全仿真；教育督导项目 47 页 demo、AI 是 Mock 但数据是 79 园真实 CSV；辣椒无 demo（demo-app/ 仅 .gitkeep）。 同样一句“这是 Mock”，含金量差一档——T7 手册第五节有三档自评表。

二、反推结果：八步各产出什么

判据没变：一个步骤存在，当且仅当它产出交付包里的某几件，或它是后续步骤的必要前置。

步 产出（进交付包） 覆盖 时间盒
L3 信息采集 一句话定义 + 交付模式判定 + domain-intake 契约 ① 90′
L2 项目与工具 —（必要前置：可用工具链 + studio/ 工作区） — 60′
L4 上半场 · 认知萃取 画像 ≥3 / 旅程 ≥2 / 流程 ≥2 / 热点分层 ② 120′
L4 下半场 · 领域建模 限界上下文域图 + skill-map（喂 L8） ③ 120′
L5 上半场 · 本体建模 五要素本体草案（七段 IR + 编译骨架 + 收尾 6 项清单） ④ 90′
L5 下半场 · 设闸与治理 HIL 设点表 + 取证清单 + SOP 成文 ⑥⑦⑧ 90′
L6 文档工程 写作专家 + 商业模式与财务语言 + 一节方案稿 + 配图占位 ⑤⑨ 150′
L7 原型开发 3–6 屏可点开原型 + Mock 清单 ⑪ 120′
L8 能力沉淀 团队编成草案；可发版插件（加分） ⑩a⑫ 150′
L8 结课路演 90 天启动计划 + 拼合 11 件、20′ 答辩（含 demo 演示 + 诚实说明） ⑩b + 全 120′ + 每组 20′

= 8 个步骤，交付包 11 件全部有归属、不重不漏，另加 1 件加分项。

与 v1 的两处实质差异： 1. T2 没有交付物但不可省 —— v1 的判据“不产交付物就不设动手”会把它筛掉，但它是所有后续步骤的前置。判据因此补了半句“或它是后续步骤的必要前置”。 2. v1 的 D2 被拆开了 —— 原本“结构与本体”合在一个环节（域图 + 本体草案），现在分给 T4（域图）与 T5（本体）：用的是两个不同的工具，中间还隔着一个分叉点（见下）。

三、⭐ T4 之后是分叉，不是流水线

T2 → T1 → T3 → T4 ─┬─ T5 本体+设闸    （要"可执行的规则与闸"）
                    ├─ T6 文书          （要"可评审的文档"）
                    ├─ T7 原型          （要"看得见的应用形态"）
                    └─ T8 插件沉淀      （要"下个项目能复用的能力"）

它们并行、不互为前置。

活证据：学前教育项目项目没做本体建模、没有 persona/journey，照样交出 653KB 可研 + 完整送审报价包 + 单一来源论证。

所以排课顺序 T5→T6→T7→T8 是教学顺序（由难到易、由内到外），不是依赖顺序。 真实项目按交付模式决定先走哪条：模式二 To-G 大盘 → T6 优先；模式一 SaaS → T5+T7 优先。
