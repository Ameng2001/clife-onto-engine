# FDE 课程 · 工作坊授课规范（所有工作坊统一遵循）

> 参照团队既有的《行业数据模型探索工作坊》（STPB 四阶九步）的**敏捷引导式**授课形式固化而成。
> 目的：把 FDE 工作坊从"静态练习册"升级为"可被敏捷教练直接主持的脚本"。**所有 `工作坊/NN_*.md` 统一按本规范重构。**
> 这份规范本身也是 **L6「锚定口径」**的示范——授课形式单点定义、八课一致套用。

---

## 一、核心授课模型：启发 → 执行（先看范例，再动手）

**每一个步骤都是"启发-执行"两拍**：
1. **启发（教练给）**：先给一个**康养项目/案例的 worked example（范例）**，让学员看"做对了长什么样"——用 `<details>` 折叠，现场点开。
2. **执行（学员做）**：学员/小组在**时间盒**内，照着范例对**自己的项目**产出同类产物。

> 铁律：**先启发、后讨论**。不给范例直接让学员讨论，会跑偏（方法论 06："没有蓝图的 Vibe Coding 会失控"）。

---

## 二、工作坊纪律（每份工作坊开头照抄，教练开场宣读）

1. **启发-执行纪律**：先看启发范例，再动手；不跳过范例直接空想。
2. **时间盒纪律**：个人发言、小组讨论严格遵从时间盒，铃响即停。
3. **终止铃纪律**：敏捷教练终止铃响起，讨论立即停止，进入下一步。
4. **停车场纪律**：一时争不出的问题挂到"停车场（parking lot）"，会后再议，不占时间盒。
5. **checkout 纪律**：每阶段末、工作坊末做 checkout（对照输出与验收标准）。

## 三、工作坊宣言（照抄，开场齐读）

- **完成大于完美**
- **团队大于个人**
- **共识大于对错**

## 五、写作约定（给重构工作坊的作者）

- **每个动手步骤必须配一个 `💡 启发` 折叠范例**，范例一律取自**康养项目/某工业城市/教育督导项目/草业项目/辣椒真实案例**（成熟度诚实标注：仅康养项目已交付，其余方案/调研级/Mock）。
- **🔔 输出**要写成"能验收的具体产物"（如"7 域 ontology-map 一段""HIL 设点表 5–8 行""商业模式画布 9 宫格填满"），不是"讨论一下"。
- **时间盒**落到分钟，总和 = 讲义里该讲的"练 + 议"时长（保持 4:4:2 的后 6 成）。
- **难点**要点名该讲反例（B-x）或方法论坑（如"区分行为与过程的粒度"→FDE 版"区分 declarative rule 与 function rule"）。
- 保留原有的**评分卡**内容，转成 checkout 对照表（达标/警示两栏），并保留"一票警示"。
- 术语、数字、案例成熟度严格对齐 `_WRITING_BRIEF.md`（引用不重算，防 B-5）。
- Markdown 用 GFM：`<details><summary>` 折叠范例（pandoc 渲染成可点开）；🔔/💡 emoji 直接用；🔔任务/输出/难点用引用块 `>` 包裹。
</content>
