7 收尾挂账 未决项显式挂 TODO，不靠“应该行” 121 骨架 + 11 文号 + SDK 待确认 每条 TODO 有落点、有谁补 有没有把不确定往前硬推？

锚定口径先于并行：多智能体/多人协作前，先产出一份 _WRITING_BRIEF.md（术语表+核心数据表+主张+纪律）。这是一致性的唯一真相源，不是靠自觉。

② HIL 设点四判据（满足任一 → 必须插人）

   ┌─ 不可逆？   （数据发布 / 状态迁移不可撤回）───┐
   ├─ 涉钱？     （增收决策 / 报销 / 分账 / 定价）──┤
   ├─ 涉合规？   （监管发布 / 补贴发放 / 授权）─────┼──► 是 → 设 HIL 闸
   ├─ 跨组织？   （跨机关 / 跨主体的动作）──────────┤        人拍板 + 写后留痕
   └─ 置信度不足？（模型输出 < 阈值，如 0.75）──────┘
                                                    └──► 否 → 可自动执行
  • 站长 HIL（增收闸）：AI 研判方案 → 站长拍板 → 转订单。置信度闸防橡皮图章（阈值占位 0.75，按错代价 = 错误增收决策）。
  • 民政 DP-H（监管发布闸）：监管数据发布前人工闸（按错代价 = 违规发布、监管追责）。
  • 口诀：AI 研判、人拍板、留痕可追溯。 高置信度不是免责，橡皮图章式的“人在环”等于没有环。

③ 十大真实反例（康养项目踩坑 → 原则）

# 坑 原则
B-1 图目标题写“22 张”，表体实际 26 行 摘要与明细单一真相源；并行产出必须收口回改
B-2 35 节并行写作，装配期编号重复/跳号 编号权归装配阶段，不归写作阶段

B-5 老龄化率 60+/65+ 口径混用张冠李戴 关键数字锚在 BRIEF 单点，引用不重算
B-6 药食同源误标“GB”、星评用已废止 MZ/T 引标准核到官方现行版本
B-7 长者旅程做“夜间急救”过重，返工 建模服务业务优先级，不求全
B-8 编译期想让 Action 越域 stage_write 跨域一律 ref/发布，纪律靠校验器
B-9 SDK 能力（default/Evaluation）想当然 不确定就显式挂账，不靠“应该支持吧”
B-10 11 处地方文号公开渠道查不到 留占位 + 锚上位国标 + 转取证清单

④ 诚实边界（FDE 的专业底线）

  • 查不到 ≠ 编一个：地方文号、内部 SOP 编号无法核验时，留 [本地待补文号] / [企业标准,FDE 补编号]，锚定上位国标，转成向对应机关/部门逐项取件的清单。
  • 智能体接不了的四件事（必须人扛）：客户关系 · 责任承担 · 价值判断 · 政治敏感度。这四项不是“暂时做不好”，是不该交出去。
  • 一句话：FDE 的专业性，一半体现在敢说“我不知道，我去查/我去取”。
